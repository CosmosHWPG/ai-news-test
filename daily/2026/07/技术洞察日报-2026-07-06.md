### 2、2026年7月，新加坡国立大学（NUS）发布OPD-Evolver：通过策略蒸馏实现智能体自我进化，9B模型在多任务上超越397B大模型 {#event-66726}

### 4、pi 框架从 LLM API 到 Agent 循环的工程化路径揭示工具接口设计对稳定性的关键影响 {#event-67000}

【智能体平台、协议与执行系统】 【Agent工程】 【Tool Calling】 【研发效率提升】

📋 **要点**：2026年7月5日，earendil-works 开源项目 pi 通过技术文章系统展示了从无状态 **LLM API** 调用到可运行 **Mini Coding Agent** 的完整工程路径。文章指出，**Agent** 的“强大”并非来自模型本身，而是来自手动维护的循环：将 **LLM** 回复塞回上下文，将工具返回值再塞给 **LLM**，反复迭代。pi 框架的核心贡献在于将工具接口按 LLM 能力边界重新设计，而非简单封装。例如，read 工具使用 **Buffer.byteLength** 按 **UTF-8** 字节数截断输出（限制 2000 行或 50KB），避免中文字符被 **JavaScript** 字符串 .length 低估；bash 工具采用尾部截断保留关键错误信息；edit 工具要求精确 oldText 匹配，拒绝模糊猜测。pi 还提供了六个控制点（beforeToolCall、afterToolCall、executionMode、steering、followUp、abort），将循环控制、状态消费、工具执行三职责解耦，支持事件订阅和 **AbortSignal** 中断。
📌 **总结**：pi 框架的工程化路径对 **Agent** 产品化具有直接参考价值。其核心启示是：**Agent** 的稳定性不取决于模型本身，而取决于工具接口是否按 **LLM** 能力边界重新设计。read 工具按真实字节截断、bash 工具保留尾部错误、edit 工具拒绝模糊匹配，这些设计原则可被其他 Agent 框架直接复用。pi 的六个控制点（beforeToolCall、afterToolCall、executionMode、steering、followUp、abort）为 Agent 产品化提供了可复用的架构参考，将循环控制、状态消费、工具执行三职责解耦，支持事件订阅和 **AbortSignal** 中断。对于技术主管和预研规划师，pi 展示了如何将 **LLM** 无状态调用的约束转化为工程优势，为构建稳定、可观测的 Agent 系统提供了具体路径。

### 1、苹果研究团队提出Conformal Thinking框架，将推理预算设定转化为风险控制问题 {#event-67603}
