### 1、ToolAtlas：通过提供者侧工具记忆实现Agent工具调用的一次学习、处处复用，在MCP基准上提升21.61% pass@1 {#event-79802}

【智能体平台、协议与执行系统】 【智能体；工具调用；ToolAtlas】 【提供者侧工具记忆】 【研发效率提升】

📋 **要点**：**LLM** Agent日益依赖外部工具，但现有方法通过在Agent侧进行参数更新、提示优化或记忆存储来改善工具使用，导致工具知识难以共享且局限于过去任务中观察到的行为。ToolAtlas提出在工具提供者侧构建持久化图结构工具记忆，通过执行验证的探测自动归纳工具能力边界、失败模式及跨工具组合。推理时，Agent通过自适应图遍历查询该记忆。在涵盖8个服务的两个MCP基准测试中，ToolAtlas在pass@1和pass@4上分别取得高达**21.61%**和**18.61%**的相对提升。同一工具记忆还能在不同环境实例和Agent框架间迁移，无需重新训练，迁移后pass@1/pass@4相对增益达**24.16%**/**16.22%**和**17.49%**/**14.27%**。该成果建立起**提供者侧工具记忆**作为有效且可复用的范式，对MCP工具服务器架构设计具有直接参考价值。
📌 **总结**：ToolAtlas改变了工具调用的架构重心：从Agent端记忆转向提供者侧记忆，显著减少Agent推理时的记忆开销，并避免任务间工具知识的碎片化。对AI工程平台而言，可将该框架集成到MCP工具服务器中，实现工具能力即插即用，无需每个Agent独立维护缓存。对推理服务，提供者侧记忆可集中管理，降低服务端复杂度并提升响应一致性。对模型训练，Agent无需针对新工具进行微调或Prompt工程即可复用已有工具知识，大幅提升研发效率。对评测，ToolAtlas在MCP基准上的跨环境迁移验证，为Agent工具调用能力提供了更可比的评估方法。总体而言，该范式有助于推动Agent工具生态的标准化和互操作性。
来源：[研究团队](https://arxiv.org/abs/2607.11126)
原文标题：ToolAtlas: Learning Once, Reusing Everywhere with Tool-Side Memory

### 1、2026年7月，美团与北京大学联合开源Omni-Flow框架，通过三层抽象统一解决多模态推理工作流编排、数据传输与KV缓存共享挑战 {#event-79883}

【AI推理与服务加速】 【Omni-Flow】 【多模态推理】 【架构替代】

📋 **要点**：美团与北京大学在2026年7月联合开源的**Omni-Flow**框架，是针对多模态大模型推理系统碎片化问题的一个系统级方案。当前**多模态推理**需要异构计算单元（文本编码器、视觉编码器、**LLM**、扩散模型等）协同工作，但现有框架缺乏统一抽象，编排逻辑分散、数据传输与特定模型紧耦合、KV缓存无法跨角色共享，导致每集成一个新模型都需要高昂的改造成本。**Omni-Flow**通过三层抽象系统化解决：控制流层提供声明式DSL定义推理流水线，由框架自动处理调度和数据传输，支持流式逐帧激活和运行时动态分支选择；数据流层以全局参数池为中心，统一管理L1/L2/L3存储层次的KV缓存分配与回收，使任何角色或副本均可相互推送或拉取数据，无需硬编码配对；计算流层让扩散Transformer复用**LLM**推理引擎的执行基础设施（相同的引擎、调度栈、分页KV缓存和权重共享机制），强制两者采用相同并行语义，实现物理权重和KV缓存的直接共享。该项目已在SGLang上实现完整原型，并在DeepSeek-V2纯LLM推理、**LongCat-**Next多模态对话和HunyuanImage-3图像生成三种典型场景上验证了有效性。开源仓库为https://github.com/meituan-longcat/omni-flow.git。
📌 **总结**：**Omni-Flow**对AI推理基础设施的工程复用价值体现在三个层面。第一，声明式工作流抽象将**多模态推理**流水线的编排逻辑从业务代码中解耦，使集成新模型只需在DSL中声明角色和连接关系，无需修改调度和数据传输代码，显著降低模型拓扑快速演进下的适配成本。第二，统一数据平面通过全局参数池实现KV缓存和中间张量的零拷贝、跨角色、跨机器共享，同一GPU上多个共址角色可复用完全相同物理权重，将GPU内存开销降至接近单个副本水平，对资源受限的单节点部署和多机高性能部署均有直接收益。第三，计算流层强制扩散Transformer复用LLM推理栈，使得vLLM/SGLang等成熟LLM serving框架的优化技术（如PagedAttention、prefix caching、continuous batching）能够无缝应用于多模态生成任务，避免了为扩散模型单独维护一套推理栈的工程负担。对于从事推理系统研发或模型服务化的团队，**Omni-Flow**的设计思路——通过清晰抽象解耦复杂性、通过统一平面实现高效共享——可直接指导下一代**多模态推理**框架的架构选型。
来源：[机智流](http://mp.weixin.qq.com/s?__biz=Mzg2NzU4MDgzMA==&mid=2247561134&idx=1&sn=574738c448798a8ae5adcfde29ecd44d&chksm=cf267af635d77dafeefad2280bf75a3d45e31d261079b8f09bbfd47c33e1c105cf07fe2d5d17&scene=0&xtrack=1#rd)

📋 **要点**：美团与北京大学在2026年7月联合开源的**Omni-Flow**框架，是针对多模态大模型推理系统碎片化问题的一个系统级方案。当前**多模态推理**需要异构计算单元（文本编码器、视觉编码器、**LLM**、扩散模型等）协同工作，但现有框架缺乏统一抽象，编排逻辑分散、数据传输与特定模型紧耦合、KV缓存无法跨角色共享，导致每集成一个新模型都需要高昂的改造成本。**Omni-Flow**通过三层抽象系统化解决：控制流层提供声明式DSL定义推理流水线，由框架自动处理调度和数据传输，支持流式逐帧激活和运行时动态分支选择；数据流层以全局参数池为中心，统一管理L1/L2/L3存储层次的KV缓存分配与回收，使任何角色或副本均可相互推送或拉取数据，无需硬编码配对；计算流层让扩散Transformer复用**LLM**推理引擎的执行基础设施（相同的引擎、调度栈、分页KV缓存和权重共享机制），强制两者采用相同并行语义，实现物理权重和KV缓存的直接共享。该项目已在SGLang上实现完整原型，并在DeepSeek-V2纯LLM推理、**LongCat-**Next多模态对话和HunyuanImage-3图像生成三种典型场景上验证了有效性。开源仓库为https://github.com/meituan-longcat/omni-flow.git。
📌 **总结**：**Omni-Flow**对AI推理基础设施的工程复用价值体现在三个层面。第一，声明式工作流抽象将**多模态推理**流水线的编排逻辑从业务代码中解耦，使集成新模型只需在DSL中声明角色和连接关系，无需修改调度和数据传输代码，显著降低模型拓扑快速演进下的适配成本。第二，统一数据平面通过全局参数池实现KV缓存和中间张量的零拷贝、跨角色、跨机器共享，同一GPU上多个共址角色可复用完全相同物理权重，将GPU内存开销降至接近单个副本水平，对资源受限的单节点部署和多机高性能部署均有直接收益。第三，计算流层强制扩散Transformer复用LLM推理栈，使得vLLM/SGLang等成熟LLM serving框架的优化技术（如PagedAttention、prefix caching、continuous batching）能够无缝应用于多模态生成任务，避免了为扩散模型单独维护一套推理栈的工程负担。对于从事推理系统研发或模型服务化的团队，**Omni-Flow**的设计思路——通过清晰抽象解耦复杂性、通过统一平面实现高效共享——可直接指导下一代**多模态推理**框架的架构选型。

### 1、ToolAtlas：通过提供者侧工具记忆实现Agent工具调用的一次学习、处处复用，在MCP基准上提升21.61% pass@1 {#event-79802}

【智能体平台、协议与执行系统】 【智能体；工具调用；ToolAtlas】 【提供者侧工具记忆】 【研发效率提升】

📋 **要点**：**LLM** Agent日益依赖外部工具，但现有方法通过在Agent侧进行参数更新、提示优化或记忆存储来改善工具使用，导致工具知识难以共享且局限于过去任务中观察到的行为。ToolAtlas提出在工具提供者侧构建持久化图结构工具记忆，通过执行验证的探测自动归纳工具能力边界、失败模式及跨工具组合。推理时，Agent通过自适应图遍历查询该记忆。在涵盖8个服务的两个MCP基准测试中，ToolAtlas在pass@1和pass@4上分别取得高达**21.61%**和**18.61%**的相对提升。同一工具记忆还能在不同环境实例和Agent框架间迁移，无需重新训练，迁移后pass@1/pass@4相对增益达**24.16%**/**16.22%**和**17.49%**/**14.27%**。该成果建立起**提供者侧工具记忆**作为有效且可复用的范式，对MCP工具服务器架构设计具有直接参考价值。
📌 **总结**：ToolAtlas改变了工具调用的架构重心：从Agent端记忆转向提供者侧记忆，显著减少Agent推理时的记忆开销，并避免任务间工具知识的碎片化。对AI工程平台而言，可将该框架集成到MCP工具服务器中，实现工具能力即插即用，无需每个Agent独立维护缓存。对推理服务，提供者侧记忆可集中管理，降低服务端复杂度并提升响应一致性。对模型训练，Agent无需针对新工具进行微调或Prompt工程即可复用已有工具知识，大幅提升研发效率。对评测，ToolAtlas在MCP基准上的跨环境迁移验证，为Agent工具调用能力提供了更可比的评估方法。总体而言，该范式有助于推动Agent工具生态的标准化和互操作性。
来源：[研究团队](https://arxiv.org/abs/2607.11126)
原文标题：ToolAtlas: Learning Once, Reusing Everywhere with Tool-Side Memory

### 2、ToFu：面向研究者的白盒、Token高效智能体框架 {#event-79690}

【智能体平台、协议与执行系统】 【智能体框架+Agent Harness+ToFu】 【白盒、token效率、研究工具】 【成本下降】

📋 **要点**：现有agentic coding工具的性能既依赖大语言模型也依赖编排代码（harness），但现有框架存在token效率低、成本高、不透明等问题。ToFu是一个面向研究者的白盒、token高效智能体框架，能够读取代码库、编辑文件、运行命令并集成开发工具。作为研究助手，ToFu在token效率、成本和多语言能力上优于现有框架，且**MIT**许可支持本地部署；作为研究对象，它提供可检查、可修改的白盒设计，允许研究者深入分析编排逻辑和工具使用行为，同时保持强基准性能和应用级用户体验。
📌 **总结**：ToFu对Agent系统研发具有直接价值：其白盒特性使研究者能够透明地理解agent行为，加速编排逻辑的迭代与评估；token效率提升显著降低研究成本，支持更多实验探索；多语言能力和本地部署选项扩展了适用场景。该框架有望成为agent研究的标准工具，推动更高效、更可靠的智能体系统设计，并促进agent评测基准的完善。
来源：[研究团队](https://arxiv.org/abs/2607.11423)
原文标题：ToFu: A White-Box, Token-Efficient Agent Harness for Researchers

### 1、UMoE通过修剪-重扩专家池实现MoE领域微调性能提升 {#event-79717}

【模型训练】 【UMoE】 【MoE领域微调】 【性能提升】

📋 **要点**：2026年7月，**Xuefeng** Li和Pengfei Liu提出**UMoE**，一种预算保持的**MoE领域微调**流水线。在微调前，先修剪最低领域对齐显著性的专家，再通过扰动重扩恢复原始专家池大小，最后应用标准SFT。在Qwen3-**30B**-A**3B**和Qwen3.5-**35B**-A**3B**上，覆盖数学、代码、科学、工具使用和Agent编码5个领域共12个基准，数学平均准确率提升3.4分，**SWE-bench** Verified提升6.0分。在强数学数据集上，即使直接SFT已超越Qwen3-**30B**-**A**3B**-Thinking**（82.81 vs 81.06），**UMoE**仍进一步将平均分提升至84.17。数据缩放实验显示增益随训练数据增长持续。
📌 **总结**：**UMoE**为MoE模型的领域微调提供了一种高效、预算保持的方法，通过重新对齐专家池提升性能而不增加推理成本。对于AI**模型训练**和部署，该方法可直接应用于通信、网络运维等垂直领域的MoE模型微调，提升特定任务的性能，同时保持推理效率。
来源：[研究团队](https://arxiv.org/abs/2607.11444)

### 2、SCOPE-RL通过奖励信号稠密化提升LLM推理，准确率提升11.2pp，推理token减少27.1% {#event-79764}

【模型训练】 【SCOPE-RL】 【奖励稠密化】 【性能提升】

📋 **要点**：基于可验证奖励的强化学习（**RLVR**）使用稀疏的最终答案奖励，无法对推理路径提供直接反馈。**SCOPE-RL**提出两阶段框架：自适应脚手架RL在成功前对隐藏答案的子问题链添加前缀分解可验证奖励；质量感知过程RL在成功后应用正确性门控过程形状奖励优化正确轨迹。在Qwen3-**8B**-Instruct上，相比纯结果GRPO，平均准确率提升11.2个百分点，推理token减少**27.1%**。在Qwen3-**0.6B**上也有效，表明奖励信号稠密化与策略更新级**RLVR**进步互补。
📌 **总结**：**SCOPE-RL**为LLM推理RL训练提供了一种有效的**奖励稠密化**方法，同时提升准确率和效率。对于AI前沿技术预研规划师，该方法可应用于RL后训练流程的改进。对于技术主管，该方法可降低推理成本并提升性能。
