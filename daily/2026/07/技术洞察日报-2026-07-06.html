智能体平台、协议与执行系统 OPD-Evolver 自进化Agent 性能提升

📋 要点：现有自进化智能体依赖相似度检索经验记忆，容易引入过期或任务不匹配的记忆，且奖励信号仅监督任务执行而难以评价记忆选择质量，导致长期运行后记忆污染。新加坡国立大学（NUS）提出OPD-Evolver，构建快慢双循环：快速循环在测试时调用外部记忆完成即时适应，慢速循环通过On-Policy Distillation将有效进化行为内化进模型参数。记忆被组织为轨迹、提示、技能和工具四个层级，智能体执行候选检索、经验筛选、记忆增强执行、经验写入及周期性的查找、合并和删除管理。方法依据记忆被选中与未选中时的任务回报差异计算归因分数V(m)，结合记忆层级先验与使用置信度，将稀疏结果奖励转化为记忆生命周期监督。特权教师可观察记忆价值、成功轨迹、未来效用和仓库诊断信息，在学生自身访问的状态与生成前缀上联合蒸馏选择、执行、写入和维护四种能力。代码已在GitHub开源（https://github.com/bingreeky/opd-evolver），论文同步发布。

📌 总结：OPD-Evolver-9B在LifelongAgentBench、MemoryArena、AMA-Bench和InterCode共10个子任务中取得同规模记忆方法的最佳结果，OS任务达65.00%高于MemEvolve的61.00%；在9/10子任务上超过STEP-3.5-FLASH 196B，6/10子任务上超过Qwen3.5-397B-A17B，如SQL达64.01%高于后者的62.74%。消融实验表明移除记忆归因后InterCode平均成绩由38.67%降至32.13%；蒸馏后所选记忆的中位价值由0.69提升至0.79，执行成功率提升约3～7个百分点、轨迹缩短最多2.5步。该框架将智能体记忆管理从外部检索转为内部能力，可复用于需要长期学习和自适应优化的AI系统（如网络运维Agent、自动化决策Agent），通过策略蒸馏降低对显式记忆库的依赖，提升系统稳定性和推理效率，为智能体平台的记忆层设计提供了可工程化的技术路线。

📋 要点：2026年7月5日，earendil-works 开源项目 pi 通过技术文章系统展示了从无状态 LLM API 调用到可运行 Mini Coding Agent 的完整工程路径。文章指出，Agent 的“强大”并非来自模型本身，而是来自手动维护的循环：将 LLM 回复塞回上下文，将工具返回值再塞给 LLM，反复迭代。pi 框架的核心贡献在于将工具接口按 LLM 能力边界重新设计，而非简单封装。例如，read 工具使用 Buffer.byteLength 按 UTF-8 字节数截断输出（限制 2000 行或 50KB），避免中文字符被 JavaScript 字符串 .length 低估；bash 工具采用尾部截断保留关键错误信息；edit 工具要求精确 oldText 匹配，拒绝模糊猜测。pi 还提供了六个控制点（beforeToolCall、afterToolCall、executionMode、steering、followUp、abort），将循环控制、状态消费、工具执行三职责解耦，支持事件订阅和 AbortSignal 中断。
