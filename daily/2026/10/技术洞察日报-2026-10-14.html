1、中国人民大学提出AEWM世界模型，用EditAct在Agent执行前纠偏决策

智能体平台、协议与执行系统 中国人民大学AEWM 世界模型纠偏 研发效率提升

📋 要点：针对长任务中错误留在历史里形成任务状态污染、持续误导决策的问题，中国人民大学提出AEWM，把世界模型关注点从环境会返回什么转向这一步会把任务带向哪里。其EditAct流程分三步：Action Judge在执行前只看已有历史和当前提议，区分关键推进、有效探索与噪声决策；仅对噪声决策调用State Revision，同时替换当前推理与行动，保留此前历史且不编造工具反馈；真实工具执行保留或修改后的行动，新推理、行动和实际反馈一起进入后续历史。AEWM基于Qwen3.5-35B-A3B，在搜索、终端和软件工程三个领域统一训练，先用52.16B tokens做mid-training，再用12万条高质量样本SFT，判断与修订各占一半，判断标签来自完整轨迹回溯标注但模型输入不含未来信息。在含3000条决策的Action Judge基准上，AEWM的macro-F1达到70.5%，超过最强对照10.6个百分点；接入EditAct后，4B、9B、35B-A3B三个Agent的六项基准平均分分别比最强基线高6.7、5.2、3.2分。

📌 总结：AEWM的价值在于把外部纠偏转化为Agent自身能力：消融显示直接编辑优于判错后让Agent重采样和只给推理提示，只改推理或只改行动也都不如一起改。以35B-A3B为例，相对ReAct，BrowseComp从40.9提升到48.1，Terminal-Bench 2.0从37.1提升到48.3；搜索行为上最长连续搜索序列均值从16.9降到13.2，每题访问不同网页数从7.7升到10.1，表现为更少连续搜索、更多页面阅读。AEWM-RFT用EditAct生成并经验证筛选的高质量轨迹微调Agent，测试时不再调用AEWM，相对Self-RFT三个领域分数再提高2.2至2.6个百分点，BrowseComp和Terminal-Bench 2.0平均轮数分别下降30.0%和16.7%。这为智能体运行时设计提供了新思路：世界模型未必需要复刻环境，也可以学习决策如何影响任务进展，并在错误扩大前改写当前决策，对核心网运维Agent等长任务场景具有参考价值。

6、Anthropic为Claude上线动态工作流，由模型生成多Agent编排程序

智能体平台、协议与执行系统 Anthropic Claude Dynami… 多Agent编排 架构替代

📋 要点：2026年10月9日，Anthropic为Claude Managed Agents上线Dynamic Workflows，目前处于Beta阶段。该机制由Claude根据任务需求生成一段编排程序，程序包含实际执行逻辑，例如并行启动多个Agent、将上一阶段结果作为下一阶段输入、按检查结果决定是否重新执行任务，以及在子Agent失败时选择继续或终止。与传统子Agent委派方式相比，后续执行步骤由编排程序直接根据返回数据推进，主Agent不必参与每一次任务交接。据官方文档，单次动态工作流最多累计启动1000个Agent，同时运行的Agent线程上限为64，单次工作流默认最长运行24小时。子Agent之间可通过编排程序传递结果，也可借助会话沙箱中的共享文件系统交换信息，但暂不支持子Agent之间直接互发消息。

📌 总结：Anthropic把多Agent系统的协调逻辑从主Agent的逐步推理转移到模型生成的编排程序，这一架构变化降低了主Agent的上下文压力，也让循环、条件分支和结果传递可以在程序层执行。对Agent平台和核心网运维Agent的架构设计而言，这意味着编排层可以独立于模型推理层进行工程优化，但工作流返回completed仅表示程序执行结束，部分线程失败仍可能以completed收尾，验收逻辑必须检查任务覆盖范围和失败项。共享文件系统带来的文件访问隔离问题也需要在权限和沙箱设计上单独处理。

7、Meta 联合 MIT、Yale 提出 ReHarness，用后向修订让 Agent 记忆可持续学习

智能体平台、协议与执行系统 ReHarness Agent持续学习与后向修订 研发效率提升

📋 要点：Meta MRS Research 联合 MIT、Yale 发布论文《Recurrent Harness for Agentic Continual Learning》，提出 ReHarness 递归 Harness 框架。现有 Agent Harness 的信息只能单向向前流动，经验一旦写入记忆，即使后续发现会导致错误也不会回头修改，导致过时或过度概括的经验被反复调取。ReHarness 在向前读取、向前写入之外加入向后修订：给定当前查询先检索 top-k 经验交给决策 Agent 生成动作，再由专门修订 Agent 针对被调取过的旧经验做检查修改，修改只能参考该经验原始任务记录，当前新任务仅用于判断旧经验好坏，避免信息泄露，最后记忆 Agent 生成互补新经验写入状态。实验在 CL-Bench、MemoryBench、MemoryArena 三个流式基准上，底层用 Claude Opus 4.8、GPT-5.5、Gemini 3.7 Flash，整体标准化增益 0.240，9 组组合中 8 组最优。

📌 总结：ReHarness 把记忆从写完即定改为依据实际使用效果动态校正，全程不改大模型参数、不重复回放历史样本、不需验证数据集，适配真实在线流式环境。对技术路线而言，它把如何更新与更新后保留什么一起评估，可能成为下一代 Agent 运行时的重要组件；对产品架构而言，后向修订机制要求保留原始轨迹并新增修订 Agent，带来额外存储与调用开销，但 token 消耗仍显著低于全量原始上下文方案，为长交互流场景下的记忆调度提供了可落地的折中。

1、Meta 推出 Crossflow 弹性 LLM 服务架构，高负载吞吐最高提升 43.4%

AI推理与服务加速 Meta Crossflow P/D分离与弹性算力租约 成本下降

📋 要点：Meta 团队提出 Crossflow 弹性 LLM 服务架构，针对静态 Prefill-Decode 分离架构难以适配动态需求的问题。实测显示某聊天场景未缓存输入与输出词元比值峰均比最高达 4.7 倍，公开智能体 trace 单日小时级需求比波动中位数达 24.5 倍，按 95 分位分配算力会导致最多 17% 集群算力闲置，而重分区单节点需数分钟到十数分钟。Crossflow 在不改变 P/D 节点角色前提下，由解码节点在 SLO 余量内生成短期多资源租约，临时借出算力处理 Prefill，并配合 Prefill 压力检测、形状感知准入和解码端故障恢复。基于 SGLang 在 GPT-OSS-120B 和 GLM-5.2 上测试，几何平均词元吞吐提升 16.2%-17.4%，高负载最高提升 43.4%，首词元时间下降 10%-57.4%，6 台服务器性能接近静态架构 9 台。

📌 总结：Crossflow 在保留 P/D 分离专业化配置与性能隔离优势的同时，用弹性算力租约解决静态分区资源浪费，不改模型内核也不调整物理拓扑。对技术路线而言，它验证了按 SLO 余量动态借出解码算力处理 Prefill 的可行性，形状感知路由与压力自适应并发控制是性能提升核心来源；对产品架构而言，该方案适合需求波动大、词元消耗高的智能体服务场景，6 台服务器接近静态 9 台的硬件成本对比为推理集群降本提供了可量化参考，相关实现已开源。
