1、人大高瓴提出AEWM，在行动执行前修订Agent错误决策使Terminal-Bench提升11.2个百分点

智能体平台、协议与执行系统 AEWM Agent行动判断与状态修订 体验提升

📋 要点：2026年10月，中国人民大学高瓴人工智能学院提出Agent-Editing World Model（AEWM），针对长程Agent任务中的task-state contamination问题，在行动执行前由Action Judge将候选决策分为Critical、Exploratory、Noisy三类，仅对Noisy决策触发State Revision重新生成推理与行动。在包含3000条决策的Action Judge Benchmark上Macro-F1达70.5%，比最强对照高10.6个百分点。在BrowseComp、DeepSearchQA、Terminal-Bench 2.0、Doc2Repo、NL2Repo、SWE-Bench Pro六项基准、三个Qwen3.5基座上，EditAct均优于ReAct和Best@3基线，平均分提升3.2-6.7个百分点；Qwen3.5-35B-A3B上Terminal-Bench 2.0从37.1%升至48.3%。

📌 总结：AEWM将世界模型关注点从环境返回预测转向Agent下一步行动是否值得执行，为长程Agent提供在线纠偏机制。其AEWM-RFT方案利用EditAct产生的验证轨迹微调Agent，在不再调用AEWM时仍比Self-RFT高2.2-2.6个百分点，BrowseComp平均交互轮数从56.2降至39.3，表明纠偏轨迹可转化为长期能力。该思路对核心网运维Agent、多步工具调用系统的可靠性设计有直接参考价值。

2、UC Berkeley联合Sakana AI提出MASS，多智能体自监督使科研基准输出效率达基座1.6倍

智能体平台、协议与执行系统 MASS 多智能体自监督与递归自改进 研发效率提升

📋 要点：2026年10月，UC Berkeley联合Sakana AI提出Multi-Agent Self-Supervision（MASS）框架，以Qwen3.6-27B为基座，通过内层搜索多智能体协作工作流、外层用执行轨迹做监督微调的交替循环，实现递归自改进。两轮训练后，MLR-Bench、DSBench、ScienceAgentBench、AstaBench四个科研基准的得分/输出token分别达基座1.60、1.35、1.20、1.28倍；MLR-Bench论文交付数从31/60增至50/60，AstaBench报告交付数从60/120增至91/120。裸任务提示下子智能体调用从1/110增至87/110，代码交接从1/110增至83/110。

📌 总结：MASS验证了将多智能体协作经验通过监督微调写入共享权重的可行性，为智能体系统的自改进训练提供了可复用路径。其核心启示在于：输出约定、文件依赖和反馈去向的显式设计可成为自监督资源，统筹决策与局部执行联合训练比单智能体长轨迹模仿更有效。但收益集中在科研任务，Terminal-Bench 2.0和SWE-bench Verified效率比分别为0.96和0.94，通用终端与软件修复任务未同步受益，且未计入流程搜索与数据生成成本。

6、华为开源 JiuwenSwarm 多智能体框架，以 E2A 协议解耦外部渠道

7、Sakana AI联合UC Berkeley提出MASS多智能体自监督方法，探索递归自改进

1、NVIDIA 联合普林斯顿发布 ReplaySSM，缓存 SSM 输入使混合模型解码提速 1.2 至 1.47 倍

AI推理与服务加速 ReplaySSM 混合模型解码 性能提升

📋 要点：混合模型将 SSM 层与少量注意力层交错，SSM 层用固定大小状态替代随上下文增长的 KV 缓存，但在服务批大小下，SSM 层在 100K token 上下文内反而成为解码延迟瓶颈，并让投机解码回滚和状态量化变得困难。NVIDIA 与普林斯顿 Dao AI Lab 联合发布 ReplaySSM，把 SSM 状态表示为检查点加近期输入缓冲，非 flush 步骤只追加输入并计算输出，缓冲填满时才将输入折叠进检查点并写回 HBM，从而把输出计算与状态更新分离。该方案已集成进 TensorRT-LLM、vLLM、SGLang 和 FlashInfer，并在 GLM-5.3-Flash 与 Kimi-K3 生产环境运行。

📌 总结：ReplaySSM 对推理服务架构的实际价值在于三点：状态内存流量约减半，batch size 256 下内核提速 1.46 至 1.80 倍、解码步骤提速 1.20 至 1.47 倍；投机解码无需为每个草稿 token 保存状态快照，验证 8 个 token 约等于一次标准步骤，吞吐达 vLLM 的 1.85 至 2.10 倍；检查点与读取副本分离精度后，NVFP4 读取配 FP32 递推把 128K token 的 KL 从 0.136 降到 0.0038。这为长上下文混合模型的服务成本与显存并发提供了新的工程路线。

2、Cloudflare发布Clef-omni多模态决策模型，单次调用覆盖文本图像音频视频

AI推理与服务加速 Cloudflare Clef-omni 多模态决策模型 成本下降

📋 要点：Cloudflare于2026年10月9日发布Clef-omni，为其Clef决策模型家族的开源权重成员，基于Qwen3-Omni-30B-A3B-Instruct后训练，保留理解主干并去掉文本转语音输出路径，采用30B总参数、3B激活的MoE结构，在Workers AI上提供64000 token上下文。模型对完整载荷做单次prefill，视频帧与音频同步为一条序列联合处理，由联合schema头对选项打分，冻结Qwen3主干并训练LoRA适配器，训练结合标签平滑交叉熵与Brier分数校准。基准上CLINC150+OOS达97.7 macro-F1，但GPQA Diamond仅47.4、低于Jev的78.3。同期Clef-flash价格降至每百万token 0.038美元，托管Clef迁移至SGLang后中位延迟从262毫秒降至152毫秒。

📌 总结：Clef-omni把决策模型从纯文本扩展到文本、图像、音频、视频四模态单次调用，对多模态智能体管线而言可直接省去转录与字幕步骤，降低编排复杂度与token成本；其返回带概率的类型化答案而非生成文本，便于路由、分类和护栏场景直接做阈值判断。同时Clef-flash价格降至0.038美元、托管Clef借SGLang提速1.7至2.0倍，说明决策模型赛道正沿低成本与低延迟方向竞争。但Clef-omni在硬推理与工作流评测上弱于文本专注的Clef，选型时需按任务类型区分。

📋 要点：2026年10月，AutoTrust在Hugging Face发布GLM5.3-Flash-E256-DGX-Spark，这是zai-org/GLM-5.3-Flash面向Blackwell系统的紧凑衍生版本，覆盖DGX Spark集群到单张B200。该版本通过神经架构搜索在每层保留288个路由专家中的256个，专家采用NVFP4量化，每token仍激活18B参数，KV Cache使用FP8，并附带mtp-nvfp4/目录下6.95GB的NVFP4 MTP草稿用于投机解码。在单张B200配合vLLM上，单流解码提速1.84倍，使用3个草稿token时达1.94倍，输出质量不变，模型保留154880词表与完整视觉塔。

1、NVIDIA 联合普林斯顿发布 ReplaySSM，缓存 SSM 输入使混合模型解码提速 1.2 至 1.47 倍

AI推理与服务加速 ReplaySSM 混合模型解码 性能提升

📋 要点：混合模型将 SSM 层与少量注意力层交错，SSM 层用固定大小状态替代随上下文增长的 KV 缓存，但在服务批大小下，SSM 层在 100K token 上下文内反而成为解码延迟瓶颈，并让投机解码回滚和状态量化变得困难。NVIDIA 与普林斯顿 Dao AI Lab 联合发布 ReplaySSM，把 SSM 状态表示为检查点加近期输入缓冲，非 flush 步骤只追加输入并计算输出，缓冲填满时才将输入折叠进检查点并写回 HBM，从而把输出计算与状态更新分离。该方案已集成进 TensorRT-LLM、vLLM、SGLang 和 FlashInfer，并在 GLM-5.3-Flash 与 Kimi-K3 生产环境运行。

📌 总结：ReplaySSM 对推理服务架构的实际价值在于三点：状态内存流量约减半，batch size 256 下内核提速 1.46 至 1.80 倍、解码步骤提速 1.20 至 1.47 倍；投机解码无需为每个草稿 token 保存状态快照，验证 8 个 token 约等于一次标准步骤，吞吐达 vLLM 的 1.85 至 2.10 倍；检查点与读取副本分离精度后，NVFP4 读取配 FP32 递推把 128K token 的 KL 从 0.136 降到 0.0038。这为长上下文混合模型的服务成本与显存并发提供了新的工程路线。
