### 1、Spine 将子任务树编译为结构化上下文，SpineCodex 成本降32.4%且里程碑分升11.8% {#event-248567}

【智能体平台、协议与执行系统】 【Spine】 【子任务树上下文】 【成本下降】

📋 **要点**：2026年10月27日，arXiv 论文针对长程编码任务中智能体顺序记录交互导致上下文膨胀与性能退化的问题提出 **Spine**。现有做法要么压缩裁剪历史而丢失未完成子任务所需信息，要么把每个子任务边界都交给递归子智能体，从而把子任务粒度与执行智能体选择混为一谈并增加协调开销。**Spine** 通过工作域让智能体显式声明子任务边界，同一智能体可就地执行嵌套子任务，仅将独立并行任务留给委派；运行时以 **SpineTree** 持久树记录子任务关系、局部交互、完成状态与返回结果，并在每次模型调用前即时编译为上下文，保留未完成子任务的交互、用结果替换已完成子任务细节，同时保持前缀缓存复用。集成到 **Codex** 得 Spine**Codex**，在 **GPT-5.6 Sol** 下 **SWE-Milestone** 分数提升**11.8%**、总成本降低**32.4%**，**ProgramBench** 平均测试通过率提升**17.3%**，十个 **FrontierSWE** 任务中八个 **Mean**@5 提升；在 **SWE-Milestone** 上以低**73.7%**总成本达到与递归子智能体相当分数。
📌 **总结**：该工作把长程编码智能体的上下文管理从历史压缩或全量委派转向显式子任务边界加即时编译，证明结构化上下文可在提升任务完成度的同时显著降低成本。对技术路线而言，它提示上下文膨胀的根因是缺少子任务完成语义，而非单纯历史过长；对产品架构而言，**Spine**Tree 与前缀缓存复用的组合可直接嵌入现有编码智能体运行时，且通过可复用软件包集成到 Pi 后，在 **Gemini 3.8 Flash** 与 **Qwen 3.8 27B** 上仍带来**9.5%**至**17.5%**的里程碑分提升，说明方案具备跨模型可移植性；对商业判断而言，**32.4%**的**成本下降**与**73.7%**的相对成本优势直接影响编码智能体的单位经济性。
来源：[研究团队](https://arxiv.org/abs/2610.37224)
原文标题：Spine: Compiling Subtask Trees into Structured Context for Long-Horizon Coding Agents

### 2、Evolving Agent Teams多智能体框架突破GPU内核优化局部最优，FlashInfer MLA解码内核提速1.2倍 {#event-248541}

【智能体平台、协议与执行系统】 【Evolving Agent Teams多智能…】 【GPU内核优化】 【性能提升】

📋 **要点**：软件工程智能体的快速进展推动其被应用于**GPU内核优化**等开放式问题，但论文发现现有编码智能体在真实专家编写的内核（如FlashInfer）上会收敛到局部最优。论文提出Evolving **Agent** Teams多智能体框架以跳出局部最优，包含两个机制：一是中央监督者诊断每个局部最优并重构智能体团队；二是持久文件系统，由学习文档、演化历史和每团队产物组成，用积累经验支撑重构。在匹配token预算下，该框架持续超越强编码智能体基线；在扩展token预算下，从零生成CUDA内核，在生产的FlashInfer MLA分页解码内核上取得**1.2倍**平均加速，并在FlashInfer-Bench的47个生产负载中36个胜出，其余11个为0.86-**0.99倍**。此外在AMD MI350X的KDA prefill上比vLLM快**3.01倍**、在**NVIDIA** B200上比FlashKDA快**3.44倍**，在Apple silicon的MoE专家卸载服务上实现Qwen3.8-**Flash-**Next在MLX 4位量化下**30.3 token**s/s解码，在RoboDojo机器人操作上留出种子得分62.1对最佳榜单55.3。
📌 **总结**：该工作把编码智能体从单智能体局部最优推进到可重构团队与经验沉淀的演化范式，并在真实**GPU内核优化**任务上取得可验证加速，说明多智能体协作与持久记忆可显著提升开放式工程优化能力。对预研与平台团队而言，其价值在于提示智能体系统设计应包含监督者诊断与经验沉淀机制，而非单纯增加采样次数；该思路可迁移到核心网网元性能调优、编译优化、算子库开发等场景，但需注意其加速数据来自特定内核与硬件组合，落地前需在目标负载上复现验证。
来源：[研究团队](https://arxiv.org/abs/2610.36848)
原文标题：Evolving Agent Teams

### 3、EMMA用结构化情景记忆提升多智能体工作流合成性能并减少训练执行 {#event-249280}

【智能体平台、协议与执行系统】 【EMMA】 【多智能体情景记忆】 【成本下降】

📋 **要点**：2026年10月，arXiv发布**EMMA**（结构化情景记忆用于多智能体工作流合成）。针对专业领域部署LLM智能体时参数训练成本高且不可解释、手工工程系统依赖专家人力的问题，**EMMA**将多智能体系统配置——包括控制器路由记忆、继承通用提示的专家智能体以及逐步过程技能——统一视为情景记忆。方法显式定义更新的归属与准入：反射器将每个诊断出的失败分配给拥有其修正权的范围，并在该范围内提出一次编辑；与骨干无关的守卫确保每次接受的编辑有界、增量且受范围约束。在KramaBench、AppWorld和BBEH上，配合五种骨干模型与四种基线（**ACE**、**GEPA**、**EvoMAS**、**ADAS**），EMMA在每个基准上均取得最佳整体表现，最高超出最强基线**32.5%**，跨骨干保持一致提升，训练执行次数比最高效基线少17-**38%**。
📌 **总结**：**EMMA**把多智能体系统的演化从依赖骨干模型结构偏好，转为由失败诊断驱动的显式范围化更新，提升了可解释性并降低训练执行成本。对智能体平台团队而言，该机制可作为多智能体工作流合成的记忆与更新层设计参考，尤其适用于多应用导航、数据池分析等复杂任务；对商业判断而言，训练执行减少17-**38%**意味着专业领域智能体适配的算力与人力成本有望下降，但需注意其效果依赖反射器与守卫的实现质量。
来源：[研究团队](https://arxiv.org/abs/2610.35966)
原文标题：EMMA: Structured Episodic Memory for Multi-Agent Workflow Synthesis

### 4、Concordat以类型化会话协议约束LLM智能体高风险操作 {#event-248584}

【智能体平台、协议与执行系统】 【Concordat】 【有限状态协议】 【安全风险】

📋 **要点**：基于大语言模型的智能体越来越多被允许执行取消预订、发放退款、变更账户等有后果的操作，而诸如“变更前须获得客户明确确认”的规则通常只写在提示词中，遵循程度取决于模型自身。该研究提出**Concordat**，一个开源Python库，把智能体视为接口为**有限状态协议**的對象，借鉴类型状态与会话类型思想，在运行时对模型强制该协议：每一轮只向模型提供当前协议状态下合法的工具，集合外的调用在产生副作用前被拒绝，保留给人类的决策只能被请求，token与工具调用预算在交接间线性分摊。协议在定义时即被检查，若子类可能绕过父类协议则被拒绝，构成行为层面的里氏替换。
📌 **总结**：该工作把智能体权限控制从提示词约定升级为运行时强制，在副作用发生前拦截非法调用，为金融、客服、电信运维等高风险场景的智能体落地提供了可验证的工程手段。其结果显示标准智能体在压力下频繁跳过确认，而tau-bench自带奖励未能检测多数违规，说明现有评测对合规行为的覆盖不足，需引入协议级检查。对核心网运维Agent等场景，该模式可映射为网元操作的状态机约束与人工审批节点，降低误操作与越权风险，同时保持任务成功率不下降。
来源：[研究团队](https://arxiv.org/abs/2610.37461)
原文标题：Concordat: Typed Sessions for LLM Agents

### 5、AgentBaton用模型交接策略将智能体任务API成本降低65.9% {#event-249278}

【智能体平台、协议与执行系统】 【AgentBaton】 【模型交接】 【成本下降】

📋 **要点**：2026年10月，arXiv发布**AgentBaton**研究。长时程智能体任务通常依赖云端强模型以保证可靠性，但成本高昂；同时低成本云模型和可本地部署的小型开源模型不断涌现。研究系统考察了通过**模型交接**实现强弱模型协作的关键设计选择，聚焦交接方向与上下文传递。结果发现，高效到强模型的交接通常不如纯强模型执行，成本降低有限甚至没有；而强模型到高效模型在任务进度合适阶段的交接，能在大幅降本的同时保持甚至提升准确率。基于此提出轻量检测器**AgentBaton**，从任务进度的重复模式中学习何时交接。在11组模型对和两个代表性基准上，平均降低API成本**65.9%**，准确率最高提升8.8个百分点。
📌 **总结**：**AgentBaton**把智能体成本优化从查询级路由推进到任务内**模型交接**，证明一次性、时机恰当的强到弱交接即可扩展准确率-成本帕累托前沿。对智能体平台与产品团队而言，该策略可直接嵌入长时程任务运行时，在不牺牲准确率的前提下大幅压缩API支出；对商业判断而言，**65.9%**的平均**成本下降**意味着智能体应用的单位任务经济性显著改善，但需注意其效果依赖交接时机检测器的训练质量与任务进度模式的可识别性。
来源：[研究团队](https://arxiv.org/abs/2610.35959)
原文标题：AgentBaton: Efficient Model Collaboration in Agentic Tasks

### 6、The Trinity递归自改进框架让多模态智能体28项基准平均提升34分 {#event-248463}

【智能体平台、协议与执行系统】 【The Trinity框架】 【递归自改进】 【性能提升】

📋 **要点**：针对多模态智能体扩展中异构可验证环境构建成本高、人工Harness迭代跟不上任务复杂度的问题，论文提出The Trinity**递归自改进**框架，通过Creator、**Explorer**、Evolver三个角色把世界生成与Harness演化耦合起来。Evolver基于已验证执行轨迹，将任务组织依据从表面类别转为共享能力需求，把原任务树重组为分层能力树；Creator对同节点异构任务抽象出可验证简化模拟世界做能力学习，**Explorer**沿能力树通过选择性继承演化可复用能力模块形成Harness树，并引入能力感知Harness路由按公开任务信息选择模块配置。结果显示演化后的Harness在28个训练基准平均提升34分、18个未见基准提升26分，含两个真实具身任务。
📌 **总结**：该框架把智能体能力积累从人工设计Harness转为沿能力树自动演化与复用，显著降低异构环境构建与人工迭代成本，并提升跨任务与跨模态泛化。对智能体平台架构而言，能力树加Harness路由可作为模块化能力复用与调度的参考设计；对预研规划而言，其**递归自改进**思路为多模态智能体持续进化提供了可验证的工程范式。

### 8、CIVER因果干预框架在SWE-Review-Bench上识别77%真实缺陷 {#event-248461}

【智能体平台、协议与执行系统】 【CIVER】 【因果干预】 【研发效率提升】

📋 **要点**：代码评审对维护软件仓库至关重要，可识别缺陷、提升代码质量并支持可靠软件演化。随着基于LLM的编码智能体被广泛采用，越来越多代码贡献和仓库变更由这些智能体生成，基于LLM的代码评审智能体也日益普遍。然而LLM评审者常生成冗长评审，包含大量潜在问题，其中许多是假阳性或缺乏充分证据。这些不可靠评审可能误导开发者和下游编码智能体，因此需要区分可操作发现与无支撑声明。研究提出**CIVER**，一种基于**因果干预**的框架，识别代码评审发现背后的核心问题并区分真实缺陷与假阳性。**CIVER**集成三个模块：评审模块评估发现，干预模块生成面向修复的扰动，验证模块对评审可靠性评分。通过专家迭代联合优化，三模块通过响应针对性修复同时在不相关变更下保持稳定来识别真实缺陷。在SWE-**Review-**Bench上的大量实验表明，CIVER通过针对性修复正确识别**77%**的真实缺陷。跨项目和下游修复评估进一步表明，CIVER可跨仓库泛化并提升编码智能体的任务成功率。
📌 **总结**：该工作将**因果干预**引入代码评审，通过评审、干预与验证三模块联合优化，在SWE-**Review-**Bench上识别**77%**真实缺陷，表明可操作发现与无证据声明可被有效区分。跨项目与下游修复评估显示**CIVER**可泛化并提升编码智能体任务成功率，对自动化代码评审的可靠性提升具有实际价值。对采用LLM编码智能体的软件团队而言，该框架可减少假阳性评审对开发者和下游智能体的误导，提升代码评审效率与软件质量保障能力。

## AI安全、可信与治理

### 1、Heads of Security 用注意力门控将提示注入攻击成功率压至 10% {#event-248382}

【AI安全、可信与治理】 【Heads of Security】 【提示注入防御】 【安全风险】

📋 **要点**：2026年10月，一项 arXiv 论文提出 **Heads of Security**（**HoS**）**提示注入防御**方法，在 **Llama-3.3-**70B**-Instruct** 与 **GPT-OSS-20B** 上验证。**HoS** 通过一小组可学习的逐头注意力门控，让每个注意力头在可信 token 与不可信 token 之间重新分配注意力，从而在模型架构层面强制实现指令与数据分离，使模型能够推理不可信内容而不执行其中注入的指令。对比基于微调的 **SecAlign**++ 与架构级方案 **ASIDE**，HoS 对自适应攻击更鲁棒、在标准效用基准上表现更好，并在标准智能体提示注入基准上达到领先水平。
📌 **总结**：该工作把**提示注入防御**从微调层下沉到注意力架构层，说明指令-数据分离可以作为模型原生能力而非外挂过滤。对技术路线而言，它提供了在保持通用基准效用的同时提升自适应攻击鲁棒性的架构级思路；对 **Agent** 产品与核心网运维智能体而言，意味着可在模型侧降低工具调用与外部内容注入风险，减少对上层规则过滤的依赖，为安全可信的智能体执行系统提供新的设计选项。

### 2、AdvGuard 用语义交互图检测系统提示泄露，多轮场景 F1 达 97.23%-99.1% {#event-248486}

【AI安全、可信与治理】 【AdvGuard】 【系统提示泄露】 【安全风险】

📋 **要点**：大语言模型依赖专有系统提示来执行任务指令、安全策略与访问控制，这些提示易受基于查询的泄露攻击：黑盒对手通过自适应多轮交互提取机密指令。现有防御多独立评估单个查询，忽略跨交互才显现的恶意行为。该研究提出 **AdvGuard**，一个模型无关的**系统提示泄露**检测与缓解框架。**AdvGuard** 用有界语义交互图建模跨查询关系，统计过滤候选组件，并将其转换为线图供图卷积网络分类，从而捕捉查询相似度中的多跳模式，区分协同提取与良性工作流；轻量提示级检测器在交互历史不足时提供前置保护，框架支持黑盒 **LLM** 部署。在混合查询评估中，AdvGuard 召回率较最强基线提升最高 **36%**，误报率不超过 **3.4%**；多轮工作负载下 F1 达 **97.23%**-**99.1%** 且召回率 **100%**；留一攻击族测试平均召回率 **99.98%**、平均 F1 **99.99%**，未观察到误报。
📌 **总结**：该工作把**系统提示泄露**防御从单点查询过滤推进到跨查询关系建模，证明多跳语义图能有效识别协同式提取，为 **LLM** 与智能体平台的安全架构提供可集成组件。其支持黑盒部署、误报率低，适合作为网关或代理层防护，对核心网智能运维助手、企业 **Agent** 等场景的提示与权限保护有直接价值。留一攻击族测试的高召回说明其对未见攻击具备泛化能力，但评估集中于提示泄露这一威胁，对工具投毒、记忆污染等其他 **Agent** **安全风险**仍需另行防护，落地时应与权限沙箱、审计机制组合使用。
来源：[研究团队](https://arxiv.org/abs/2610.36295)
原文标题：Detecting and Mitigating Query-Based System Prompt Leakage Attacks
