### 1、中国人民大学提出AEWM世界模型，用EditAct在Agent执行前纠偏决策 {#event-223033}

【智能体平台、协议与执行系统】 【中国人民大学AEWM】 【世界模型纠偏】 【研发效率提升】

📋 **要点**：针对长任务中错误留在历史里形成任务状态污染、持续误导决策的问题，中国人民大学提出AEWM，把世界模型关注点从环境会返回什么转向这一步会把任务带向哪里。其EditAct流程分三步：**Action** Judge在执行前只看已有历史和当前提议，区分关键推进、有效探索与噪声决策；仅对噪声决策调用State **Revision**，同时替换当前推理与行动，保留此前历史且不编造工具反馈；真实工具执行保留或修改后的行动，新推理、行动和实际反馈一起进入后续历史。AEWM基于Qwen3.5-**35B**-**A3B**，在搜索、终端和软件工程三个领域统一训练，先用**52.16B** tokens做mid-training，再用**12万**条高质量样本SFT，判断与修订各占一半，判断标签来自完整轨迹回溯标注但模型输入不含未来信息。在含3000条决策的**Action** Judge基准上，AEWM的macro-F1达到**70.5%**，超过最强对照10.6个百分点；接入EditAct后，**4B**、**9B**、**35B**-**A3B**三个Agent的六项基准平均分分别比最强基线高6.7、5.2、3.2分。
📌 **总结**：AEWM的价值在于把外部纠偏转化为Agent自身能力：消融显示直接编辑优于判错后让Agent重采样和只给推理提示，只改推理或只改行动也都不如一起改。以**35B**-A**3B**为例，相对ReAct，BrowseComp从40.9提升到48.1，**Terminal-Bench 2.**0从37.1提升到48.3；搜索行为上最长连续搜索序列均值从16.9降到13.2，每题访问不同网页数从7.7升到10.1，表现为更少连续搜索、更多页面阅读。**AEWM-**RFT用EditAct生成并经验证筛选的高质量轨迹微调Agent，测试时不再调用AEWM，相对Self-RFT三个领域分数再提高2.2至2.6个百分点，BrowseComp和**Terminal-Bench 2.**0平均轮数分别下降**30.0%**和**16.7%**。这为智能体运行时设计提供了新思路：世界模型未必需要复刻环境，也可以学习决策如何影响任务进展，并在错误扩大前改写当前决策，对核心网运维Agent等长任务场景具有参考价值。

### 2、LangChain通过harness工程将编码智能体Terminal Bench排名从30名外提升至前5 {#event-222314}

【智能体平台、协议与执行系统】 【deepagents-cli】 【harness工程】 【性能提升】

📋 **要点**：2026年10月，**LangChain**披露其编码智能体**deepagents-cli**在Terminal **Bench 2.**0上从52.8分提升至66.5分，提升13.7分，排名从30名外进入前5，且模型固定为gpt-5.2-codex，仅调整harness。改进手段包括：通过LangSmith trace分析构建Trace **Analyzer** Skill定位失败模式；在系统提示中加入规划-构建-验证-修复流程并配合PreCompletionChecklistMiddleware强制自验证；用LocalContextMiddleware注入目录与工具上下文；用LoopDetectionMiddleware检测重复编辑；采用xhigh-high-xhigh的推理预算分配。
📌 **总结**：该实验说明在模型不变的前提下，**harness工程**可通过自验证、trace驱动调试、上下文注入与推理预算分配显著提升Agent任务表现，为Agent性能优化提供了独立于模型升级的第二条路径；对研发团队设计Agent harness、构建trace反馈闭环与评估中间件价值具有直接参考意义，也提示harness设计需针对不同模型定制。

### 3、上海 AI 实验室联合多校提出 Real2Gym，真机技能复用使 token 用量降 74.9% {#event-223072}

【智能体平台、协议与执行系统】 【Real2Gym 视频到仿真技能复用】 【阶段级代码决策】 【研发效率提升】

📋 **要点**：来自上海人工智能实验室、上海交通大学、浙江大学、中国科学技术大学、香港中文大学和香港大学的研究团队提出 **Real2Gym**，针对仿真场景重建得像却无法复现视频操作的问题，把动作能否在物理引擎中完成作为场景验收条件。系统对多视角视频利用 **Pi3X** 几何线索并结合 **SAM2** 分割关联不同视角物体，约束尺度与位置后构建可编辑 **Blender** 场景及对应 **MuJoCo** 环境；单视角输入采用相应几何初始化方案。随后围绕物体被抓起、接触支撑面、夹爪释放等交互关键帧，由智能体自检视角、布局、接触与外观并局部修正，修正后的动作在 **MuJoCo** 中执行并核查支撑、接触与稳定性，轨迹再导回 **Blender** 与原视频对照。
📌 **总结**：在 **DROID** 与 **EgoDex** 的 24 个场景评估中，**Real2Gym** 在内容对齐、视角对齐、动作保真度和仿真成功评分上优于所比较的 **GPT** 基线；复用首轮经验后的第二次执行平均成功率达 **87.5%**，**GPT**-6 Astra Direct Mode 基线为 **70.8%**，策略执行 token 用量减少约 **74.9%**，平均模型响应次数从约 31 次降至约 14 次。在 **Franka** 机械臂的方块入盘、挂杯、杯子放入微波炉并关门三项任务各 3 次尝试中均成功，盘子上架任务经仿真迭代后也完成。该工作把自我改进落在技能库更新而非权重更新，为机器人操作经验复用与仿真到真机迁移提供可验证路径，但点云噪声与精细操作控制仍有改进空间。

### 5、腾讯云 TencentDB Agent Memory 接入 JEV 决策服务，Skill 召回冗余 token 降近四成 {#event-223016}

【智能体平台、协议与执行系统】 【TencentDB Agent Memory】 【JEV决策服务与Skill召回】 【成本下降】

📋 **要点**：**腾讯云** **TencentDB Agent Memory** 引入可插拔决策服务，将是否召回、选择哪些候选资产、是否触发记忆更新等判断抽象为独立接口，并提供 **JEV** 接入示例。**JEV** 在两个在线决策点工作：召回侧在权限允许范围内对候选编号和说明做一次结构化判断，确定使用后再加载内容；生成侧在场景记忆 L2 更新后，比较当前 L3 与新增 L2 信息，按冲突、适用边界变化、新规则、信息强化、无变化分类，前三类立即更新，信息强化延迟，无变化跳过。实测 **Skill** 召回中主模型重复注入 token 从 24.96M 降至 15.04M，**SWE-bench Pro** 长难题通过数由 **30%** 升至 **40%**；记忆生成侧总成本降低 **13.8%**，L3 生成调用减少 **39.7%**。
📌 **总结**：该方案把范围明确的选择与触发判断从主模型剥离，让主模型专注任务分析与执行，为 **Agent** 记忆系统提供了快路径管时机、慢路径管内容的工程分工。对技术路线而言，决策服务可插拔意味着团队可按任务特点、部署环境和评估结果替换判断模型，降低对单一主模型的耦合；对产品架构而言，**Memory** 从翻历史升级为连接经验积累、上下文组装与能力改进的中间层，有助于把个人经验沉淀为可被下一个 **Agent** 复用的团队资产。

### 6、Anthropic为Claude上线动态工作流，由模型生成多Agent编排程序 {#event-222509}

【智能体平台、协议与执行系统】 【Anthropic Claude Dynami…】 【多Agent编排】 【架构替代】

📋 **要点**：2026年10月9日，**Anthropic**为Claude **Managed** Agents上线Dynamic **Workflows**，目前处于Beta阶段。该机制由Claude根据任务需求生成一段编排程序，程序包含实际执行逻辑，例如并行启动多个Agent、将上一阶段结果作为下一阶段输入、按检查结果决定是否重新执行任务，以及在子Agent失败时选择继续或终止。与传统子Agent委派方式相比，后续执行步骤由编排程序直接根据返回数据推进，主Agent不必参与每一次任务交接。据官方文档，单次动态工作流最多累计启动1000个Agent，同时运行的Agent线程上限为64，单次工作流默认最长运行**24小时**。子Agent之间可通过编排程序传递结果，也可借助会话沙箱中的共享文件系统交换信息，但暂不支持子Agent之间直接互发消息。
📌 **总结**：**Anthropic**把多Agent系统的协调逻辑从主Agent的逐步推理转移到模型生成的编排程序，这一架构变化降低了主Agent的上下文压力，也让循环、条件分支和结果传递可以在程序层执行。对Agent平台和核心网运维Agent的架构设计而言，这意味着编排层可以独立于模型推理层进行工程优化，但工作流返回completed仅表示程序执行结束，部分线程失败仍可能以completed收尾，验收逻辑必须检查任务覆盖范围和失败项。共享文件系统带来的文件访问隔离问题也需要在权限和沙箱设计上单独处理。

### 7、Meta 联合 MIT、Yale 提出 ReHarness，用后向修订让 Agent 记忆可持续学习 {#event-223017}

【智能体平台、协议与执行系统】 【ReHarness】 【Agent持续学习与后向修订】 【研发效率提升】

📋 **要点**：**Meta** MRS Research 联合 **MIT**、**Yale** 发布论文《**Recurrent Harness** for **Agentic Continual Learning**》，提出 **ReHarness** 递归 **Harness** 框架。现有 **Agent** **Harness** 的信息只能单向向前流动，经验一旦写入记忆，即使后续发现会导致错误也不会回头修改，导致过时或过度概括的经验被反复调取。**ReHarness** 在向前读取、向前写入之外加入向后修订：给定当前查询先检索 top-k 经验交给决策 **Agent** 生成动作，再由专门修订 Agent 针对被调取过的旧经验做检查修改，修改只能参考该经验原始任务记录，当前新任务仅用于判断旧经验好坏，避免信息泄露，最后记忆 Agent 生成互补新经验写入状态。实验在 **CL-Bench**、**MemoryBench**、**MemoryArena** 三个流式基准上，底层用 **Claude Opus 4.8**、**GPT-5.5**、**Gemini 3.7 Flash**，整体标准化增益 0.240，9 组组合中 8 组最优。
📌 **总结**：**ReHarness** 把记忆从写完即定改为依据实际使用效果动态校正，全程不改大模型参数、不重复回放历史样本、不需验证数据集，适配真实在线流式环境。对技术路线而言，它把如何更新与更新后保留什么一起评估，可能成为下一代 **Agent** 运行时的重要组件；对产品架构而言，后向修订机制要求保留原始轨迹并新增修订 **Agent**，带来额外存储与调用开销，但 token 消耗仍显著低于全量原始上下文方案，为长交互流场景下的记忆调度提供了可落地的折中。

### 8、谷歌ADK覆盖Python、Go、TypeScript、Java、Kotlin五种语言 {#event-221478}
