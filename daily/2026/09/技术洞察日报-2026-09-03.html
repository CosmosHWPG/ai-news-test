1、TRIAGE 三层路由框架通过轨迹复用实现 LLM 智能体零 token 成本执行

智能体平台、协议与执行系统 TRIAGE 轨迹复用 成本下降

📋 要点：2026年9月1日，一项发表于 arXiv 的研究提出了 TRIAGE，一个三层路由框架，通过复用历史执行轨迹来减少 token 消耗。其核心创新是 TaaS（Trajectory-as-a-Skill），将历史执行轨迹抽象为可复用技能。TRIAGE 将查询分为三个级别：1）直接复用——相同查询，0 token；2）技能替换——相似查询，通过确定性参数替换实现0 token；3）完整 ReAct——新查询，自动存储以供未来复用。在1007个安全监控查询的大规模实验中，TRIAGE 实现了62.3%的 token 节省，其中56.0%的查询在 Level 2、5.5%在 Level 1，均以零成本执行。在 ToolBench 的跨领域验证中实现了76.3%的 token 减少。在线学习实验显示，L2 命中率在前100个查询内从0%上升到57%，平均 token 成本从198降至74.7。

📌 总结：TRIAGE 对智能体平台、协议与执行系统领域具有重要影响，它提供了一种简单而高效的轨迹复用机制，可以显著降低智能体系统的推理成本和延迟。对于技术主管和 AI 前沿技术预研规划师而言，TRIAGE 的设计思路——将历史经验抽象为可复用技能——可以直接应用于网络运维智能体、客服智能体等需要处理大量重复或相似查询的场景，从而提升系统效率和用户体验。

2、推理级联自改进循环存在盲点：验证器接受错误答案比例随学生能力增长而上升

📋 要点：推理级联通过用小模型回答大部分查询、将困难尾部升级到前沿模型来降低成本。研究团队测量了真实 LLM 上的自改进循环，发现四个关键结果：验证器盲点（接受学生错误答案的比例）随学生能力增长而扩大（β 从 0.12 到 0.55），在廉价学生-廉价验证器组合中最严重；使用前沿验证器可将 β 降至约 0.05，但会导致 46% 的查询升级到前沿模型；基于验证器拒绝的纠正微调不会改善小模型，反而使其退化甚至崩溃；级联自身仪表盘显示平坦的 3% 错误率，而真实交付错误率高达 32%。研究给出了解释盲点的理论：两总体守恒定律 ε∞ ≲ q₀β₀，其中每个环内指标改善而真实质量不改善。
