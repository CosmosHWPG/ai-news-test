### 1、TRIAGE 三层路由框架通过轨迹复用实现 LLM 智能体零 token 成本执行 {#event-159631}

【智能体平台、协议与执行系统】 【TRIAGE】 【轨迹复用】 【成本下降】

📋 **要点**：2026年9月1日，一项发表于 arXiv 的研究提出了 **TRIAGE**，一个三层路由框架，通过复用历史执行轨迹来减少 token 消耗。其核心创新是 **TaaS**（**Trajectory-as-a-Skill**），将历史执行轨迹抽象为可复用技能。**TRIAGE** 将查询分为三个级别：1）直接复用——相同查询，**0 token**；2）技能替换——相似查询，通过确定性参数替换实现**0 token**；3）完整 **ReAct**——新查询，自动存储以供未来复用。在1007个安全监控查询的大规模实验中，TRIAGE 实现了**62.3%**的 token 节省，其中**56.0%**的查询在 **Level** 2、**5.5%**在 **Level** 1，均以零成本执行。在 **ToolBench** 的跨领域验证中实现了**76.3%**的 token 减少。在线学习实验显示，L2 命中率在前100个查询内从**0%**上升到**57%**，平均 token 成本从198降至74.7。
📌 **总结**：**TRIAGE** 对**智能体平台、协议与执行系统**领域具有重要影响，它提供了一种简单而高效的**轨迹复用**机制，可以显著降低智能体系统的推理成本和延迟。对于技术主管和 AI 前沿技术预研规划师而言，**TRIAGE** 的设计思路——将历史经验抽象为可复用技能——可以直接应用于网络运维智能体、客服智能体等需要处理大量重复或相似查询的场景，从而提升系统效率和用户体验。
来源：[研究团队](https://arxiv.org/abs/2609.01428)
原文标题：TRIAGE: Three-level Routing and Intelligent Agent Guidance for Efficient Execution

### 2、实时追踪模型以 14 倍更少 token 实现更高准确率，为长程智能体监控提供高效方案 {#event-158642}

【智能体平台、协议与执行系统】 【实时追踪】 【状态折叠】 【成本下降】

📋 **要点**：长程智能体的追踪超出人类观察者和智能体自身的上下文窗口。研究团队提出**实时追踪**模型，一个仅追加的事件账本，增量折叠为类型化运行状态并编译为每个消费者的视图。在观察者侧，以 **LLM** 阅读器为代理，编译视图使用约 14-**15 倍**更少的输入 token 和 5-**7 倍**更低成本回答监控问题，准确率更高（0.85-0.87 对比 0.48）。在智能体侧，120 链接顺序依赖任务中，维护每步运行统计的机制成功完成 30/30，而全上下文提示仅 8/30。折叠的剩余价值包括确定性可审计性和从同一状态服务观察者。
📌 **总结**：该追踪模型为长程智能体的监控和状态管理提供了高效方案。通过增量折叠而非全量回放，大幅降低了 token 消耗和成本，同时保持了更高的准确率。对于需要监控长程智能体运行的企业级应用，该方法提供了实用的工程方案。对于 AI 预研规划师，该工作展示了如何通过结构化状态管理解决长程任务中的上下文窗口限制问题，这一设计模式可推广到其他需要长期状态追踪的场景。
来源：[研究团队](https://arxiv.org/abs/2609.01466)
原文标题：Parsing the Stream: A Live Trace Model for Long-Horizon Agents and Their Observers

### 3、Harness-of-Harness框架实现多日自主软件开发，迭代后平均提升52.25% {#event-158643}

【智能体平台、协议与执行系统】 【Harness-of-Harness】 【自主软件开发】 【研发效率提升】

📋 **要点**：2026年9月2日，arXiv论文提出**Harness-of-Harness**（**HoH**）框架，使LLM-based编码Agent能够在**自主软件开发**中持续改进。**HoH**在现有编码Agent harness之上组织迭代规划-编码-测试循环，通过平衡修复与能力增长、将开发范围限定为小且可验证的增量、分离实现时测试与独立评估、约束可验证输出而非规定Agent工作流等机制，实现持续改进。在GameCraft-**Bench**、FrontierSWE和Program**Bench**上，三个harness-model对（**Codex+GPT-5.5**、**OpenCode+DeepSeek-V4-Pro**、**Pi+MiniMax-M3**）均优于对应独立harness，三次迭代后平均相对提升**52.25%**，最大提升**82.86%**。在超过70次迭代的多日部署中，HoH自主开发出一款第一人称射击游戏，包含连贯故事线、完整核心机制和可玩体验。
📌 **总结**：HoH框架为长期自主Agent系统提供了可复用的工程范式，证明了通过迭代改进，编码Agent可以完成从需求到可玩软件的完整开发流程。对AI前沿技术预研规划师和技术主管而言，该框架的“平衡修复与能力增长”“分离测试与评估”等机制可直接应用于网络运维Agent、自动化测试等场景。对5G/6G标准专家，该工作展示了Agent在复杂工程任务中的潜力，对核心网自动化配置和故障恢复的Agent化演进具有参考价值。
来源：[研究团队](https://arxiv.org/abs/2609.01481)
原文标题：Harness-of-Harness: Multi-Day Autonomous Software Development with Continual Improvement

### 5、门控记忆路由通过学习执行记忆降低多智能体系统推理成本 {#event-158443}

【智能体平台、协议与执行系统】 【门控记忆路由】 【多智能体】 【成本下降】

📋 **要点**：基于 **LLM** 的**多智能体**系统通过编排多个智能体的配置和协作来解决复杂推理问题。**门控记忆路由**提出一种方法，将每个决策基于查询和学习到的执行记忆。学习到的记忆写入门控仅提交非冗余推理步骤，学习到的检索门控为每个智能体提供紧凑的相关子集，使每个决策基于干净、信息丰富的状态。在每一步，系统从该记忆中选择下一个角色和骨干模型，而自适应停止控制器在记忆包含足够证据时停止执行。在五个推理和代码生成基准上，该方法在达到最佳平均准确率（超过最强基线 2.44 个百分点）的同时，将 **HumanEval** 推理成本降低 **31.9%**。代码已开源。
📌 **总结**：该工作为**多智能体**系统提供了高效的记忆管理方法，直接解决了执行历史过载导致的成本膨胀问题。对于智能体平台和推理成本优化领域的技术主管和预研规划师而言，**门控记忆路由**的学习式写入和检索机制可集成到现有智能体框架中，在保持或提升准确率的同时显著降低推理成本。该工作也展示了如何通过自适应停止控制来避免不必要的计算，这对构建成本高效的智能体系统具有实际指导意义。
来源：[研究团队](https://arxiv.org/abs/2609.00237)
原文标题：Learning What to Retain: Gated-Memory Routing for Efficient Collaboration in Multi-Agent LLM Systems

### 1、吴恩达团队提出Prefix Sliding方法，丢弃中间推理token实现3倍推理加速 {#event-159176}

【AI推理与服务加速】 【Prefix Sliding】 【KV缓存】 【性能提升】

📋 **要点**：2026年9月2日，吴恩达团队发表论文并开源**Prefix Sliding**方法。核心洞察来自对Qwen3-**1.7B**在AIME25推理轨迹上的注意力分布可视化：前缀（尤其是前4个token作为attention sink）和最近约1000个token分走了绝大部分注意力，中间推理token几乎无人关注。**Prefix Sliding**规则为保留前缀+保留滑动窗口（如**4096 token**），其余丢弃，使每生成一个新token的成本变为常数。在AIME25、**GPQA Diamond**、MATH500上，相同思考时间内准确率全面优于full attention，最高提速**3倍**。配合截断反向传播，可将RL训练中的推理轨迹扩展到**10万**token以上。团队为Nvidia Hopper架构手写了基于FlashAttention的自定义kernel。
📌 **总结**：**Prefix Sliding**为长程推理和Agent场景提供了一种高效、零额外生成开销的上下文管理方案。其“有界成本”特性是实现无限测试时扩展的关键前提，且可直接应用于现有模型无需重新训练。对技术主管和预研规划师而言，该方法可显著降低长上下文Agent的推理成本，对网络运维Agent、多轮对话系统等场景具有直接工程价值。对5G/6G标准专家，该方法在核心网AI推理中的长上下文处理场景（如NWDAF的长时间序列分析）具有潜在应用价值。

### 2、推理级联自改进循环存在盲点：验证器接受错误答案比例随学生能力增长而上升 {#event-158641}

【AI推理与服务加速】 【推理级联】 【验证器盲点】 【安全风险】

📋 **要点**：**推理级联**通过用小模型回答大部分查询、将困难尾部升级到前沿模型来降低成本。研究团队测量了真实 **LLM** 上的自改进循环，发现四个关键结果：**验证器盲点**（接受学生错误答案的比例）随学生能力增长而扩大（β 从 0.12 到 0.55），在廉价学生-廉价验证器组合中最严重；使用前沿验证器可将 β 降至约 0.05，但会导致 **46%** 的查询升级到前沿模型；基于验证器拒绝的纠正微调不会改善小模型，反而使其退化甚至崩溃；级联自身仪表盘显示平坦的 **3%** 错误率，而真实交付错误率高达 **32%**。研究给出了解释盲点的理论：两总体守恒定律 ε∞ ≲ q₀β₀，其中每个环内指标改善而真实质量不改善。
📌 **总结**：该研究揭示了**推理级联**自改进循环的根本性缺陷：系统通过自身验证器计算的指标无法反映真实质量下降。这一发现对依赖级联策略降本的系统设计有重要警示：自改进循环可能产生虚假的安全感，实际质量可能远低于仪表盘显示。对于 AI 预研规划师，该工作强调了独立验证机制的重要性，以及在使用级联策略时需要谨慎评估真实质量而非仅依赖内部指标。
来源：[研究团队](https://arxiv.org/abs/2609.01345)
原文标题：Cheap Verifiers, Large Blind Spots: Measuring the Reliability Cost of Cost-Saving Cascades

### 3、CacheBridge实现高效跨模型KV缓存传输，存储减少8倍，速度提升3倍 {#event-158533}

【AI推理与服务加速】 【KV缓存】 【跨模型传输】 【成本下降】

📋 **要点**：多模型系统中LLM之间的上下文共享需要接收模型预填充共享前缀，因为**KV缓存**是模型特定的。最近的闭式跨模型KV传输（全头映射）通过拟合无训练仿射映射器避免了这种重放，但其全头设计使传输质量对架构差异敏感，且映射器存储和应用成本随层支持增长。CacheBridge协同设计了架构索引映射器支持、注意力对齐校准和有界映射器构建，同时保留闭式仿射接口用于在线部署。CacheBridge将每个目标头限制为匹配的源头，按因果注意力敏感性加权重构误差，并使用融合GPU内核构建加权充分统计量，无需物化完整观察张量。在三个传输方向上，CacheBridge恢复了全头映射丢失大量准确性的两个Ministral 3传输方向，同时在Qwen3上保留**99.83%**的平均目标性能。在Qwen3 **14B**→**32B**上，映射器存储减少**8倍**，应用加速最多**3.0倍**，使用十分之一的校准数据匹配全头映射，500序列构建从**92.63秒**减少到**8.63秒**（**10.7倍**）。
📌 **总结**：该研究对**AI推理与服务加速**领域具有重要价值。CacheBridge通过架构索引映射和注意力对齐校准，解决了跨模型**KV缓存**共享的效率问题，在存储、速度和校准数据需求上均实现了显著优化。对于技术主管，该技术可直接用于构建多模型推理服务系统，实现高效的上下文共享和模型切换。对于AI前沿技术预研规划师，该研究提出的注意力对齐校准和有界映射器构建方法，为跨模型知识迁移提供了新思路。

### 2、分布式隐式危害DIH揭示多模态视频审核中的组合安全盲点 {#event-158198}

【AI安全、可信与治理】 【多模态安全】 【组合危害】 【安全风险】

📋 **要点**：针对多模态大语言模型在视频审核中的组合安全盲点，研究者提出分布式隐式危害（**DIH**）概念：由看似无害的组件组合而成的视频在整体解读时可能传达有害含义。研究聚焦两种代表性情况：跨视觉片段的时间分布危害和音视频流之间的跨模态危害。为弥补数据缺失，开发了多智能体合成框架，生成超过9000个带有推理标注的**DIH**视频。对30多个MLLM（包括前沿专有模型和领先开源系统）的评测显示，它们在检测两种DIH时均存在持续且显著的缺陷，前沿模型也常能正确评估孤立组件但无法识别**组合危害**。
📌 **总结**：该工作识别并系统化了多模态视频审核中的一个关键安全盲点，为安全评测基准和模型改进提供了新方向。对于内容审核和安全AI系统的研发具有重要参考价值。
来源：[研究团队](https://arxiv.org/abs/2609.00206)
原文标题：Distributed Implicit Harm: A Compositional Safety Blind Spot in MLLM-Based Video Moderation
