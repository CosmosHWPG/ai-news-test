### 1、Google Research 提出 RRSI，正则化智能体框架自改进降低 30% token 消耗 {#event-191488}

【智能体平台、协议与执行系统】 【RRSI】 【递归自改进】 【研发效率提升】

📋 **要点**：**LLM** 智能体的能力很大程度上由其 harness（提示、控制流、工具、记忆与上下文管理）放大，近期方法通过迭代提出并选择组件级编辑来自动化这一过程，形成智能体系统层面的**递归自改进**（**RSI**），但此类演化容易记忆训练任务而过拟合，表现为分布内增益大、分布外基准增益缩小甚至消失。**Google Research** 提出 **RRSI**，将正则化原则引入 harness 自改进：提议器采用时间退火预算限制单个候选可捆绑的编辑数量，并基于演化历史鼓励未探索轨迹；选择器配备 critic 与 pruner，前者筛除基准特定提案，后者移除过小、过贵或不再有用的改动。
📌 **总结**：在覆盖编码、智能体工作区与工程设计任务的八个基准上，**RRSI** 在演化集上最高提升 14.1 分，在五个分布外基准上最高提升 4.7 分，同时产出的 harness 比未正则化演化少用 **30%** 策略 token。对技术路线而言，这为智能体框架自动优化提供了抑制过拟合、偏好可复用机制的方法论，可降低智能体系统迭代中的算力与 token 成本；代码与项目页已公开，便于工程团队复现并用于自研 **Agent** 平台的 harness 优化。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.24972)
原文标题：RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

### 2、Jev-Mem提出System-One控制智能体记忆，LoCoMo评分0.777且构建提速6.6倍 {#event-191496}

【智能体平台、协议与执行系统】 【Jev-Mem】 【智能体记忆架构】 【性能提升】

📋 **要点**：智能体记忆对长时程AI智能体日益重要，但许多现有系统依赖自回归LLM控制记忆的组织、检索和使用方式，将昂贵生成放在记忆操作的关键路径上。该论文提出**Jev-Mem**，一种受System-**One**/**System-**Two认知启发的**智能体记忆架构**：System-**One**负责快速轻量决策，**System-**Two负责较慢的审慎推理。**Jev-Mem**通过专用System-One控制平面、结构化多关系记忆平面和System-Two推理平面实现分工，System-One控制器在构建阶段管理记忆类型和关系组织，在检索阶段动态执行查询路由、检索预算分配、图遍历、候选评分和自适应停止，System-Two仅在复杂推理和答案合成时调用。在LoCoMo上，Jev-**Mem**取得LLM-as-a-Judge总分0.777，较最强基线相对提升**11.0%**，记忆构建时间降至**158秒**、较最快竞争系统提速**6.6倍**，平均查询延迟降至**0.93秒**、降低**36.7%**。
📌 **总结**：该工作为长时程智能体记忆提供了效率与效果兼顾的架构范式，把昂贵生成从记忆关键路径移出，对智能体平台的记忆系统设计有直接参考价值。对AI前沿技术预研规划师而言，**System-**One控制平面和自适应停止机制可迁移到其他智能体记忆和检索系统；对技术主管而言，**6.6倍**构建提速和**36.7%**延迟降低意味着长时程智能体的部署成本显著下降；对商业主管而言，该架构提示记忆系统可作为智能体产品的差异化能力，而非单纯的成本中心。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.23986)
原文标题：Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents

【智能体平台、协议与执行系统】 【EdgeGen】 【合成边缘案例】 【研发效率提升】

📋 **要点**：2026年9月，针对工具调用大模型智能体在企业部署中缺乏高质量多样化任务数据集、现有合成方法生成通用任务且忽略智能体底层状态或数据库的问题，**EdgeGen** 提出合成任务生成框架，从智能体规范中提取合规规则，并据此生成数据库接地的边缘案例任务，这些任务被设计为违反上述规则。与现有合成数据生成技术结合后，**EdgeGen** 通过微调和 harness 优化提升智能体能力，形成无需人工标注的全自动闭环系统。在 tau2bench 航空域上，用 EdgeGen 生成数据微调带来 **2%** 至 **42%** 的平均进度提升，而其他基线方法对部分模型出现退化；在 harness 优化方面，该方法对 **Gemma-4-e4b** 模型较人工整理和基础 harness 分别带来 **10%** 和 **30%** 的平均进度提升。
📌 **总结**：**EdgeGen** 的价值在于把合规规则转化为可自动生成的边缘案例任务，使工具调用智能体在隐私受限、难以获取真实任务数据的企业场景下仍可进行评测和优化。对技术路线而言，从智能体规范提取合规规则并生成数据库接地任务的方法，可作为 **Agent** 评测数据集构建和 harness 优化的参考；对产品架构而言，全自动闭环无需人工标注，有利于降低企业智能体持续优化的数据成本。该工作若被 **Agent** 平台采纳，可能推动边缘案例合成成为工具调用智能体上线前的标准评测环节。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.24115)
原文标题：EDGEGEN: Improving Tool-Calling Agents Beyond Happy Paths with Synthetic Edge Case Generation

### 4、TypeSafe发布Jev判断模型，LangChain测试其Agent评估器表现 {#event-188214}

【智能体平台、协议与执行系统】 【TypeSafe Jev】 【Agent评估器】 【成本下降】

📋 **要点**：2026年9月15日，**TypeSafe** AI发布Jev模型，将其定位为System **One Models**，接收程序状态或文本后快速返回结构化判断结果及概率，提供Noul、**Choice**、Score三类判断形式。9月20日LangChain发布Jev-as-a-Judge实验，让Jev与GPT-5.6 **Luna**、**GPT-**5.6 T**erra**、**Claude Sonnet 4.**6对固定Agent输出反复评分，小规模测试中Jev平均每次调用约**0.44秒**、成本约0.00035美元，连续评分一致性表现突出。开发者Matthew Berman的实验用Jev分析37个品牌724条实时广告、产生8724次判断，约**40秒**完成、Token成本约9美分、每条广告中位处理时间约216毫秒。社区还出现fast-jev-compaction等Claude Code插件，用Jev评分压缩上下文，以及浏览器Agent用Jev选择下一步动作的开源项目。

### 1、D-RAC 用 PDF 归一化与多模态 Markdown 转换降低企业文档分块成本 77.8% {#event-191491}

【AI推理与服务加速】 【D-RAC】 【RAG 文档摄入】 【成本下降】

📋 **要点**：企业知识库的检索增强生成系统需要摄入 **PDF**、**Word**、演示文稿和扫描件等异构文档格式，其内容常被锁定在复杂视觉布局、多栏页面和密集表格中。基于规则的提取和 **OCR** 会破坏阅读顺序、压平表格并丢失标题层级，而基于提取文本的全智能体分块则带来高 token 成本和幻觉风险。研究者提出 **Document Retrieval-Aware Chunking**（**D-RAC**），将 **W-RAC** 框架扩展到任意文档格式。**D-RAC** 首先将任意输入文档归一化为 **PDF**，利用几乎所有格式都有忠实确定性 PDF 渲染的特性；随后单次多模态 **LLM** 将渲染页面转换为检索优化 **Markdown**，将表格改写为自包含散文语句并保留标题层级；之后分块按 **W-RAC** 方式确定性解析为 ID 可寻址单元，再基于标识符而非文本进行轻量 **LLM** 分块规划。在 **RAG-Multi-Corpus** 基准的 236 文档 795 页 PDF 子集上，D-RAC 在 **72 分钟**内零错误转换和分块整个语料，产生 1748 个检索就绪块。与前沿 LLM 的智能体分块相比，D-RAC 将分块阶段输出 token 减少 **95.7%**，分块成本降低 **77.8%**（**GPT-4.1** 定价）至 **85.6%**（**Gemini 2.5 Pro** 定价），分块时间减少 **75%**，并可线性扩展到 500 页以上文档。
📌 **总结**：**D-RAC** 把企业文档 **RAG** 摄入从规则提取和全智能体分块推进到 **PDF** 归一化加单次多模态转换，在保持确定性和可观测性的同时大幅降低 token 成本和幻觉风险。对 **RAG** 技术路线而言，这意味着文档摄入环节可成为独立优化对象，而非简单依赖 **OCR** 或全智能体分块；对企业知识库产品架构而言，**77.8%** 至 **85.6%** 的**成本下降**和 **75%** 的时间减少可能显著降低大规模文档入库的运营成本。该工作也提示多模态 **LLM** 在文档转换中的单次调用即可替代复杂的智能体分块流程。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.24220)
原文标题：Document Retrieval-Aware Chunking (D-RAC): Universal Retrieval-Aware Ingestion of Enterprise Documents via PDF Normalization and Multimodal Markdown Conversion

### 2、Fireworks AI 发布 FireRouter，多模型路由把 DeepSWE 通过率从 74.1% 提到 97.6% {#event-192247}

【AI推理与服务加速】 【FireRouter】 【模型路由】 【成本下降】

📋 **要点**：**Fireworks AI** 发布 **FireRouter**，并基于 **DeepSWE** v1.1 的113个工程任务、18个模型做了路由潜力分析。分析显示，最佳单模型 **GPT-6 Astra** 通过率为**74.1%**、单任务成本6.52美元；而按任务选择最优模型的 oracle 路由可达**97.6%**、成本1.88美元，仅用开源权重模型也能达到**90.3%**、1.45美元。**FireRouter** 在任务级跨开源与闭源**模型路由**，并具备缓存感知能力，避免切换模型时丢弃已付费上下文。
📌 **总结**：该结果说明模型能力已分散在模型池中，路由策略本身成为系统能力的一部分。对推理服务与 **Agent** 架构而言，选型重点从“押注单一最强模型”转向“构建互补模型组合与可预测的选择策略”，有望在保持可靠性的同时显著降低 token 成本，并推动模型服务层出现新的路由与缓存组件。

📌 **总结**：在覆盖编码、智能体工作区与工程设计任务的八个基准上，**RRSI** 在演化集上最高提升 14.1 分，在五个分布外基准上最高提升 4.7 分，同时产出的 harness 比未正则化演化少用 **30%** 策略 token。对技术路线而言，这为智能体框架自动优化提供了抑制过拟合、偏好可复用机制的方法论，可降低智能体系统迭代中的算力与 token 成本；代码与项目页已公开，便于工程团队复现并用于自研 **Agent** 平台的 harness 优化。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.24972)
原文标题：RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

### 2、Jev-Mem提出System-One控制智能体记忆，LoCoMo评分0.777且构建提速6.6倍 {#event-191496}

【智能体平台、协议与执行系统】 【Jev-Mem】 【智能体记忆架构】 【性能提升】

📋 **要点**：智能体记忆对长时程AI智能体日益重要，但许多现有系统依赖自回归LLM控制记忆的组织、检索和使用方式，将昂贵生成放在记忆操作的关键路径上。该论文提出**Jev-Mem**，一种受System-**One**/**System-**Two认知启发的**智能体记忆架构**：System-**One**负责快速轻量决策，**System-**Two负责较慢的审慎推理。**Jev-Mem**通过专用System-One控制平面、结构化多关系记忆平面和System-Two推理平面实现分工，System-One控制器在构建阶段管理记忆类型和关系组织，在检索阶段动态执行查询路由、检索预算分配、图遍历、候选评分和自适应停止，System-Two仅在复杂推理和答案合成时调用。在LoCoMo上，Jev-**Mem**取得LLM-as-a-Judge总分0.777，较最强基线相对提升**11.0%**，记忆构建时间降至**158秒**、较最快竞争系统提速**6.6倍**，平均查询延迟降至**0.93秒**、降低**36.7%**。
📌 **总结**：该工作为长时程智能体记忆提供了效率与效果兼顾的架构范式，把昂贵生成从记忆关键路径移出，对智能体平台的记忆系统设计有直接参考价值。对AI前沿技术预研规划师而言，**System-**One控制平面和自适应停止机制可迁移到其他智能体记忆和检索系统；对技术主管而言，**6.6倍**构建提速和**36.7%**延迟降低意味着长时程智能体的部署成本显著下降；对商业主管而言，该架构提示记忆系统可作为智能体产品的差异化能力，而非单纯的成本中心。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.23986)
原文标题：Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents

## AI推理与服务加速

### 1、D-RAC 用 PDF 归一化与多模态 Markdown 转换降低企业文档分块成本 77.8% {#event-191491}

【AI推理与服务加速】 【D-RAC】 【RAG 文档摄入】 【成本下降】

📋 **要点**：企业知识库的检索增强生成系统需要摄入 **PDF**、**Word**、演示文稿和扫描件等异构文档格式，其内容常被锁定在复杂视觉布局、多栏页面和密集表格中。基于规则的提取和 **OCR** 会破坏阅读顺序、压平表格并丢失标题层级，而基于提取文本的全智能体分块则带来高 token 成本和幻觉风险。研究者提出 **Document Retrieval-Aware Chunking**（**D-RAC**），将 **W-RAC** 框架扩展到任意文档格式。**D-RAC** 首先将任意输入文档归一化为 **PDF**，利用几乎所有格式都有忠实确定性 PDF 渲染的特性；随后单次多模态 **LLM** 将渲染页面转换为检索优化 **Markdown**，将表格改写为自包含散文语句并保留标题层级；之后分块按 **W-RAC** 方式确定性解析为 ID 可寻址单元，再基于标识符而非文本进行轻量 **LLM** 分块规划。在 **RAG-Multi-Corpus** 基准的 236 文档 795 页 PDF 子集上，D-RAC 在 **72 分钟**内零错误转换和分块整个语料，产生 1748 个检索就绪块。与前沿 LLM 的智能体分块相比，D-RAC 将分块阶段输出 token 减少 **95.7%**，分块成本降低 **77.8%**（**GPT-4.1** 定价）至 **85.6%**（**Gemini 2.5 Pro** 定价），分块时间减少 **75%**，并可线性扩展到 500 页以上文档。
📌 **总结**：**D-RAC** 把企业文档 **RAG** 摄入从规则提取和全智能体分块推进到 **PDF** 归一化加单次多模态转换，在保持确定性和可观测性的同时大幅降低 token 成本和幻觉风险。对 **RAG** 技术路线而言，这意味着文档摄入环节可成为独立优化对象，而非简单依赖 **OCR** 或全智能体分块；对企业知识库产品架构而言，**77.8%** 至 **85.6%** 的**成本下降**和 **75%** 的时间减少可能显著降低大规模文档入库的运营成本。该工作也提示多模态 **LLM** 在文档转换中的单次调用即可替代复杂的智能体分块流程。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.24220)
原文标题：Document Retrieval-Aware Chunking (D-RAC): Universal Retrieval-Aware Ingestion of Enterprise Documents via PDF Normalization and Multimodal Markdown Conversion

## 模型训练

### 1、Harness-Zero通过智能体即harness蒸馏，任务成功率从23.3%提升至44.3% {#event-191494}

【模型训练】 【Harness-Zero】 【harness蒸馏】 【研发效率提升】

📋 **要点**：2026年9月20日，一篇arXiv预印本针对智能体harness增益与部署时harness绑定、最佳harness因领域和模型而异的问题，研究**harness蒸馏**：用领域或实例优化的harness作为训练时引导，将其诱导的行为迁移进模型权重，使增益在单一固定目标harness下仍能保留。挑战在于两个harness的动作空间和可用信息不同，优化harness的引导不能直接作为目标harness的监督。**Harness-Zero**通过agent-as-harness实现：在优化harness引导下，一个harnessing agent在执行前于目标harness动作空间中修正学生响应，将harness引导转化为训练演示。在知识工作、工具使用和科学领域实验中，移除专用harness后，**Harness-Zero**将基础模型宏平均任务成功率从**23.3%**提升至**44.3%**，超过保留该harness时的**41.7%**，并在三个领域28种模式中平均恢复**82.3%**的harness诱导行为。
📌 **总结**：**Harness-Zero**对智能体部署架构有直接启示：专用harness的增益可通过训练时蒸馏内化进模型权重，部署时无需保留复杂harness，降低推理时系统复杂度和路由成本。对**模型训练**路线而言，agent-as-harness提供了将外部系统行为转化为训练信号的可复用方法，可能改变智能体能力构建的分工。对技术主管而言，**44.3%**对**23.3%**的提升和**82.3%**的行为恢复率意味着该方法在多个领域具有可迁移性，值得评估在自有智能体产品中的应用。
来源：[Hugging Face Papers](https://arxiv.org/abs/2609.24974)
原文标题：Harness-Zero: Harness Distillation via Agent-as-Harness
