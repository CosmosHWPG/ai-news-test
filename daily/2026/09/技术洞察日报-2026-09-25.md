### 1、IQuest Research联合北航、曼彻斯特大学发布ModularRSI，冻结权重下Harness演化提升Agent准确率 {#event-194630}

【智能体平台、协议与执行系统】 【ModularRSI】 【Harness自我演化】 【研发效率提升】

📋 **要点**：**IQuest** Research联合北京航空航天大学、曼彻斯特大学等发布**ModularRSI**，研究在基础模型权重冻结条件下，**Agent**能否通过改造模型外围运行机制Harness获得持续自我改进。方法上把**Agent**表示为A=(M,H)，将Harness拆为Agent **Loop**、**Observation Management**、**Tool Use**、**Context Management**、**Task Completion** Detection五个模块独立演化，从多次rollout轨迹中提取结构化缺陷，经Program **Check**、**Diff Review**、**Execution** Validation三道验证后写回代码，再通过Cross-**Module** Integration联合演化。实验在Terminal-**Bench 2.**0上把准确率从47.57提升至52.43，Agent **Loop**单模块贡献约2.99个百分点，**Observation Management**使平均交互步数下降约**35%**；跨领域迁移到SWE-**Bench** Verified提升2.40个百分点，替换基础模型后GLM-5.2从59.55升至61.80、**MiniMax-2.**5从41.57升至44.94。
📌 **总结**：该工作把Agent能力提升的优化轴从模型权重扩展到Harness层，说明工具调用、上下文管理、错误恢复和任务完成判断等机制可独立于模型迭代并跨模型迁移。对Agent平台与执行系统而言，这意味着运行时、记忆、权限与验证机制本身构成可积累的工程资产，也提示数据难度分布（中等难度任务信息密度最高）将成为Harness RSI的关键设计变量。

### 2、北交清华与蚂蚁提出ARGUS，多智能体协作给视频鉴伪补证据链 {#event-195128}

【智能体平台、协议与执行系统】 【ARGUS视频鉴伪】 【多智能体取证】 【安全风险】

📋 **要点**：北京交通大学、清华大学与蚂蚁集团的研究者提出ARGUS，将多智能体协作引入视频鉴伪。系统由纹理、光照、运动、物理四类观察智能体从不同维度独立收集证据，观察阶段不输出最终真假结论，裁判智能体再综合观察报告与抽取的视频帧，对相互印证或冲突的证据进行权衡，输出二元预测和对应取证解释。训练以Qwen2.5-**VL-**7B为基础，先分别对观察者与裁判做监督微调，再冻结观察者、仅用GRPO优化裁判。团队同时构建FaceVid-**Forensics-**100K数据集，含**10万**段视频、覆盖33种合成方法。在域外测试集7636段视频上，ARGUS取得**69.87%**准确率、**81.82%**召回率与**53.28%** F1。
📌 **总结**：ARGUS把鉴伪流程从单一模型直接映射真假，改为证据收集与判断分离，使系统“看到了什么”和“因此如何判断”可被分别检查，降低多个模型沿同一错误直觉连续推理的风险。对安全与可信方向，这种证据先行的设计为需要解释的深度伪造检测提供了可泛化路径，其域外测试协议专门考察未见生成器下的表现；对Agent架构，独立观察加裁判汇总的模式说明多智能体分工在需要可解释判断的任务中具备工程价值，但观察内容仍可能遗漏线索，证据需结合原视频核查。

### 3、斯坦福与英伟达开源CLM-8B，Agent决策延迟最高降9倍 {#event-196041}

【智能体平台、协议与执行系统】 【CLM-8B】 【System One模型】 【性能提升】

📋 **要点**：斯坦福大学与**NVIDIA** Research研究人员开源Jev同类System One模型**CLM-8B**，目标是让Agent跳过长文本生成，直接从若干候选动作中做选择。CLM的架构差异在于把当前状态与候选动作分开计算，固定动作可提前算好并反复使用，因此在需要连续决策的场景中更快；官方测试显示**CLM-8B**整体表现接近Jev，最高将延迟压低约**9倍**。团队还将CLM用于Coding Agent答案筛选：由Opus 5与Fable 5生成多份候选方案，再由微调后的CLM选出最优一份，在38个DeepSWE留出任务上成功率达**81.6%**，在30个Terminal-**Bench 2.**1留出任务上达**87.6%**。**CLM-**8B基于冻结的Qwen3-**8B**，仅额外训练状态与动作投影头，训练数据包括约**6000万**组问答、**3000万**个困难负样本和约**100万**条Agent轨迹，代码与权重以Apache 2.0许可开放。
📌 **总结**：该模型把Agent决策从生成式推理转为判别式选择，用冻结主干加轻量投影头的方式获得接近专用模型的准确率与显著更低的延迟，为Agent运行时架构提供了新的执行层组件。对技术路线而言，状态与动作分离计算使固定动作可预计算复用，这一思路可迁移到工具调用与动作空间固定的智能体系统；对产品判断而言，开源权重与宽松许可降低了Coding Agent方案筛选能力的自建门槛，值得智能体平台团队评估将其嵌入候选生成-选择流水线。

### 4、Google Cloud API Gateway 公测支持 REST API 直接暴露为 MCP 工具 {#event-196141}

【智能体平台、协议与执行系统】 【Google Cloud API Gateway】 【MCP 工具暴露】 【研发效率提升】

📋 **要点**：企业大量能力位于智能体不可见的 **REST API** 之后，此前要让某个接口可被智能体调用，团队通常需另建并运维一套 **MCP** 服务器，重复实现网关已具备的路由、认证和配额逻辑。**Google Cloud** **API** Gateway 在 **Public Preview** 中可充当远程 **MCP** 服务器：在已部署的 **Open**API** 3.0.x**/3.1.x 规范上以 x-google-api-management.mcp 注解开启，部署后网关在 /mcp 基础路径提供 MCP 服务，接收标准 **MCP JSON-RPC** 请求，把每个 tools/call 转码为对应 **REST** 请求，套用既有策略后再把响应转回 MCP 结果。由于转码请求与普通 **REST** 调用不可区分，原有 **JWT** 或 **API Key** 认证、配额和日志保持不变，MCP 与 REST 共用一条策略路径和一份配额。默认 tools/list 未认证，生产环境需用 **JWT** 保护；tools/call 始终执行底层 REST 操作要求的认证。当前限制包括 **HTTP 204** 等空响应体操作不暴露、单网关最多 1000 个工具、MCP 与模型路由不能在同一 API 配置中启用。
📌 **总结**：该能力把 **MCP 工具暴露**从“新建服务器”降级为“注解既有 **OpenAPI** 规范”，直接影响智能体平台与企业 **API** 治理架构：架构师可复用现有网关的认证、配额与日志链路，避免 **MCP** 与 **REST** 双轨策略不一致；技术主管可据此缩短企业 **API** 智能体化的交付周期；同时 tools/list 默认未认证带来的工具名与输入模式暴露风险，需在安全治理中纳入默认加固项。
来源：[AIHot Virxact 一手信源热点](https://developers.googleblog.com/turn-your-rest-apis-into-mcp-tools-with-google-cloud-api-gateway)

📋 **要点**：北京交通大学、清华大学与蚂蚁集团的研究者提出ARGUS，将多智能体协作引入视频鉴伪。系统由纹理、光照、运动、物理四类观察智能体从不同维度独立收集证据，观察阶段不输出最终真假结论，裁判智能体再综合观察报告与抽取的视频帧，对相互印证或冲突的证据进行权衡，输出二元预测和对应取证解释。训练以Qwen2.5-**VL-**7B为基础，先分别对观察者与裁判做监督微调，再冻结观察者、仅用GRPO优化裁判。团队同时构建FaceVid-**Forensics-**100K数据集，含**10万**段视频、覆盖33种合成方法。在域外测试集7636段视频上，ARGUS取得**69.87%**准确率、**81.82%**召回率与**53.28%** F1。
📌 **总结**：ARGUS把鉴伪流程从单一模型直接映射真假，改为证据收集与判断分离，使系统“看到了什么”和“因此如何判断”可被分别检查，降低多个模型沿同一错误直觉连续推理的风险。对安全与可信方向，这种证据先行的设计为需要解释的深度伪造检测提供了可泛化路径，其域外测试协议专门考察未见生成器下的表现；对Agent架构，独立观察加裁判汇总的模式说明多智能体分工在需要可解释判断的任务中具备工程价值，但观察内容仍可能遗漏线索，证据需结合原视频核查。

### 1、LatWeave以知识格确定性算子实现多跳问答可审计执行 {#event-195550}

【AI模型】 【LatWeave知识格】 【多跳问答】 【架构替代】

📋 **要点**：2026年9月，一项arXiv论文针对概率式问答系统将已知内容与推理方式混为单一概率计算、导致幻觉无法根除、证据链无法审计的问题，提出LatWeave：将知识组织为多维知识格，把**多跳问答**编译为meet（约束交集）、compare（格序比较）、abstain（结构化弃答）三个确定性算子，LLM仅出现在构建侧的一次性抽取与查询规划侧，答案生成路径零LLM、零任务训练且端到端可审计。在六个公开基准上，知识完备时MetaQA（39,093问）三跳meet链近乎无损，any-hit 0.9975，与全监督KBQA相当；模板化多跳2WikiMultihopQA留出集n=1,258上EM 0.865，高于已发表的结构增强RAG复现；在MuSiQue开放文本深度组合与HotpotQA抽取覆盖缺口上如实报告退化并归因于格代数层之外；信息不完整时IIRC弃答准确率0.971，泄漏率0.029。
📌 **总结**：该结果说明在知识完备的操作包络内，确定性执行不付出性能代价，且答案路径每一步都可重算，这为需要审计与可复现的问答系统提供了区别于概率式RAG的架构选择；同时论文如实标注了开放文本深度组合与抽取覆盖缺口上的退化边界，提示该范式适用条件明确，落地时需先界定知识完备度与抽取覆盖范围。

原文标题：Meet, Compare, or Abstain: LatWeave for Deterministic Multi-Hop Question Answering on Knowledge Lattices
