1、TikTok SRE负责人：AI Agent本质是分布式系统，需引入幂等性和熔断机制

智能体平台、协议与执行系统 TikTok Agent可靠性 安全风险

📋 要点：2026年9月，TikTok SRE技术负责人Salman Munaf在演讲中系统阐述AI Agent作为分布式系统的本质。他指出，Agent调用外部服务时，问题就不再只是模型问题，而变成了分布式系统问题。核心观点包括：超时不代表失败，超时代表未知，Agent面对失败的第一反应是重试，因此必须把幂等性焊死在工具层；上下文能够影响行动时它就是状态，状态会过期，应该把记忆当作缓存来处理；Agent需要最大轮次数、预算、花费上限和最大并行调用数，防止重试风暴；熔断器是必须的，如果下游系统不健康，熔断器应阻止Agent继续调用；日志不够用，必须记录Agent每一步看到了什么、据此做了什么、为什么认为这样是对的。他强调，模型能力不能消除网络失败、过期数据和对抗性输入，构建Agent时最该问的问题是：当它犯错的时候，系统允许它做到哪个程度？

📌 总结：Salman Munaf的演讲将AI Agent可靠性问题纳入分布式系统框架，为Agent系统设计提供了成熟的工程方法论。对于技术预研规划师，这意味着Agent系统需要从分布式系统角度重新设计，引入幂等性、熔断、预算控制和可观测性等机制。对于核心网架构师，这提示未来网络中的AI Agent需要类似的可靠性设计，确保在故障时不会造成不可逆的后果。建议将分布式系统的最佳实践纳入Agent系统设计规范。

4、学术论文为Agent Harness给出严格定义：四大必要条件缺一不可

智能体平台、协议与执行系统 Agent Harness 定义框架 架构替代

📋 要点：Sanderson Oliveira de Macedo教授在论文《What makes a harness a harness》中给出了Agent Harness的严格定义：一个系统必须同时满足智能体循环（推理-行动-观测交替）、工具接口（感知和修改外部环境）、上下文主动管理（智能决定信息取舍）和独立于模型的控制机制（不依赖模型自觉）四个条件。论文评估了Claude Code、Codex CLI、Aider、Cline、OpenHands和SWE-agent六个主流编程智能体，确认它们均满足条件，但控制机制各有侧重（如Claude Code的运行时护栏、Codex CLI的分级权限、Aider的Git回滚）。论文还区分了Harness与Agent Framework（如AutoGen）、SDK、IDE插件和Eval Harness的差异。

📌 总结：该定义为智能体系统的工程评估提供了统一框架，使业界能够公平对比不同系统的可靠性差异。对于预研规划师而言，论文提出的四组矛盾维度（自主性vs管控、宽泛vs精选上下文、通用vs专用、开放权限vs强隔离）指明了Agent Harness的未来研究方向。技术主管可基于该框架评估自有智能体系统的工程成熟度，特别是在控制机制和上下文管理方面的设计取舍。

1、西湖大学与南洋理工提出Code World Model，代码驱动视频世界模型

AI模型 Code World Model 世界模型 架构替代

📋 要点：西湖大学AGI Lab与南洋理工大学研究团队提出了Code World Model，一种以语言模型为“大脑”的新型世界模型范式。其核心思路是让coding agent通过持续编写、调用和修改代码，维护并更新可执行的world state；与当前观察相关的状态再被转换为proxy，用来指导video model生成精细的视觉画面。研究团队认为，游戏视频并非世界本身，而是程序执行结果被渲染后的像素投影。若只保留动作与像素，再让视频模型直接学习二者之间的映射，就等于绕过原本存在的程序、规则和显式world state，要求模型从视觉结果中反向拟合整套程序行为。Code World Model重新划分了两者的职责：知识、目标、规则与长期因果由coding agent和代码负责，外观、运动细节、光照与纹理由video model负责。当前原型采用MiniMax-H3的Ref2VA backbone作为video model，推理阶段由GPT-5.6 Sol担任coding agent。实验使用约5.6小时gameplay source video进行LoRA适配，模型能遵循proxy指定的人物位置、动作轨迹、场景布局与相机运动。

📌 总结：Code World Model为可交互视频世界提供了新的技术范式。通过将世界推演和世界呈现解耦，由代码维护可执行状态，视频模型生成视觉画面，解决了传统视频模型难以显式维护高层语义的问题。这一方法对于AI前沿技术预研规划师具有重要参考价值，尤其是在世界模型和具身智能的研究方向。它表明，通过结合语言模型的推理和编程能力与视频模型的视觉生成能力，可以构建更可控、更可扩展的虚拟世界，为游戏开发、机器人仿真等领域提供新的工具。

1、斗象AIBeat团队发现大模型加密推理状态可跨模型重放导致思维链泄露

AI安全、可信与治理 推理状态重放 思维链泄露 安全风险

📋 要点：2026年9月7日，斗象SPAI实验室AIBeat团队发布实验报告，揭示了大型语言模型推理状态的安全漏洞。实验基于论文《Stealing Reasoning Traces from Proprietary LLM APIs》的思路，但未破解加密算法，而是从工程侧验证了推理状态的可重放性。团队使用AIBeat自动化安全评测框架，在GPT链路（Sol→Luna）和Claude链路（Opus 4.6→Haiku 4.5）上执行了24条测试用例。结果显示：将源模型（如Opus 4.6）的完整推理状态（包括thinking和signature）原封不动地传递给目标模型（如Haiku 4.5），目标模型不仅能恢复源任务信息（如大整数质因数分解中的数字和因子），甚至能完美复现源模型特有的错误推理路径。在完整有效状态组中，恢复率达到100%（6/6），而阴性对照组（无状态、短状态、签名仅等）均未出现同类现象。实验还发现，仅约2.5%的第三方中转通道能保留并传递thinking块中的signature，表明该漏洞受真实模型调用影响。

📌 总结：该发现对AI安全架构具有重要警示意义：首先，厂商通过加密隐藏推理过程（防蒸馏）的护栏并非绝对安全，加密状态可跨模型反序列化复用，导致核心推理逻辑泄露；其次，企业级API网关需建立推理状态清洗机制，对thinking、signature、encrypted_content等字段进行安全审计和强制剥离；第三，多模态和复合链路的普及将扩大状态重放攻击面，防蒸馏需要动态演进的持久防线。对于通信和核心网领域，若未来引入AI推理能力，需考虑类似的安全隔离机制。

3、推测不确定性方法预测智能体失败，执行错误率降低6-8个百分点

AI安全、可信与治理 Speculative Uncertainty 智能体失败预测 安全风险

📋 要点：软件工程LLM智能体失败代价高昂：自信地错误行动，坏行动仅在昂贵执行和重试后识别。研究者提出Speculative Uncertainty (SU)，从黑盒智能体输出token中恢复预测失败信号，无需访问logits、权重、激活或重复采样。反转推测解码，小型开放权重草稿模型在单次前向传递中评分智能体已生成轨迹。从推测交叉似然中提取相位感知特征，分离推理和行动跨度，并针对可验证目标校准。SU产生失败似然分数，任何下游策略（如路由、人工干预或额外测试时计算）可直接消费。在Qwen3-Coder-480B和Claude 3.5 Sonnet上实例化执行前否决门策略，执行错误率降低6-8个百分点，token成本降低14-19%，无需重训练即可迁移到分布外基准，并跨智能体模型泛化。

📌 总结：SU为智能体安全部署提供了可操作的失败预测机制，通过低成本草稿模型评分，显著降低执行错误和token成本。这对于提升AI智能体的可靠性和经济性具有重要价值。

📋 要点：西湖大学AGI Lab与南洋理工大学研究团队提出了Code World Model，一种以语言模型为“大脑”的新型世界模型范式。其核心思路是让coding agent通过持续编写、调用和修改代码，维护并更新可执行的world state；与当前观察相关的状态再被转换为proxy，用来指导video model生成精细的视觉画面。研究团队认为，游戏视频并非世界本身，而是程序执行结果被渲染后的像素投影。若只保留动作与像素，再让视频模型直接学习二者之间的映射，就等于绕过原本存在的程序、规则和显式world state，要求模型从视觉结果中反向拟合整套程序行为。Code World Model重新划分了两者的职责：知识、目标、规则与长期因果由coding agent和代码负责，外观、运动细节、光照与纹理由video model负责。当前原型采用MiniMax-H3的Ref2VA backbone作为video model，推理阶段由GPT-5.6 Sol担任coding agent。实验使用约5.6小时gameplay source video进行LoRA适配，模型能遵循proxy指定的人物位置、动作轨迹、场景布局与相机运动。

📌 总结：Code World Model为可交互视频世界提供了新的技术范式。通过将世界推演和世界呈现解耦，由代码维护可执行状态，视频模型生成视觉画面，解决了传统视频模型难以显式维护高层语义的问题。这一方法对于AI前沿技术预研规划师具有重要参考价值，尤其是在世界模型和具身智能的研究方向。它表明，通过结合语言模型的推理和编程能力与视频模型的视觉生成能力，可以构建更可控、更可扩展的虚拟世界，为游戏开发、机器人仿真等领域提供新的工具。

AI安全、可信与治理 推理状态重放 思维链泄露 安全风险

📋 要点：2026年9月7日，斗象SPAI实验室AIBeat团队发布实验报告，揭示了大型语言模型推理状态的安全漏洞。实验基于论文《Stealing Reasoning Traces from Proprietary LLM APIs》的思路，但未破解加密算法，而是从工程侧验证了推理状态的可重放性。团队使用AIBeat自动化安全评测框架，在GPT链路（Sol→Luna）和Claude链路（Opus 4.6→Haiku 4.5）上执行了24条测试用例。结果显示：将源模型（如Opus 4.6）的完整推理状态（包括thinking和signature）原封不动地传递给目标模型（如Haiku 4.5），目标模型不仅能恢复源任务信息（如大整数质因数分解中的数字和因子），甚至能完美复现源模型特有的错误推理路径。在完整有效状态组中，恢复率达到100%（6/6），而阴性对照组（无状态、短状态、签名仅等）均未出现同类现象。实验还发现，仅约2.5%的第三方中转通道能保留并传递thinking块中的signature，表明该漏洞受真实模型调用影响。

📌 总结：该发现对AI安全架构具有重要警示意义：首先，厂商通过加密隐藏推理过程（防蒸馏）的护栏并非绝对安全，加密状态可跨模型反序列化复用，导致核心推理逻辑泄露；其次，企业级API网关需建立推理状态清洗机制，对thinking、signature、encrypted_content等字段进行安全审计和强制剥离；第三，多模态和复合链路的普及将扩大状态重放攻击面，防蒸馏需要动态演进的持久防线。对于通信和核心网领域，若未来引入AI推理能力，需考虑类似的安全隔离机制。

📋 要点：NVIDIA热工程师Ajay Sekar于2026年9月7日在Data Center Dynamics发表技术分析，指出当前AI液冷部署中存在一个被忽视的可靠性风险：现代AI加速器（700-1000W/设备）在训练任务初始化或推理查询突发时，功率跃迁可在数十毫秒内完成，而CDU的PID控制回路因二次回路传播延迟（15-45秒）、传感器响应（3-8秒）、控制器轮询（1-5秒）和阀门执行（5-30秒）等物理限制，总响应滞后达60-120秒。在此热债窗口内，加速器结温可超过稳态基线10-20°C，触发固件频率限制并降低计算吞吐量；长期累积的热循环还会导致焊点疲劳和封装分层。文章指出，当前DCIM系统以1-5分钟滚动平均监测稳态参数，完全无法捕捉秒级瞬态热行为，而加速器BMC的亚秒级结温数据与CDU日志分属不同系统且未关联。
