2、Dream-RSI 提出递归自改进探索框架，用回放模拟器降低发现成本

智能体平台、协议与执行系统 Dream-RSI 递归自改进探索 研发效率提升

📋 要点：递归自改进对自主 AI 智能体日益关键，但探索策略管理是主要瓶颈：固定策略难以适应搜索空间扩展，在线策略优化又需在延迟且昂贵的反馈下导航庞大元搜索空间。Dream-RSI 提出可扩展的递归自改进探索框架，通过轻量编排层使探索显式可编程，同时保持底层编码智能体不变。其核心思路是把累积的发现历史作为已实现搜索空间上的回放模拟器，在历史发现树构建的模拟器中执行 dreaming，获得即时低成本离策略反馈来评估和优化探索策略，改进后的策略再部署到线上驱动进一步发现，形成自改进循环。在算法工程、数学优化和 GPU 内核工程中，该框架实现相当或更优的发现质量并显著降低发现成本。

📌 总结：Dream-RSI 的价值在于把智能体探索策略优化从昂贵在线评估转为回放模拟器中的离策略学习，为递归自改进提供可扩展且低成本的工程路径。对智能体平台而言，这意味着长周期搜索任务的算力与时间成本有望下降；对 GPU 内核工程、算法工程等场景，该框架提供了可复用的探索策略优化范式，值得在智能体运行时与自动化研发工具链中跟踪其实际落地效果。

1、vLLM 优化 Kimi K3 推理，吞吐提升 2.8 倍、TTFT 降低 85%

AI推理与服务加速 vLLM Kimi K3 性能提升

📋 要点：2026年9月13日，vLLM 团队发布博客，介绍针对 Kimi K3 模型的推理性能优化。在 8K/1K 工作负载、TP8、8 tokens DSpark 推测解码、并发 1/4/16 条件下，对比 v0.27.1 到 commit 82a85dc1，实现 56%-60% 延迟降低、2.2-2.8 倍吞吐提升和 72%-85% TTFT 降低。优化包括：自适应调度预算（PR #51725、#51726），将默认 max_num_batched_tokens 从 8192 提升至 16384，TTFT 降低 55%-65%，吞吐提升 41.5%；内部 KDA 前缀检查点（PR #52789、#53614），TTFT 降低 9%-25%；零拷贝混合 KDA 批次（PR #56159），吞吐提升 5.2%-7.7%；延迟 MXFP4 终结（PR #53152、#53327），端到端延迟降低约 5%；ReplaySSM（PR #51855）在相同缓存预算下有效容量提升 10.97%；PD 分离与混合状态卸载（PR #51358、#50344）；解码上下文并行（PR #50484）在 120k token 工作负载下 KV 缓存容量从 1.93M 提升至 19.75M tokens，TPOT p50 从 13.8ms 降至 10.5ms。

📌 总结：vLLM 对 Kimi K3 的优化表明，通过调度、缓存、状态管理和并行策略的协同设计，可以显著提升长上下文和智能体工作负载的推理效率。自适应调度预算和 KDA 前缀检查点减少了不必要的模型前向和计算开销；ReplaySSM 通过重建 KDA 状态而非存储，提升了缓存有效容量；PD 分离和状态卸载解决了混合注意力与状态空间模型的传输难题；解码上下文并行通过序列维度分片 MLA KV，提升了长共享前缀场景的 KV 缓存容量和 TPOT。这些优化为推理服务系统在 MoE、混合架构和长上下文场景下的性能调优提供了可复用的工程实践，对降低 token 成本和提升服务吞吐具有直接价值。

1、智谱与清华唐杰提出Trace as State推理时扩展方法，DeepSeek V4 Pro准确率从29.2%跃升至81.8%

AI模型 Trace as State方法 推理时扩展 性能提升

📋 要点：2026年9月，智谱与清华大学唐杰团队在arXiv发表论文，提出一种名为Trace as State的推理时扩展方法。核心思想是：让模型先在长上下文上运行一遍，收集推理轨迹并序列化为文本T，然后在第二遍时将T放置在上下文之前重新读一遍再作答。实验使用DeepSeek V4 Pro、Qwen 3.7 Max和GLM-5.2三个模型，在GraphWalks、MRCRv2和NUB-1M三个基准上测试。结果显示，DeepSeek V4 Pro在GraphWalks Parents任务上从初始29.2%提升至81.8%（轨迹前置），而轨迹后置仅提升至43.0%；GLM-5.2在GraphWalks Parents上达到100% EM。理论分析表明，条件状态在前时模型只需存储当前状态（约b比特），条件在后时需为每个可能状态保留完整档案（最坏需b·2^b比特），存在指数级内存差距。

📌 总结：Trace as State方法无需修改模型架构或额外训练，仅通过改变推理轨迹在上下文中的位置即可显著提升长上下文推理性能，为推理时扩展提供了低成本、高收益的新范式。该方法在27个模型×任务×指标组合中赢了26个，且性能随轨迹数量增加而单调上升，表明轨迹数量本身就是一个可调节的扩展旋钮。对于AI前沿技术预研规划师而言，该方法可直接应用于现有长上下文模型，提升搜索、推理、问答等任务的准确性，且与现有推理引擎兼容。对于核心网架构师，若将此类方法应用于网络运维Agent的长上下文分析，可提升故障诊断和日志分析的准确性。

2、Elo-per-token 分析揭示智能体测试时算力边际收益递减与扩展拐点

模型评测 Elo-per-token 测试时算力扩展 研发效率提升

📋 要点：2026年9月，Elo-per-token 分析提出衡量智能体测试时策略扩展性的方法。大语言模型智能体在修订方案、使用工具、探索备选与决定停止时自适应分配测试时算力，使性能扩展难以度量。该研究选取可对中间提交给出连续分数的开放式任务，使长轨迹中的进展可观测。Elo-per-token 分析跟踪每个 token 预算下找到的最优解，并用 Bradley-Terry 模型将任务内排序聚合为跨不同分数尺度的 Elo 评分。研究将其应用于四个通用智能体在四个开放式基准上、单会话最高 1 亿 token 的场景，以及三个反馈驱动的 LLM 优化框架的受控单任务干预。独立采样提供理论刻画参考，其 Elo 随对数算力线性增长。相较该参考，智能体初期转化 token 为 Elo 更快，但边际收益递减并最终低于参考线。研究定义扩展拐点为边际 Elo 增益与独立采样参考相等的单会话预算，并以该点作为单会话预算，在 FrontierCS Polyomino Packing 上将 1 亿 token 拆分到并行会话，较单长会话提升 264 Elo，较十个短会话提升 355 Elo。

📌 总结：该工作把智能体测试时算力从经验性加码转向可度量的边际收益分析，提出扩展拐点这一可操作判据，说明在拐点之后继续拉长单会话的收益低于独立采样参考。对智能体推理调度而言，这意味着预算应优先拆分为并行会话而非单次长轨迹，为推理服务在会话编排、并发调度与成本控制上提供了量化依据；对评测体系而言，Elo-per-token 提供了一种跨任务、跨分数尺度比较智能体扩展性的方法，可补充传统单点基准的不足。

1、智谱与清华唐杰提出Trace as State推理时扩展方法，DeepSeek V4 Pro准确率从29.2%跃升至81.8%

AI模型 Trace as State方法 推理时扩展 性能提升

📋 要点：2026年9月，智谱与清华大学唐杰团队在arXiv发表论文，提出一种名为Trace as State的推理时扩展方法。核心思想是：让模型先在长上下文上运行一遍，收集推理轨迹并序列化为文本T，然后在第二遍时将T放置在上下文之前重新读一遍再作答。实验使用DeepSeek V4 Pro、Qwen 3.7 Max和GLM-5.2三个模型，在GraphWalks、MRCRv2和NUB-1M三个基准上测试。结果显示，DeepSeek V4 Pro在GraphWalks Parents任务上从初始29.2%提升至81.8%（轨迹前置），而轨迹后置仅提升至43.0%；GLM-5.2在GraphWalks Parents上达到100% EM。理论分析表明，条件状态在前时模型只需存储当前状态（约b比特），条件在后时需为每个可能状态保留完整档案（最坏需b·2^b比特），存在指数级内存差距。

📌 总结：Trace as State方法无需修改模型架构或额外训练，仅通过改变推理轨迹在上下文中的位置即可显著提升长上下文推理性能，为推理时扩展提供了低成本、高收益的新范式。该方法在27个模型×任务×指标组合中赢了26个，且性能随轨迹数量增加而单调上升，表明轨迹数量本身就是一个可调节的扩展旋钮。对于AI前沿技术预研规划师而言，该方法可直接应用于现有长上下文模型，提升搜索、推理、问答等任务的准确性，且与现有推理引擎兼容。对于核心网架构师，若将此类方法应用于网络运维Agent的长上下文分析，可提升故障诊断和日志分析的准确性。

📋 要点：2026年9月，Elo-per-token 分析提出衡量智能体测试时策略扩展性的方法。大语言模型智能体在修订方案、使用工具、探索备选与决定停止时自适应分配测试时算力，使性能扩展难以度量。该研究选取可对中间提交给出连续分数的开放式任务，使长轨迹中的进展可观测。Elo-per-token 分析跟踪每个 token 预算下找到的最优解，并用 Bradley-Terry 模型将任务内排序聚合为跨不同分数尺度的 Elo 评分。研究将其应用于四个通用智能体在四个开放式基准上、单会话最高 1 亿 token 的场景，以及三个反馈驱动的 LLM 优化框架的受控单任务干预。独立采样提供理论刻画参考，其 Elo 随对数算力线性增长。相较该参考，智能体初期转化 token 为 Elo 更快，但边际收益递减并最终低于参考线。研究定义扩展拐点为边际 Elo 增益与独立采样参考相等的单会话预算，并以该点作为单会话预算，在 FrontierCS Polyomino Packing 上将 1 亿 token 拆分到并行会话，较单长会话提升 264 Elo，较十个短会话提升 355 Elo。

📌 总结：该工作把智能体测试时算力从经验性加码转向可度量的边际收益分析，提出扩展拐点这一可操作判据，说明在拐点之后继续拉长单会话的收益低于独立采样参考。对智能体推理调度而言，这意味着预算应优先拆分为并行会话而非单次长轨迹，为推理服务在会话编排、并发调度与成本控制上提供了量化依据；对评测体系而言，Elo-per-token 提供了一种跨任务、跨分数尺度比较智能体扩展性的方法，可补充传统单点基准的不足。
