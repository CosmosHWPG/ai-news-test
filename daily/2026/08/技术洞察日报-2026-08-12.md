### 1、IBM研究团队提出ALTK-Evolve按需检索式记忆，同精度下推理成本降至ACE四成 {#event-123521}

【智能体平台、协议与执行系统】 【ALTK-Evolve】 【记忆检索】 【成本下降】

📋 **要点**：IBM研究院在Hugging Face博客发布**ALTK-Evolve**与ACE的对比研究，两者都通过智能体历史轨迹提炼可复用经验并在推理时回灌，但**ALTK-Evolve**采用按需检索少量高支持度指南的方式，而非ACE每步全量注入完整手册。在AppWorld基准上，使用相同ReAct智能体，**ALTK-**Evolve在DeepSeek-**V3.**2上任务完成率**89.3%**对ACE的**80.4%**，Token消耗263K对634K；在gpt-oss-120b上准确率**56.0%**对**54.8%**，Token消耗116K对777K。该方法通过支持计数保留经验强度，按任务检索相关指南，并针对弱模型减少注入量，实现了同精度下推理成本的大幅下降。
📌 **总结**：**ALTK-Evolve**的按需检索式记忆机制为智能体记忆管理提供了新范式，证明全量注入并非必要，按需检索可在保持或提升准确率的同时显著降低Token消耗，对长时程智能体的推理成本优化具有直接价值。该研究为智能体记忆系统的设计提供了可复用的工程方案，并可能影响未来智能体框架的记忆与检索模块标准，对AI前沿技术预研和智能体平台架构设计具有参考意义。

原文标题：Thinking of ACE? We Can Do It with Fewer Tokens

### 2、SkillSentry用运行时保障框架提升LLM智能体技能执行成功率24.1% {#event-125778}

【智能体平台、协议与执行系统】 【SkillSentry】 【运行时保障】 【体验提升】

📋 **要点**：LLM智能体即使具备技能，也可能在不同任务或重复运行中执行不稳定，原因包括偏离技能流程或单步执行错误。**SkillSentry**提出技能导向的**运行时保障**框架，基于新DSL表示技能执行指南，初始化时结合从技能文档提取的规范和历史成功/失败轨迹挖掘的执行经验，围绕智能体执行循环进行监控和引导，并利用新轨迹迭代完善指引。在15个技能、两个LLM智能体（**Claude** Code和Codex，分别搭配**Claude**-**Haiku-4.5**/**Claude-Opus-4.**6和GPT-5.2/**GPT-5.4**）上，平均任务成功率提升**24.1%**，且重复运行变异性更低。该工作为智能体技能执行提供了可靠性的系统化保障。
📌 **总结**：**SkillSentry**将DSL和**运行时保障**引入智能体技能执行，填补了技能库与稳定执行之间的可靠性鸿沟，为可预测的智能体自动化奠定了基础。对于通信运营商和设备商，采用此类保障机制可确保网络运维Agent在配置变更、故障恢复等高风险操作中的一致性，减少因执行偏差导致的业务影响。其迭代精化机制也使技能库能够随运行数据持续改进，提升长期鲁棒性。
来源：[研究团队](https://arxiv.org/abs/2608.09253)
原文标题：SkillSentry: Reliable Skill Execution for LLM Agents via Runtime Assurance

### 3、TRACE 自动化上下文工程，轨迹挖掘诊断智能体上下文故障 {#event-125762}

【智能体平台、协议与执行系统】 【TRACE】 【上下文工程】 【运维效率提升】

📋 **要点**：生产 AI 智能体在上下文源（系统提示、知识库、工具描述和程序技能）包含错误或缺口时失败。当前维护依赖手动日志审查和临时调试，随交互量增长造成可扩展性瓶颈。研究提出 **TRACE**，自动化反馈循环，挖掘历史智能体轨迹以诊断和修复上下文故障。关键洞察是轨迹富含隐式不满信号——用户纠正、改写、放弃线索——揭示上下文源失败位置，无需显式反馈收集。与模型微调不同，**TRACE** 在上下文层操作，实现快速迭代而无需重训练。在 60 个不满轨迹上，TRACE 实现 **72.7%** 根因归因和 **82%** 端到端修复有效性，显示超过 **80%** 的上下文层故障可通过挖掘历史轨迹自动诊断和修复。
📌 **总结**：**TRACE** 通过轨迹挖掘实现上下文层故障的自动诊断和修复，显著提升智能体维护效率。对预研规划师，该方法可借鉴用于构建智能体运维系统，通过历史轨迹分析自动优化上下文配置，降低人工调试成本。
来源：[研究团队](https://arxiv.org/abs/2608.09153)

### 4、openJiuwen联合昇腾推出算力亲和机制，Agent首token时延降低57.46% {#event-123573}

【智能体平台、协议与执行系统】 【openJiuwen】 【KV Cache】 【性能提升】

📋 **要点**：**openJiuwen**开源智能体平台由华为2012实验室、华为云、计算、终端等团队联合打造，针对Agent长任务中**KV Cache**管理低效问题，构建了算力亲和能力。核心机制是Agent Hint接口，Agent在任务状态变化时（子任务结束、工具调用等待、上下文压缩、会话恢复）向推理引擎下发语义信号，引擎据此执行缓存驱逐、卸载和预取动作。推理引擎内新增SAM（会话感知管理器）维护会话与缓存归属关系，**SPM**（会话感知池化管理器）将语义传递到分布式缓存池，缓存跨层级迁移借助昇腾灵渠总线。在SWE-bench Verified数据集上模拟10用户并发使用JiuwenSwarm，开启算力亲和后首token时延降低**57.46%**，端到端时延降低**27.61%**，**Prefix** Cache命中率提升**33%**，池化缓存使用量峰值降低**25.24%**。
📌 **总结**：**openJiuwen**算力亲和将**KV Cache**管理从通用访问热度判断升级为面向**Agent**执行工作流的语义级调度，解决了**Agent**掌握任务状态与引擎掌握算力资源之间的断层问题。对推理系统架构而言，Agent Hint作为开放接口规范可被其他框架复用，SAM和SPM的分层设计为会话感知缓存管理提供了参考实现。对硬件协同而言，该方案在昇腾平台上复用既有缓存接口，通过灵渠总线实现跨层级数据流动，展示了NPU平台上Agent推理优化的可行路径。对商业判断而言，首token时延降低**57%**和存储峰值降低**25%**的量化结果，为同等硬件承载更复杂Agent协作流程提供了直接依据。
来源：[机器之心](https://www.jiqizhixin.com/articles/2026-08-11-7?source=rss)

### 6、查询证明7B分析Agent以规则门控超越32B基线，业务真理率高0.237且成本低71% {#event-125779}

【智能体平台、协议与执行系统】 【QueryProof】 【业务真理】 【成本下降】

📋 **要点**：LLM分析智能体通常以SQL语法准确率评估，但生产环境中的失败常表现为业务定义歧义、仓库无法回答、模式变更后的废弃列以及执行成功但返回错误业务数字等问题，这些无法被执行匹配指标捕获。论文引入WarehouseReliabilityBench，包含400个冻结任务，约一半正确响应为澄清、弃权或拒绝。**QueryProof**是一个**7B** **Agent**，使用从语义层和物理目录派生的规则决定行为，并对每个答案执行确定性后检查。在80任务测试中，**QueryProof**比直接提示的**32B**基线**业务真理**率高0.237（区间[0.112,0.375]），成本降低**71%**；错误成功从0.754降至0.351，在可回答任务上未返回错误数字。但路由层移除影响不大，且重采样模板家族时区间包含零，效果方向可靠但幅度不确定。
📌 **总结**：该研究为生产级数据分析Agent设计提供了新范式：通过业务规则和物理目录的确定性检查来保证“**业务真理**”而非仅SQL语法，同时用较小模型实现高可靠低成本的解决方案。对通信领域的经营分析和网络数据分析，可采用类似语义层和规则门控机制，避免大模型带来高成本和不可控输出。该工作也强调了评估基准应从执行匹配转向业务语义正确性，推动分析Agent向着更可信的方向发展。
来源：[研究团队](https://arxiv.org/abs/2608.09254)
原文标题：Business Truth, not SQL Accuracy: A Rule-Gated 7B Analytics Agent Outperforms a Direct-Prompted 32B Baseline

### 7、Agentic Router用执行反馈驱动的双路径学习提升SONiC命令行运维成功率 {#event-125766}

【智能体平台、协议与执行系统】 【Agentic Router】 【SONiC运维】 【体验提升】

📋 **要点**：基于大语言模型的命令行网络运维智能体虽然在生成命令上表现出一定能力，但无法保证执行成功或规避操作风险，现有方法忽视执行后经验对候选覆盖和动作选择的联合优化。**Agentic Router**设计为执行落地的双路径框架：提案路径将可复用的操作经验抽象为可检索指南，在不修改底层LLM的情况下提升可行动作覆盖；选择路径则利用真实SSH反馈，通过会话级LoRA更新后果预测器，以效用与风险感知重排序选出最终动作。在多轮SONiC操作会话中，基于Qwen3提案模型的实验表明，该框架显著提升可行动作覆盖和Top-1执行成功率，两条适应路径在交互中互补增益。此类方法使运维智能体能够从历史执行中持续学习，改善对不熟悉状态的处理，减少人工介入。
📌 **总结**：该方法为网络运维智能体提供了一种不改变模型本体的经验闭环学习范式，使运维Agent能够自主沉淀失败教训和成功经验，降低重复错误。对核心网设备商和运营商而言，将**Agentic Router**引入CLI配置变更、故障排查等场景，可有效提高自动化操作的可靠性和操作安全性，减少误操作带来的业务中断风险。其会话级LoRA更新机制还支持多租户隔离或按域定制，为大规模网络运维平台积累领域经验提供落地路径，并有望成为网络自治能力的重要组成部分。
来源：[研究团队](https://arxiv.org/abs/2608.09184)
原文标题：Agentic Router: An Execution-Grounded Continual Learning Approach With Memory

### 1、技能蒸馏将推理溢价摊销为可复用技能，输出token减少2.7-6倍且性能超越推理模式 {#event-125603}

📋 **要点**：部署的LLM安全护栏通常是静态的，在发布时冻结，而新的越狱技术和有害类别可能在几天内出现，导致防御总是滞后一步。本研究介绍了**SESG**（**自进化**安全护栏），一个在生产环境中运行的多智能体系统。**SESG**监控已部署护栏后的实时流量，识别两类失败：形式新颖的越狱和内容新颖的有害类别。一旦确认失败，生成智能体合成针对性的配对训练数据；验证智能体重新平衡批次，使模型自身的错误引导其训练集；路由智能体将训练动作与诊断出的差距匹配，并将下一版本返回生产。经过六轮实时进化（V0到V6），一个**1.7B**的护栏在16-**24小时**内适应新威胁，仅需约**2小时**的人力，而手动流程需要40-**90小时**。自2026年4月以来，SESG已成为深信服护栏的主要更新管道，在两个月内自主关闭了15个新威胁场景中的14个。
📌 **总结**：**SESG**展示了AI安全防护从静态向动态**自进化**转变的可行性。该系统通过自动化威胁检测、训练数据生成和模型更新，将新威胁的适应时间从数天缩短至一天内，极大提升了安全响应的时效性，并显著降低了人力成本。这对于需要快速应对不断演变的攻击手段的安全团队具有重要价值。该案例为安全产品厂商提供了新的竞争方向，即构建能够自我进化的安全系统，以应对日益复杂的AI安全威胁。
来源：[研究团队](https://arxiv.org/abs/2608.08471)
原文标题：Yesterday's Shield, Today's Spear: A Self-Evolving Safety Guardrail in Production

### 4、AdvSafe 双对抗框架提升大型推理模型越狱鲁棒性，仅用 1K 样本 {#event-125302}

【AI安全、可信与治理】 【AdvSafe】 【越狱鲁棒性】 【安全风险】

📋 **要点**：大型推理模型在复杂任务上表现出色，但仍易受有害提示影响产生不安全输出。现有对齐方法多关注提示模式而非内在攻击机制，导致泛化能力不足。**AdvSafe** 提出双对抗框架，通过两阶段对抗游戏使模型内化不安全知识。第一阶段，自主代理动态生成欺骗性越狱提示，尝试突破强教师模型。第二阶段，被突破的教师模型执行认知反击，解释攻击成功的原因以及如何识别和缓解此类提示。该过程生成紧凑的推理数据集，捕捉丰富、可泛化的不安全知识。基于该数据集训练的学生模型通过内在威胁理解隐式获得安全对齐。实验表明，仅用 1K 合成样本，**AdvSafe** 对齐的 **LRM** 比现有基线具有显著更强的**越狱鲁棒性**，且几乎无性能下降，并提高了对分布外提示的鲁棒性。
📌 **总结**：**AdvSafe** 为大型推理模型的安全对齐提供了一种高效且有效的新方法，通过理解攻击机制而非模式匹配，实现了更好的鲁棒性-效用权衡。对于 AI 前沿技术预研规划师，这为安全对齐研究提供了新思路，可能推动更通用、更鲁棒的安全防御机制的发展。对于技术主管，该方法的低样本需求和高效率使其具有实际部署潜力。
来源：[研究团队](https://arxiv.org/abs/2608.09542)
原文标题：Dual-Adversarial Safety Alignment: Cultivating Intrinsic Threat Comprehension in LRMs

### 5、SkillsMetric静态分析框架检测恶意Agent技能，但存在盲区 {#event-125692}

【AI安全、可信与治理】 【SkillsMetric】 【静态分析】 【安全风险】

📋 **要点**：**Agent** Skills作为增强LLM智能体的结构化指令和脚本包，其安全属性尚未得到充分研究。本研究提出了**SkillsMetric**，一个五阶段**静态分析**框架，从模式密度、统计异常、数据流污点、导入异常和能力不匹配五个维度对技能包进行评分。研究构建了包含2266个技能、覆盖16种攻击类型的对抗性评估数据集，并在完整的SkillMD-138K语料库上进行了评估。框架取得了AUC 0.93和5折交叉验证F1 **73.4%**的成绩，对数据外泄（**93%**）和隐写载荷（**93%**）有较强检测能力。然而，研究也发现了根本性盲区：使用常见shell命令的主机破坏攻击能规避所有五个阶段（**0%**检测率），而通过自然语言操纵的提示注入检测率仅为**42%**。这些发现表明，**静态分析**单独不足以保障技能安全，需要结合快速静态预筛选和语义审查的纵深防御架构。
📌 **总结**：该研究为Agent技能安全领域提供了首个系统性的**静态分析**评估框架，明确了其能力边界。它证明了**静态分析**是安全防线的重要组成部分，但存在无法检测的盲区，特别是针对主机破坏和复杂提示注入。这为安全架构师提供了关键指导：不能仅依赖静态分析，必须构建包含语义审查、行为监控等多层次的纵深防御体系。对于智能体平台和生态的运营者，这意味着需要投资于更全面的安全检测工具和流程，以应对日益增长的Agent技能安全威胁。
来源：[研究团队](https://arxiv.org/abs/2608.08468)
原文标题：SkillsMetric: Mapping the Detection Boundary of Static Analysis for Malicious Agent Skills

### 1、ArchAgent v2 自动化多级数据预取架构搜索，IPC 提升 3.8% 并超越冠军方案 {#event-125838}

【AI与通算硬件】 【ArchAgent v2】 【预取】 【性能提升】

📋 **要点**：智能体 AI 在自动化算法设计方面展现出潜力，但扩展到计算机微架构发现仍因搜索空间巨大、硬件预算严格和模拟时间长而困难。**ArchAgent v2** 将自动微架构搜索扩展到多级数据预取。原始 **ArchAgent** 成功在竞赛中发现了单级缓存替换策略，但无法扩展到多级预取，因为设计空间和自由度更大。为克服，作者引入级联进化搜索，通过顺序进化和冻结各级预取器来细分设计空间，以及硬件可实现反馈循环，将实时大小估计嵌入进化过程。在 **DPC4** 的相同规则下评估，**ArchAgent v2** 自动设计的三级预取器优于手工设计冠军，发现的策略在基线上获得 **3.8%** 的几何平均 **IPC** 加速，比前冠军 **BertiGO** 提升 **0.3%**。在低带宽单核配置中，策略获得 **4.6%** 性能加速，而 **BertiGO** 为 **2.6%**。多核进化仍因模拟延迟阻碍进化速度而具挑战。对超过 12,000 个候选设计的进化剖析提供了自动化进化智能体如何探索和合成复杂微架构逻辑的洞见。
📌 **总结**：该工作将自动化搜索成功应用于复杂的多级硬件设计，为芯片架构师提供了一种高效探索设计空间的方法。对硬件供应商和预研团队，**ArchAgent v2** 能够快速生成有竞争力的预取策略，缩短设计周期，且其级联思想可推广到其他硬件配置搜索。这有助于降低先进芯片设计的研发成本并提升性能。

原文标题：ArchAgent v2: A Case Study with the Data Prefetching Championship
