### 1、LobeHub 用三层 Agent 组织架构把团队交接瓶颈从人转向验收 {#event-254054}

【AI应用与产品化场景】 【LobeHub】 【Agentic组织】 【研发效率提升】

📋 **要点**：2026年11月，**LobeHub** 创始人文彬披露其 **Agent** 原生协作实践。**LobeHub** 将团队时间黑洞分为执行类、决策类和盲区类，并构建三层 **Agent** 组织：第一层 **Personal Agent** 替人过滤信息，第二层项目主管 Agent 负责派活与验收，第三层 **Claude Code**、**Codex** 等执行 Agent 干活。技术上，LobeHub 把 Agent 循环、会话状态与执行环境拆开，每步调用独立执行，步间靠队列和 **Redis** 推进，工具调用发往 **AWS** 沙箱，从而突破 **Vercel** 单次 **300 秒**限制，每天承受几万次 Agent 执行。Agent 之间可直接交接，上游主管 Agent 向 lobe-ui 主管 Agent 提需求，次日自动发版并通知升级。
📌 **总结**：**LobeHub** 的实践表明，**Agent** 协作的瓶颈正从任务执行转向人机验收。其三层架构和队列+**Redis+**沙箱的执行解耦方案，为构建 **Agent**ic 组织提供了可复用的工程范式：Agent 循环与执行环境分离使长程任务稳定运行，主管 Agent 层实现任务派发与验收自动化，Agent 间直接交接减少人工转述。开源验收工具 **Acceptance** 将需求拆为检查项并在真实产品中逐项验证，配合 **Agent Vent** 机制将吐槽聚类为修复任务，使新增上报从 84 条降至 49 条。这些探索对核心网运维 Agent 的分层设计与验收流程具有直接参考价值。

### 1、DeepSeek开源Super Agent原型提出Router-Worker分工与静默修复机制 {#event-253959}

【智能体平台、协议与执行系统】 【DeepSeek Super Agent】 【Router-Worker架构】 【研发效率提升】

📋 **要点**：**DeepSeek** Harness团队于10月31日发布《**Super-**agent设计探索：迈向更自主的Agent系统》文章，并在GitHub开源原型dsh-superagent-prototype。核心设计包括：Router作为项目主管负责任务分发和上下文管理，Worker在独立空间执行单一任务，两者上下文隔离、靠订阅同一Thread感知冲突；系统通过规则过滤加模型语义判断两道筛网识别工作环境中的触发器，在无人艾特时主动复现Bug并提交修复PR；采用异步任务机制和Watchdog监控任务进展与方向；将Agent大脑、任务记录和操作电脑分离以支持云端持续运行。原型目前面向单一GitHub仓库，可选接入飞书，部分设计尚未实现。
📌 **总结**：**Super** Agent的**Router-Worker架构**与主Agent带子Agent方案存在本质区别：Router不承担深入推理和频繁协调负担，Worker之间上下文隔离，降低了多任务并行时的推理耦合。触发器驱动和静默修复机制为Agent从被动响应向主动执行演进提供了可参考的工程路径，但多Session设计带来更多token消耗，主动性与成本之间的平衡仍是产品化关键约束。

## AI推理与服务加速

### 1、llm-d发布分布式推理网络方案，UCCL后端在400G IB达49.5GB/s {#event-254001}

【AI推理与服务加速】 【llm-d】 【NIXL】 【性能提升】

📋 **要点**：**llm-d**发布博客详解分布式推理网络方案。**llm-d**的prefill-decode分离架构将计算密集的prefill与内存带宽密集的decode分离到专用GPU池，但KV Cache必须从prefill传输到decode才能生成首个token，传输时间直接影响TTFT。llm-d依赖**NIXL**进行KV Cache传输，**NIXL**提供统一API抽象UCX over **RDMA**、libfabric over **AWS** EFA等后端。llm-d v0.5集成UCCL后端，提供与UCX对等的动态传输选择、本地传输和性能优化。在400G InfiniBand网络中，UCCL和UCX均达**49.5GB**/s，约**99%**线速；Mooncake饱和在**42GB**/s。在100G TCP下，**UCCL GPU-to-**GPU传输**1GB**需**211ms**，UCX需1.8s，慢近**9倍**。llm-d还提供preflight检查工具验证网络健康。
📌 **总结**：**llm-d**网络方案对技术路线而言，表明P/D分离架构中网络成为推理延迟的一阶因素，KV Cache传输优化直接影响TTFT；对产品架构而言，**NIXL**统一抽象使推理服务可跨云和本地部署，UCCL后端在TCP场景下显著优于UCX，为受限部署提供可行选项；对商业判断而言，**llm-d**与NVIDIA合作推进网络栈标准化，可能影响推理服务框架竞争格局，降低分布式推理部署门槛。

### 2、llm-d在三家GPU混部集群验证前缀缓存路由，异构池吞吐最高提升91% {#event-254003}

【AI推理与服务加速】 【llm-d】 【异构GPU前缀缓存路由】 【性能提升】

📋 **要点**：**llm-d** v0.7.0在NxtGen主权云的混合GPU环境上开展异构推理服务实验，集群包含三家GPU厂商的加速器池，通过100G RoCE网络互联，vLLM副本以TP=1部署。实验对比**llm-d**前缀缓存感知路由与Kubernetes轮询调度，服务granite-4.1-8b和sarvam-30b两个模型，工作负载为prefill-heavy的shared_prefix_synthetic。结果显示，在所有单厂商和异构池中，llm-d均提升吞吐并降低TTFT，且改善幅度随池规模和异构程度增长：单厂商池吞吐提升**25%**至**83%**，异构A+B+C池吞吐提升**91%**，TTFT降低**5.4倍**。llm-d通过感知饱和度和缓存命中集中路由，避免轮询调度下低容量或饱和Pod累积队列深度的问题。
📌 **总结**：该实验为已有混合GPU容量的运营商和企业AI平台团队提供了异构推理服务的工程验证：前缀缓存感知路由可使不同代际、不同厂商的加速器池表现为统一推理服务，提升吞吐并降低TTFT，同时保留各厂商平台特定优化。这对主权云、本地部署和错峰硬件更新场景有直接参考价值，说明缓存感知路由器是异构算力池统一服务层的关键组件，可降低异构集群的运维复杂度和容量规划难度。
来源：[llm-d](https://llm-d.ai/blog/heterogeneous-inference-3-vendor-sovereign-cluster)
原文标题：Heterogeneous inference serving across three GPU vendors with llm-d

### 1、复旦创智OpenMOSS团队揭示混合架构长文力学，提出滑窗线性注意力改进外推 {#event-253741}

【AI模型】 【OpenMOSS】 【混合注意力架构】 【架构替代】

📋 **要点**：复旦大学与上海创智学院**OpenMOSS**团队（邱锡鹏、何子薇指导）在376M至**3B**四种规模上系统比较RoPE/**NoPE**全注意力、滑窗注意力和GLA/GDN门控线性注意力的混合架构。研究发现混合位置让混合架构具有更好长文表现，但存在滑窗混合扩长的跷跷板效应和线性混合没有免费午餐效应。团队提出短窗口疲惫与长窗口懒惰现象，并通过增大滑窗窗口和结合LongCE损失显著提升SWA-**NoPE**/RoPE层混模型的长文续训表现。针对线性混合外推不足，提出滑窗线性注意力（**SWLA**）对GLA/GDN有效相对位置范围施加滑窗约束，同时对NoPE注意力使用对数校正，在RULER的NIAH-SK1任务上从4k训练长度外推到64k，达到**16倍**免训练外推并保持**100%**准确率。
📌 **总结**：该工作从混合位置角度为长上下文混合架构设计提供系统性分析框架，揭示滑窗注意力和线性注意力在长度外推与扩长训练中的互补关系。对模型架构研究者，SWLA策略和LongCE损失是可复用的改进手段；对推理服务团队，混合架构的窗口大小选择和混合比例调优直接影响长上下文场景的吞吐和延迟表现，该研究提供了实验依据。

### 2、商汤开源 SenseNova Loop-9B-Preview，以循环计算让 9B 参数媲美 27B 模型 {#event-253800}

【AI模型】 【SenseNova Loop-9B-Previ…】 【Looped Transformer】 【架构替代】

📋 **要点**：商汤科技于 10 月 30 日宣布开源日日新 **SenseNova Loop-**9B**-Preview**，该模型采用 **Looped Transformer** 架构，以 **9B** 尺度模型为基座，保留首尾各 4 层原始解码器模块，将中间层改造为参数共享的循环计算模块，通过多轮迭代扩展有效计算深度。模型进一步引入 mHC（**Manifold-Constrained Hyper-Connections**），利用多路残差连接与受约束的信息混合增强特征交互并维持信号传播稳定性。官方称在当前评测设置下，模型在代码生成、办公场景和智能体任务等方向优于其他模型，并在 **WorkBuddy Bench**、**RaccoonPPT Bench** 和 **AutomationBench** 上超过 **Qwen3.5-27B**；消融实验显示采用 mHC 后 **GPQA Diamond** 和 **TeamBench** 分别提高 4.42 分和 13.34 分。
📌 **总结**：该模型把提升小参数模型能力的路径从扩大参数量转向扩展有效计算深度，若评测结论可复现，将降低复杂推理与多步 **Agent** 任务的部署门槛，对端侧、边缘与成本敏感场景的模型选型构成新选项；对预研规划者而言，需关注循环计算带来的推理延迟与显存开销是否被评测覆盖，以及 mHC 机制在长上下文与工具调用场景下的稳定性，同时跟踪商汤后续 **DSA** 与自适应迭代次数机制的进展。

### 1、上海交大联合复旦腾讯优图开源EvaOmni，评测全模态模型视听证据定位 {#event-253761}

【模型评测】 【EvaOmni】 【全模态评测】 【研发效率提升】

📋 **要点**：上海交通大学、复旦大学、腾讯优图实验室等机构联合开源**EvaOmni**基准，面向全模态大语言模型同时评测答案正确性与视听证据定位。基准包含392段视频、1027道人工标注问答，覆盖15种细粒度能力，模型需在选择答案的同时返回支持答案的音频和视频时间区间。对24个Omni LLM的评测显示，**Gemini3.7-**Flash答案准确率达**79.4%**，双模态精确定位得分B.G.为**35.1%**，与人类专家的**94.3%**相差59.2个百分点。在Level 3复杂推理任务中，**Gemini3.7-**Flash答案准确率**79.1%**但B.G.降至**12.3%**。
📌 **总结**：**EvaOmni**将答案正确性与视听证据定位拆分为可核对指标，揭示当前Omni LLM在精确定位证据方面与人类专家差距达59.2个百分点，为全模态**模型评测**提供更细粒度标准。对AI前沿技术预研规划师而言，该基准可用于评估模型在视听推理任务中的证据溯源能力；对技术主管而言，模型选型时需同时关注答案准确率和证据定位精度，而非仅看答题正确率。

### 2、飞捷科思联合复旦发布Fysiverse-UniWAM，24项真机测试导航与移动操作双第一 {#event-253739}

【模型评测】 【Fysiverse-UniWAM】 【具身智能】 【性能提升】

📋 **要点**：飞捷科思（**Fysics AI**）联合复旦大学认知与智能技术实验室提出统一世界动作模型**Fysiverse-UniWAM**，从预训练视频世界模型出发，通过共享骨干网络实现导航与操作联合学习。团队提出MAP（操作锚定位姿）将适合后续操作的参考位置与朝向作为导航学习目标，并自动生成超过**150万**条轨迹、约**7500小时**的MAP-Data数据集。**Mixed-**Stream架构让导航流和操作流独立采样但共享视频DiT与动作DiT骨干，通过Mixture-of-Transformers实现协同建模。在MAP-Bench基准中平均位置误差9.85厘米、朝向误差2.30°，较最强基线分别降低**30.1%**和**44.0%**。24项真机测试中13项导航位置误差全部领先，4项移动操作成功率全部第一，平均成功率**80.0%**，领先π₀.₅达17.5个百分点。
📌 **总结**：该工作表明统一机器人能力不只有扩大预训练规模一条路，通过MAP几何监督和Mixed-Stream架构设计，可在不依赖完整移动操作示范数据的条件下实现导航与操作协同。对**具身智能**研究者，**MAP-**Data自动生成流程和零样本真机迁移结果提供了降低真实数据依赖的可行方案；对机器人厂商，该路线可降低数据采集成本，但需关注板载算力和推理延迟对实际部署的约束。

### 1、LeanGuard 以 Lean4 策略运行时拦截工具调用，提示注入成功率从57.9%降至5.9% {#event-256174}

📌 **总结**：**llm-d**网络方案对技术路线而言，表明P/D分离架构中网络成为推理延迟的一阶因素，KV Cache传输优化直接影响TTFT；对产品架构而言，**NIXL**统一抽象使推理服务可跨云和本地部署，UCCL后端在TCP场景下显著优于UCX，为受限部署提供可行选项；对商业判断而言，**llm-d**与NVIDIA合作推进网络栈标准化，可能影响推理服务框架竞争格局，降低分布式推理部署门槛。
