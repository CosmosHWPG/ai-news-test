5、epistemic-guard 用进程外 MCP 收据代理把工具调用伪造与记忆污染纳入运行时校验

智能体平台、协议与执行系统 epistemic-guard MCP 收据代理 安全风险

📋 要点：针对使用模型上下文协议（MCP）的语言模型智能体面临的三类运行时校验缺口——工具调用后叙述虚构未执行或超时的副作用、未验证的模型叙述或网页文本与已执行工具输出一同进入持久记忆、镜像网页满足多源佐证造成回声放大——研究提出 epistemic-guard v0.5.2，一个开源 Python 库与进程外 stdio MCP 收据代理，共 15 个模块、GPU 显存占用 0 MiB。该方案把 Ed25519 签名密钥隔离在进程外，写入 RFC 6962 Merkle 日志并做 AER-1 收据转换，在 CPU 上用经 SHA-256 校验的 OpenVINO INT8 编码器检查回合后叙述，对 7 个溯源域的 SQLite 写入做门控，并折叠逐字与轻度编辑的线缆同步 RAG 镜像。在一致性测试中，它拒绝 100% 被篡改收据（200 个 Merkle 叶），通过 58/58 官方 AER-1 摄入向量与 50/50 参考校验导出，验证 100% 的 40 次故障注入线缆调用与 100 次并发追加且零密钥泄露，阻断 100% 的 100 次未授权记忆写入。在 250 条冻结基准轨迹上达到 93.2% 准确率、17.9 毫秒热中位 CPU 延迟，比 12B-14B GPU 评审器高 6.4 至 6.8 个百分点且延迟低 4.26 至 4.5 倍；在 60 条实时 mcp-proxy 轨迹上以 9.16 毫秒 p50 捕获 96.15% 危害。

📌 总结：该工作把 MCP 智能体的安全边界从执行前线缆检查推进到执行后收据与叙述绑定，用进程外签名、Merkle 日志和 CPU 端 INT8 编码器实现零 GPU 显存的低延迟校验，直接回应了工具调用智能体在记忆溯源和动作伪造上的可信缺口。对技术路线而言，它示范了如何在不依赖大参数量 GPU 评审器的前提下达到更高准确率与更低延迟，为智能体运行时安全提供了可复用的开源组件；对产品架构而言，收据代理与溯源门控可作为 MCP 网关或智能体运行时的标准安全层；对合规与审计而言，RFC 6962 Merkle 日志与 AER-1 收据转换便于满足可追溯性要求，但实时轨迹上 38.24% 的假阳性率提示生产部署仍需调优。

📋 要点：PyTorch 发布 ExecuTorch-TensorRT，基于 Torch-TensorRT 2.15 与 ExecuTorch 1.6，将 PyTorch 模型经 torch.export 捕获后由 TensorRT 编译，无法转换的部分交由 ExecuTorch CUDA 后端在同一 CUDA 流上执行，最终保存为无需 libtorch 的 .pte 程序。在 NVIDIA Jetson Orin Nano 8GB 上，3.6B 参数的 pi0.5 策略每动作块约 467ms，而 PyTorch eager 模式内存不足；GR00T 1.7 约 215ms，整体性能与 ONNX-TensorRT 差距在 4% 以内，内存占用显著低于 Torch-TensorRT 路径。

📌 总结：该方案说明 PyTorch 生态正在补齐边缘端到端部署链路，对技术路线的影响在于机器人策略和端侧模型可摆脱 libtorch 依赖，对产品架构的影响在于边缘设备内存占用下降使更大参数模型可落地，对研发效率的影响在于一次 pip 安装即可完成编译与运行，对商业判断的影响在于 Jetson 等边缘板卡的推理部署门槛降低，有利于端侧 AI 应用规模化。
