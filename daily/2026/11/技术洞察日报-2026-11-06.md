### 1、Coca-Cola以潜在上下文压缩降低智能体token消耗70%-89% {#event-261244}

【智能体平台、协议与执行系统】 【Coca-Cola潜在压缩模型】 【工具观察压缩】 【成本下降】

📋 **要点**：2026年11月4日，一篇arXiv论文指出LLM智能体通常将原始工具输出追加到上下文，多步交互中长而嘈杂的观察带来大量上下文开销并稀释对任务相关信息的注意力，而现有token剪枝与摘要方法受离散文本表示限制，压缩比有限。作者提出**Coca-**Cola连续潜在上下文压缩模型，将**工具观察压缩**为潜在token并嵌入智能体输入嵌入空间；同时引入动作保持训练，对齐完整观察与压缩观察下智能体的下一动作分布，使压缩模型学习保留决策关键信息的动作充分潜在token。在四个问答基准、两个模型族上的网络搜索智能体实验中，**Coca-**Cola降低token消耗**70.01%**-**89.24%**，端到端运行时间降低**24.45%**-**55.97%**，同时持续提升任务表现。代码已在GitHub公开。
📌 **总结**：**Coca-**Cola把智能体上下文压缩从离散文本摘要推进到连续潜在表示，在显著降低token与运行时间的同时提升任务表现，对智能体执行系统的上下文管理有直接工程价值。对架构师而言，潜在token嵌入输入空间意味着压缩层可与现有智能体框架解耦集成；对技术主管而言，**70%**以上token节省对长程智能体成本结构影响显著；对预研规划而言，动作保持训练为压缩与决策一致性提供了可复用范式。
来源：[研究团队](https://arxiv.org/abs/2611.06500)
原文标题：Tools Need Not Speak in Text: Latent Context Compression for Agents

### 2、MKD2World用类型化空间Markdown世界模型提升Web智能体任务成功率 {#event-261118}

【智能体平台、协议与执行系统】 【MKD2World】 【世界模型】 【体验提升】

📋 **要点**：GUI智能体可借助**世界模型**前瞻提升决策质量，但前提是预测状态能准确反映动作后的界面。现有状态表示难以同时捕捉界面布局、UI语义和显式位置。研究团队提出类型化空间Markdown（**TSM**），一种面向桌面Web界面的Markdown风格文本状态表示，按空间关系序列化块级和原子级UI元素，联合编码类型、视觉语义、显式位置、可选控件状态和层级归属。为训练截图到**TSM**的渲染器，团队构建AtomBlock-WebUI数据集，通过在HTML注入元素类型标签并在渲染后直接提取边界框，避免事后推断导致的标注错误。基于TSM提出**MKD2World**桌面Web**世界模型**，分两阶段训练当前状态描述和动作条件下一状态预测。推理时智能体按需查询**MKD2World**并执行摘要步骤，提取任务相关证据选择动作。**MKD2World-**9B在域外测试集EleF1为26.50，超过GPT-5.6-Sol的14.98达11.52分；在Online-Mind2Web任务上，将Qwen3.5-**35B**智能体成功率从**22.94%**提升至**37.61%**。
📌 **总结**：**MKD2World**证明将界面状态表示为类型化空间Markdown并训练动作条件**世界模型**，可让Web智能体在执行前预测动作后果，从而在开源模型上取得接近领先GUI**世界模型**的性能。对智能体平台架构而言，该工作提供了一条不依赖闭源大模型、通过状态表示和世界模型提升任务成功率的工程路径，代码已在GitHub开源，便于复现和集成。对预研规划而言，世界模型作为智能体执行系统的可选组件，可能改变当前以工具调用和提示工程为主的架构，将规划能力下沉到状态预测模块，但需关注域外泛化和标注数据构建成本。
来源：[研究团队](https://arxiv.org/abs/2611.06544)
原文标题：MKD2World: A Typed Spatial MarkDown World Model For Web Agents

### 3、SpecCompact用槽位并行语义推测加速智能体上下文压缩，最高提速5.63倍 {#event-261525}

【智能体平台、协议与执行系统】 【SpecCompact】 【上下文压缩】 【性能提升】

📋 **要点**：LLM智能体使用**上下文压缩**来管理不断增长的交互历史，但用大模型摘要长历史会带来显著延迟，因此压缩需在信息保留与延迟之间权衡。研究团队观察到结构化摘要槽位在独立生成时仍能保留信息，据此提出**SpecCompact**框架，通过槽位并行语义推测加速压缩。**SpecCompact**微调一个小型起草器并并行生成槽位；目标模型逐行验证每个提议并修复被拒内容，后续起草则使用更新后的槽位前缀。系统优化进一步减少重复的上下文处理和模型调用。在AppWorld与τ³基准、两个目标模型上，SpecCompact相对Hermes风格摘要实现2.04至**5.63倍**压缩提速。独立的下游评估显示存在随模型和任务而异的性能权衡，Hermes内部用户研究进一步显示中位压缩提速达**8.68倍**。
📌 **总结**：该工作把推测解码的起草-验证范式迁移到智能体**上下文压缩**，对技术路线意味着长会话智能体的延迟瓶颈可以通过小模型起草加目标模型逐行验证来缓解，而不必在信息保留上大幅让步。对产品架构而言，压缩阶段的加速可直接降低多轮智能体应用的响应时延和推理成本，适合在上下文管理器或运行时层集成；对研发规划而言，下游评估显示性能权衡随模型和任务而异，提示在采用该方案时需针对具体业务做端到端效果验证，而非只测压缩速度。
来源：[研究团队](https://arxiv.org/abs/2611.06876)
原文标题：SpecCompact: Accelerating LLM Agent Context Compaction with Slot-Parallel Semantic Speculative Verification

### 4、Google将Agent Substrate、gVisor、OpenRL捐给CNCF，Agent Substrate 1.0上线GKE {#event-260304}

【智能体平台、协议与执行系统】 【Agent Substrate】 【CNCF沙箱】 【架构替代】

📋 **要点**：随着AI从人类规模走向智能体规模，**Agent**以有状态循环持续提出动作、派生Subagent、在沙箱内执行代码并回灌模型，传统Kubernetes为每个活跃**Agent**保留Pod会锁死内存与CPU。**Google**宣布将源自内部的**Agent Substrate**、gVisor、OpenRL三个项目捐给CNCF，其中**Agent Substrate**达到1.0并在GKE上GA。Agent **Substrate**把有状态Actor与身份同计算解耦，空闲时快照到存储、请求到来时在500毫秒内恢复到任意Worker，宣称可支撑百万级沙箱、容器密度达标准容器**10倍**、每秒500次以上挂起恢复；gVisor以用户态应用内核隔离不可信代码，支持GPU/TPU与检查点恢复；OpenRL在Kubernetes上以Python原语编排RL后训练，配合llm-d做前缀感知路由与GPU时间切片。
📌 **总结**：该动作把智能体运行时、沙箱隔离与RL后训练从单一厂商资产转为CNCF中立项目，对技术路线意味着Agent执行层可能形成类似Kubernetes的开放标准底座，云厂商、芯片厂商和独立软件商可平等参与。对产品架构而言，**Actor**/**Worker**/Gateway的解耦与亚秒级恢复为高密度、低空闲成本的Agent托管提供参考范式，gVisor的GPU/TPU与快照支持则影响沙箱选型。对商业判断，**Google**借开源治理扩大GKE与TPU/GPU生态吸引力，同时把gVisor内核补丁上游化障碍转为社区议题，可能削弱单一厂商在Agent基础设施上的排他优势。
来源：[Google Cloud](https://cloud.google.com/blog/products/containers-kubernetes/open-infrastructure-for-autonomous-agents-comes-to-cncf/)

### 6、SumOne用掩码重建训练独立摘要器，智能体推理成本降约78% {#event-261240}

【智能体平台、协议与执行系统】 【SumOne摘要器】 【上下文压缩】 【成本下降】

📋 **要点**：2026年11月4日，一篇arXiv论文提出SumOne，针对长程语言模型智能体交互历史不断膨胀、**上下文压缩**必要的问题。现有学习式压缩方法常依赖下游任务结果或求解器行为，导致训练与特定任务或智能体耦合。SumOne是独立摘要器，通过掩码重建训练以保留智能体历史信息：给定过期历史的摘要，冻结的重建器恢复原始轨迹中被随机掩码的部分，重建质量结合长度惩罚构成任务无关奖励，用GRPO优化摘要器，从而直接从原始轨迹获得自监督信号，无需参考摘要或下游任务执行。推理时仅保留轻量摘要器，实现即插即用**上下文压缩**。在长程搜索与软件工程任务上，SumOne相对全上下文运行，在DeepSearchQA上降低约**78%**推理成本，在SWE-bench Verified上降低约**75%**，绝对性能下降0.04，且同一检查点可跨下游模型与智能体框架迁移而无需额外微调。
📌 **总结**：SumOne把智能体记忆压缩从任务耦合的训练范式转为任务无关的自监督摘要，推理时即插即用，直接降低长程智能体的token成本与上下文压力。对架构师而言，独立摘要器可作为记忆层组件嵌入现有智能体框架，无需改动求解器；对技术主管而言，约**75%**-**78%**的推理**成本下降**对长程任务的经济性有实质改善；对预研规划而言，掩码重建加GRPO的奖励设计为记忆压缩提供了可复用的训练范式。
来源：[研究团队](https://arxiv.org/abs/2611.06445)
原文标题：SUMONE: A Simple and Efficient Summarizer for Plug-and-Play Agent Memory

📌 **总结**：该工作把扩散草稿**模型训练**的**上下文并行**瓶颈定位为查询—上下文非对称性与锚点采样负载不均，说明注意力通信可以做到与上下文长度无关。对训练基础设施而言，**Split-KV**在CP规模64下保持**85%**至**91%**弱扩展效率、较最快基线最高加速**3.67倍**，且LPT负载均衡不平衡度低于**1%**、规划速度快三个数量级，为长上下文草稿**模型训练**提供可扩展的并行方案，降低跨节点通信开销与调度成本；对推测解码技术路线而言，训练效率提升有助于扩散草稿模型在更大上下文场景中落地。

### 1、germline execution以数据隔离限制MCP工具链泄露，153次攻击零未授权披露 {#event-261250}

【AI安全、可信与治理】 【germline execution】 【MCP工具链】 【安全风险】

📋 **要点**：针对AI智能体依赖第三方MCP服务器、而签名真实并不保证行为良性的信任缺口，研究者先演示一个合法签名的MCP工具在运行政策允许的目标请求中嵌入敏感数据实施泄露，Meta的MCPGuard-Dynamic在同一运行中能拦截直接外泄尝试，但在全部试验中未能阻止该攻击。为此研究者提出**germline execution**：每次工具调用都运行在从无数据胚系进程派生的临时副本中，每个副本只获得其目标所授权的信息，从而在不检查也不信任工具实现的前提下限制信息泄露。在副本隔离与无数据胚系的显式假设下，论文证明了对每个签名发布的汇点非干扰；在153次攻击运行中，**germline execution**下未检测到未授权披露，而基线防御和消融运行的比例为**5.9%**至**74.5%**。

原文标题：Signed, Sealed, Leaked: Trust Beyond Signature for MCP Toolchains

### 6、研究指机器遗忘标准指标可掩盖特征差异，单一梯度步即可暴露分歧 {#event-261393}

【AI安全、可信与治理】 【机器遗忘】 【特征恢复】 【合规/监管影响】

📋 **要点**：**机器遗忘**通常用删除后标准指标评估，即把遗忘模型与在剩余数据上重训的模型比较，但这类快照评估可能掩盖两个模型所编码特征上的重要差异。论文证明，若遗忘模型与重训模型输出一致但编码不同特征，对其预测头做单个梯度步即可打破这种一致；论文进一步表明，删除任意小比例数据就可能使重训选择性质不同的特征，因此匹配重训可能要求学习完整模型从未拥有的特征。论文随后提出区分缺失特征与多余特征的**特征恢复**度量，并在八种遗忘方法上验证。
📌 **总结**：结果显示，在标准指标上表现良好的模型往往无法恢复重训特征，而这种不匹配可预测后续再学习与下游适配相对重训的偏差，且直接纠正该不匹配能够系统性减少此类偏差。对**机器遗忘**的技术路线而言，这意味着仅凭删除后快照指标不足以判断遗忘是否等价于重训，评测需引入特征层面的恢复度量；对合规与治理而言，该发现提示以重训等价性为卖点的遗忘声明需要更严格的验证口径，否则可能在再学习或下游微调后暴露出被掩盖的差异。
