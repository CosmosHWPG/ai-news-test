1、清华联合无问芯穹开源 Uni3Sim，面向超节点集群的推理仿真平台

AI推理与服务加速 Uni3Sim 超节点集群仿真 研发效率提升

📋 要点：2026 年 11 月，无问芯穹联合清华大学朱振华助理教授、汪玉教授团队开源仿真平台 Uni3Sim，面向大规模 LLM 推理服务。平台以统一异构硬件、统一存储层次和统一 Scale-Up/Scale-Out 互连协议与拓扑为核心，构建 ArchPrism、HBFrame 和 ProtoBridge 三个模型，分别计算算子、存储访问和通信任务执行时间，并接入 SGLang、vLLM 原生调度器。团队在 NVIDIA A800、沐曦 C500 和昇腾 910B 上验证，Qwen3 和 Llama3.1 系列模型 TTFT 误差小于 21.2%，TPOT 误差小于 9.4%，系统吞吐误差小于 5.2%。

📌 总结：Uni3Sim 把超节点集群的性能评估从依赖物理试错转为可复现的数字仿真，使开发者在硬件落地前就能比较不同芯片、存储和互连方案对 TTFT、TPOT 和吞吐的影响。其存储池实验显示，GLM-5.2 在 128 张 H200 上实现 1.31 倍每 GPU 逻辑 Token 吞吐；缓存实验则揭示 KV Cache 复用率提至 60% 时吞吐增加 50.7% 但每 GPU 小时收入下降 19.7%，说明更高吞吐不一定带来更高收入。该平台对推理基础设施设计和商业定价策略均有参考价值。

2、LMSYS 为 ERNIE 5.5 Flash 在 SGLang 上实现 1074 tokens/s 低延迟解码

AI推理与服务加速 SGLang 低延迟解码 性能提升

📋 要点：LMSYS 针对 ERNIE 5.5 Flash 这类采用 mHC 多残差流的大型稀疏 MoE 模型，在 SGLang 中补充低延迟解码支持并做端到端优化。团队在四张 SM100 GPU、BS=1、55K 输入与 1K 输出条件下，引入低延迟 GEMM 与张量并行，集成 DSpark 投机解码，迭代调优计算通信融合、多流执行与 PDL，并完成 MegaLLMoE、注意力数据流重构和 One-Pass mHC 等优化，最终实现 1074 tokens/s 的端到端解码速度。

📌 总结：该工作说明低并发解码是典型内存受限负载，优化重点在于缩短串行关键路径上的权重读取、调度同步与通信开销。对推理服务架构而言，投机解码、MoE 大核融合与注意力数据流重构可显著降低单请求延迟，为长上下文、低并发场景下的 serving 系统提供可复用的工程路线，也提示模型架构与推理引擎需协同设计。

3、llm-d与SGLang社区实现Kubernetes原生Wide-EP服务，TTFT最高降5.9倍

AI推理与服务加速 SGLang 分层KV缓存 性能提升

📋 要点：llm-d与SGLang社区合作，将SGLang作为llm-d的可选推理引擎后端，与vLLM并列，仅需替换引擎相关部署叠加层与路由配置即可复用同一DisaggregatedSet编排、按rank的InferencePool发现、前缀缓存感知路由与验证流程；在Wide-EP部署中每个注意力数据并行rank持有独立KV缓存并共享专家权重，双方使每个DP rank成为独立可路由可观测的Kubernetes端点；实测在16卡1P1D部署中，将驱逐的KV块卸载到主机内存L2使缓存命中率保持85%至95%，并发128输出从319提升至1257 tok/s、提升3.94倍，中位TTFT从174.2秒降至20.1秒；扩展至32卡H200后中位TTFT再降5.9倍至3.43秒、输出1903 tok/s，共享L3在故障切换时以99.94%命中率恢复108万token并将冷副本恢复TTFT降低57%。

📌 总结：该集成表明推理服务栈正走向引擎可插拔与分层KV缓存标准化，SGLang与vLLM可在同一编排与路由体系下互换，降低多引擎选型的迁移成本；对架构师而言，主机内存L2与共享L3的分层设计直接决定长上下文场景的缓存命中率与故障恢复时延，是容量规划与SLA设计的关键变量，对技术主管而言，TTFT从174.2秒降至3.43秒的量化结果可作为推理集群扩容与成本权衡的依据，对商业判断而言，多副本韧性提升有助于支撑高并发在线服务的可用性承诺。

4、SGLang与Miles实现比特精确的True On-Policy RL，消除训练与推理概率偏差

AI推理与服务加速 SGLang与Miles True On-Policy RL 研发效率提升

📋 要点：2026年11月23日，LMSYS博客发布由RadixArk Miles团队撰写的技术文章，介绍True On-Policy RL方案。在LLM强化学习中，推理引擎生成响应，训练器更新权重，但两者运行不同内核、不同批次形状，有时精度不同，在MoE模型中微小数值差异可能导致token路由到不同专家，使训练变为离策略。TOP RL通过让训练器逐比特复现推理引擎的log-probabilities，消除这一偏差。该方案在SGLang和Miles中实现，已在DeepSeek-V4-Flash和V4.1、GLM-5.2/5.3和5.3-Flash、Qwen3、3.5/3.6/3.8和3.8-Flash-Next上验证，所有模型族在全深度下通过比特级前向一致性测试，支持投机解码，已在Hopper和Blackwell GPU上测试。

📌 总结：TOP RL方案解决了在线策略强化学习中训练器与推理引擎概率不一致的根本问题，对技术路线而言，比特精确对齐可消除MoE模型中的专家路由偏差，使PPO/GRPO等算法真正保持在线策略，有望提升RL训练稳定性和收敛效率；对产品架构而言，该方案要求推理引擎和训练框架深度协同，SGLang和Miles的集成模式可能成为RL训练基础设施的新参考；对研发工作而言，代码和启动配方将开源，可降低复现门槛。

AI安全、可信与治理 AWS WAF AI Security MCP/A2A 安全风险

📋 要点：2026年11月23日，AWS WAF的AI端点自动发现与防护正式可用。发现能力通过新的API Gateway API Portal提供，从流量日志和服务配置记录中自动识别API Gateway、Application Load Balancer和Amazon CloudFront后的LLM、MCP和A2A端点，无需部署代理或转发日志，未记录的公开MCP服务器会以影子API形式呈现。防护能力通过新的AWS WAF AI Security托管规则组提供，实施协议识别和合规检查以阻断畸形的MCP和A2A消息；启用内容检查后，规则组调用Amazon Bedrock Guardrails的InvokeGuardrailsCheck API检测请求中的提示注入、越狱尝试、有害内容以及响应中的敏感信息。API Portal在32个AWS区域可用，AI Security在7个区域可用，内容检查调用由Bedrock单独计费。

2、OpenAI 与 Cisco 开源 Shirudo 运行时，用 eBPF 盾在打补丁前防护 Linux

AI安全、可信与治理 Shirudo eBPF 防护盾 安全风险

📋 要点：针对漏洞披露后打补丁与重启仍需数天、期间服务暴露于攻击的问题，OpenAI 与 Cisco 开源 Shirudo 运行时，利用 eBPF 在操作系统关键点运行小程序，观察可疑行为并对运行中系统施加定向防护。其设计包含四项能力：无需重启即可阻断脆弱代码路径的实时防护、面向智能体的可编程控制以调查漏洞并生成盾、加载前经密码学签名与 eBPF 校验器验证的可信部署，以及基于 TPM 的硬件背书验证记录。在受控测试中，由 Codex 生成的盾为 Java Base64 解码器增加输入检查并附加到运行中的 Elasticsearch 进程，阻断了 Java4Shell 攻击尝试。

📌 总结：Shirudo 把 AI 生成防护与 eBPF 内核可编程能力结合，使安全团队能在补丁窗口期以可验证方式维持服务运行，对基础设施安全架构与运维流程有直接参考价值；其开源与签名验证设计也为智能体参与安全运维提供了权限与审计边界，但长期效果仍需在更多真实漏洞场景中验证。

3、Anthropic 与 Claude 协作发布黎曼猜想 Lean 4 形式化证明，社区完成多轮独立核验

AI安全、可信与治理 Claude 形式化验证 安全风险

📋 要点：2026年11月21日，Anthropic 研究科学家 Levent Alpöge 与人工智能模型 Claude 协作，公开发布黎曼猜想及广义黎曼猜想的 Lean 4 形式化证明，包含175187个文件、约1700万行代码。次日 Lean FRO 与 Mathlib 社区发布联合声明，确认代码通过严格编译与陈述比对。社区核验包括静态扫描排查 native_decide 等逃逸原语、脱离原环境导出重放至 nanoda 等多个独立检查器、独立干净文件比对与断网沙盒复现。MIT 数学家 Andrew Sutherland 的独立审计确认整个代码库没有 sorry、没有自定义公理，仅依赖 Lean 标准库三条基础公理。此前质疑者指出代码中存在 anyGeometry 定义恒返回 True，但该定义仅用于类型检查，不影响最终定理有效性。

📌 总结：该事件对 AI 安全与可信治理有深远影响：AI 生成的大规模形式化证明引入新的信任危机，信任主体从人类数学家的职业声誉转向 AI 和工具链的可靠性，AI 以达成目标为导向的训练机制可能促使其钻工具链或内核空子。对技术路线而言，形式化验证在 AI 辅助数学发现中的角色从辅助工具升级为关键裁判，RLVR 范式依赖证明助手提供客观负反馈；对产品架构而言，多独立检查器交叉重放和沙盒复现成为高保障验证的标准流程；对商业判断而言，形式化验证能力可能成为 AI 数学和科学发现领域的重要竞争壁垒。
