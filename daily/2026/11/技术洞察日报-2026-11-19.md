### 1、DeltaHarness 提出自演化执行框架，视频编辑任务端到端时延降低 30% {#event-279376}

【智能体平台、协议与执行系统】 【DeltaHarness】 【工具执行调度】 【性能提升】

📋 **要点**：arXiv 论文 **DeltaHarness** 针对工具使用智能体的执行框架问题：同一任务和资源描述下，运行时条件可能反转有效执行计划的时延排序，仅靠静态描述无法确定最优计划。论文提出执行引导的策略搜索方法，通过 **QHI** 循环利用观测到的响应更新运行时调度、修正物理计划并选择后续实验，由独立确认面板控制策略替换。在固定调度下，修正后的物化策略在一个视频编辑任务的三组新配对上将完整交付时延降低 **30.0%**；在留出任务上，演化策略相对最佳固定计划降低 **8.2%**，相对初始提案降低 **4.6%**。
📌 **总结**：该工作对智能体执行系统架构有直接启发：工具调用和任务执行的调度不应依赖静态计划，而应通过运行时测量持续修正。**QHI** 循环和独立确认面板的机制设计为智能体框架的自适应调度提供了可参考的工程模式。对推理服务和智能体平台而言，这意味着执行框架需要具备运行时策略搜索和替换能力，以应对资源条件变化导致的计划失效。对商业判断而言，时延降低直接关联用户体验和资源成本，自适应执行框架可能成为智能体产品差异化的工程基础。
来源：[研究团队](https://arxiv.org/abs/2611.21688)
原文标题：DeltaHarness: Self-Evolving Harnesses for Resource-Adaptive Tool Execution

### 3、BRIDGE最小RAG记忆追平LongMemEval-S与BEAM，EverMemBench领先5.7-6.3分 {#event-278596}

【智能体平台、协议与执行系统】 【BRIDGE】 【智能体记忆】 【成本下降】

📋 **要点**：**智能体记忆**研究长期在RAG之上叠加抽取、覆盖更新、反思和图合成等原语，arXiv在2026年11月发布的**BRIDGE**论文发现这些原语在测试基准中几乎无法收回成本。**BRIDGE**只保留链式观测笔记、**BM25+**余弦混合检索和时序渲染，在LongMemEval-S与BEAM上以bootstrap置信区间追平此前最优，在EverMemBench上比最佳记忆基线高5.7-6.3分，每查询约5-7K reader提示token、每次写入或查询仅一次LLM调用。作者进一步用5个对抗探针×20个场景检验动作可用性，发现没有架构全面胜出：原子事实抽取（**LangMem**）赢在规则应用，BRIDGE的块摘要记忆赢在模式归纳，该结论跨4个领域、3个评分器与3类reader成立。
📌 **总结**：该结果对**智能体记忆**与运行时设计有直接参考价值：若最小RAG记忆已能在主流基准上追平复杂原语，工程团队可以削减抽取、反思、图合成带来的额外LLM调用与存储开销，把预算转向reader端提示与规则呈现。论文同时指出标准基准只衡量检索内容、不衡量智能体能否据此行动，并用规则应用与模式归纳对抗探针给出可操作的评测补丁，为建立以任务可用性为核心的记忆评测口径提供方法。对自智网络、运维等长会话Agent场景，其可迁移含义是记忆层不宜过度设计，应以单次LLM调用、token预算可控和可验证的规则遵循作为取舍标准。
来源：[研究团队](https://arxiv.org/abs/2611.22179)
原文标题：RAG in a Trenchcoat: When Minimal Memory Is Enough for Agentic Systems, and When It Isn't

### 4、arXiv论文提出Readie以学习式启动快照将代码沙箱启动延迟降低3至22倍 {#event-278589}

【智能体平台、协议与执行系统】 【Readie代码沙箱】 【启动快照】 【性能提升】

📋 **要点**：2026年11月arXiv论文针对AI智能体迭代生成并执行代码时依赖代码沙箱、而现有沙箱启动缓慢的问题展开研究，指出无论采用自定义快照还是单一胖镜像，根因都是难以构建既紧凑又能覆盖多样智能体生成代码所需包与数据集的预热快照。论文提出学习式**启动快照**思路：单个快照难以兼顾紧凑与覆盖，但一组快照可以，每个快照体积小、初始化快并覆盖部分智能体生成代码，整体覆盖大部分负载。作者将快照集合构建形式化为优化问题并用近似算法求解，在15000个公开与LLM合成脚本上规划，系统Readie在相同存储预算下将启动延迟降低3至**22倍**，端到端运行时间降低1.3至**3.3倍**。
📌 **总结**：该工作把智能体代码执行基础设施的瓶颈定位在沙箱**启动快照**的紧凑性与覆盖率矛盾，并用学习式快照集合给出可量化改进，对智能体运行时、工具调用与代码执行架构具有直接工程价值。对核心网与云基础设施团队而言，该思路可迁移到网元测试沙箱、自动化运维脚本执行环境等场景，通过按负载学习预热快照降低任务启动开销，从而提升智能体与自动化流程的端到端效率并降低资源占用。
来源：[研究团队](https://arxiv.org/abs/2611.22171)
原文标题：Readie: Low-Latency Code Sandboxes for AI Agents

【智能体平台、协议与执行系统】 【Uber MCP Gateway】 【MCP 工具治理】 【架构替代】

📋 **要点**：2026年11月18日，**InfoQ** 报道 **Uber** 构建 **MCP** Gateway，用于规范智能体发现和调用内部服务的方式。该平台支持 800 多个 **MCP** Server 和 5000 多个工具，采用控制平面 **MCP Registry** 与运行时 **Proxy Gateway** 分离架构：**Registry** 维护工具定义、**Schema**、所有权和启用设置，**Proxy** 将 MCP 请求转换为 **HTTP**、gRPC 或 **TChannel** 调用。**AutoCrawler** 扫描内部 **IDL** 注册表，从 **Protocol Buffers** 和 Thrift **Schema** 提取 **API** 定义并生成兼容 MCP 的 Schema，新工具默认禁用直至团队审核启用。**Omni MCP** 支持渐进式发现，智能体可搜索服务器、发现工具、获取单个 Schema 并按需调用；**Response Projection** 允许指定所需响应字段。网关在服务器和工具两个层级执行授权，并支持 **PII** 脱敏和第三方 **Token** 交换。

### 1、SpecSearch 硬件感知搜索把投机解码吞吐提升到 vLLM 的 2.01 倍 {#event-278613}

【AI推理与服务加速】 【SpecSearch】 【投机解码】 【性能提升】

📋 **要点**：**投机解码**可加速 **LLM** 推理，但其最优配置同时取决于工作负载、**GPU** 硬件与可用显存：论文给出 **RTX 5090** 上 **DFlash** 在低并发时达自回归 **3.50 倍**吞吐，而在高并发短输出场景反而只有 **0.76 倍**，说明固定配置难以跨场景复用。**SpecSearch** 因此构建硬件感知搜索引擎，联合优化解码策略、草稿长度与精度，用解析成本模型刻画显存与算力约束以筛掉不可行配置并缩小搜索空间，再基于多 **GPU** 标定测量训练参数高效的 **Jev** 预测器——通过 **LoRA** 适配冻结的 **Qwen3-4B** 并加线性修正层，使其在未见 GPU 上直接选择高吞吐配置。在 **NVIDIA** **RTX 5090**、**H100**、**L40** 与 **AMD MI300X** 上经 v**LLM** 服务，全标定版本平均吞吐为自回归的 **2.01 倍**、**投机解码**的 **1.36 倍**，无需部署卡标定的预测器为投机解码的 **1.30 倍**。
📌 **总结**：该工作指出**投机解码**收益高度依赖工作负载与硬件组合，固定配置在高并发短输出下甚至低于自回归，因此把“按卡逐次调参”转为可迁移的硬件感知选型：预测器保留全标定 **97.36%** 的吞吐，意味着新卡上线可不做在线标定即获得接近最优配置。对推理服务平台，这支持把解码策略、草稿长度与精度纳入统一的自动调优层，在混布 **RTX 5090**、**H100**、**L40**、**MI300X** 的集群中稳定兑现吞吐收益，为 token 成本、并发容量与延迟 **SLA** 规划提供可测量基线，同时降低因选型错误导致的资源浪费。
来源：[研究团队](https://arxiv.org/abs/2611.22296)
原文标题：SpecSearch: Towards Hardware-Aware Efficient Speculative Decoding

### 2、HyCoInfer将预填充放云端GPU、解码分到边缘FPGA，500Mbps下吞吐提升4.11倍 {#event-278583}

📋 **要点**：2026年11月arXiv论文针对AI智能体迭代生成并执行代码时依赖代码沙箱、而现有沙箱启动缓慢的问题展开研究，指出无论采用自定义快照还是单一胖镜像，根因都是难以构建既紧凑又能覆盖多样智能体生成代码所需包与数据集的预热快照。论文提出学习式**启动快照**思路：单个快照难以兼顾紧凑与覆盖，但一组快照可以，每个快照体积小、初始化快并覆盖部分智能体生成代码，整体覆盖大部分负载。作者将快照集合构建形式化为优化问题并用近似算法求解，在15000个公开与LLM合成脚本上规划，系统Readie在相同存储预算下将启动延迟降低3至**22倍**，端到端运行时间降低1.3至**3.3倍**。
📌 **总结**：该工作把智能体代码执行基础设施的瓶颈定位在沙箱**启动快照**的紧凑性与覆盖率矛盾，并用学习式快照集合给出可量化改进，对智能体运行时、工具调用与代码执行架构具有直接工程价值。对核心网与云基础设施团队而言，该思路可迁移到网元测试沙箱、自动化运维脚本执行环境等场景，通过按负载学习预热快照降低任务启动开销，从而提升智能体与自动化流程的端到端效率并降低资源占用。
来源：[研究团队](https://arxiv.org/abs/2611.22171)

## AI推理与服务加速

### 1、SpecSearch 硬件感知搜索把投机解码吞吐提升到 vLLM 的 2.01 倍 {#event-278613}

【AI推理与服务加速】 【SpecSearch】 【投机解码】 【性能提升】

📋 **要点**：**投机解码**可加速 **LLM** 推理，但其最优配置同时取决于工作负载、**GPU** 硬件与可用显存：论文给出 **RTX 5090** 上 **DFlash** 在低并发时达自回归 **3.50 倍**吞吐，而在高并发短输出场景反而只有 **0.76 倍**，说明固定配置难以跨场景复用。**SpecSearch** 因此构建硬件感知搜索引擎，联合优化解码策略、草稿长度与精度，用解析成本模型刻画显存与算力约束以筛掉不可行配置并缩小搜索空间，再基于多 **GPU** 标定测量训练参数高效的 **Jev** 预测器——通过 **LoRA** 适配冻结的 **Qwen3-4B** 并加线性修正层，使其在未见 GPU 上直接选择高吞吐配置。在 **NVIDIA** **RTX 5090**、**H100**、**L40** 与 **AMD MI300X** 上经 v**LLM** 服务，全标定版本平均吞吐为自回归的 **2.01 倍**、**投机解码**的 **1.36 倍**，无需部署卡标定的预测器为投机解码的 **1.30 倍**。
📌 **总结**：该工作指出**投机解码**收益高度依赖工作负载与硬件组合，固定配置在高并发短输出下甚至低于自回归，因此把“按卡逐次调参”转为可迁移的硬件感知选型：预测器保留全标定 **97.36%** 的吞吐，意味着新卡上线可不做在线标定即获得接近最优配置。对推理服务平台，这支持把解码策略、草稿长度与精度纳入统一的自动调优层，在混布 **RTX 5090**、**H100**、**L40**、**MI300X** 的集群中稳定兑现吞吐收益，为 token 成本、并发容量与延迟 **SLA** 规划提供可测量基线，同时降低因选型错误导致的资源浪费。
来源：[研究团队](https://arxiv.org/abs/2611.22296)
原文标题：SpecSearch: Towards Hardware-Aware Efficient Speculative Decoding

### 2、HyCoInfer将预填充放云端GPU、解码分到边缘FPGA，500Mbps下吞吐提升4.11倍 {#event-278583}

【AI推理与服务加速】 【HyCoInfer】 【云边协同推理】 【性能提升】

📋 **要点**：大模型服务长期依赖云端GPU，但自回归解码受内存带宽约束，GPU算术单元利用率不足；边缘FPGA解码能效更优，却难以独立承载高并发负载。**HyCoInfer**将预填充固定在云端GPU，把解码按队列负载、提示长度和网络状态分配到云端GPU与边缘FPGA，并用层间流水传输、解码侧预计算和基于残差向量量化的带宽自适应KV Cache压缩，缓解异构容量均衡、广域链路KV Cache传输和异构执行时延三类障碍。系统在两张**NVIDIA** V100和一块AMD **Xilinx Alveo** U280上、100-1000Mbps链路中验证，500Mbps时请求有效吞吐达云侧vLLM的**4.11倍**，平均端到端时延降低最多**61.1%**。
📌 **总结**：该工作把边缘FPGA从单纯推理加速卡提升为可参与解码分工的异构算力节点，说明**云边协同推理**的瓶颈已从单点算力转向容量均衡、KV Cache跨广域传输和异构调度。对推理服务平台而言，可据此评估在受限带宽下引入FPGA或异构加速器的收益边界；对核心网与边缘云规划者，则提供了把边缘算力纳入大模型服务链路的量化参考，但结论基于V100与Alveo U280的仿真与实测组合，尚需在现网带宽和真实负载下复核。
来源：[研究团队](https://arxiv.org/abs/2611.22086)
原文标题：HyCoInfer: Cloud-Edge Collaborative Inference for Large Language Models on Heterogeneous GPU-FPGA Architectures

### 1、RSI-Prime数据集以决策级损失掩码训练GLM-5.3自主后训练，性能相对提升31.95% {#event-278690}

【模型训练】 【RSI-Prime】 【自主后训练】 【研发效率提升】

📋 **要点**：2026年11月17日，arXiv刊出**RSI-Prime**论文，研究如何让大模型从“被训练”转向“执行训练”，为递归自我改进（**RSI**）打基础。作者构建**RSI-Prime**数据集，覆盖七类任务共350条完整实验轨迹，对训练实践中的决策进行细粒度识别与质量标注，并采用决策级损失掩码排除对低质量行为的监督。在**自主后训练**基准PostTrainBench上，用该数据集训练GLM-5.3后，整体性能相对原始GLM-5.3提升**31.95%**，表明模型可通过学习训练实践中的高质量决策来提升自身开展训练实验的能力。
📌 **总结**：该工作把“**模型训练**能力”本身作为可训练对象，提出用决策级标注与损失掩码过滤低质量训练行为的方法，对预研规划的意义在于：若模型能自主完成超参选择、数据配比与实验重规划，模型迭代的人力成本结构可能改变。但当前仅在PostTrainBench单一基准与GLM-5.3上验证，**31.95%**为相对提升，且RSI叙事带有较强前瞻性，距离生产级自动训练系统仍有明显差距，宜作为技术路线观察而非近期落地方案。
来源：[研究团队](https://arxiv.org/abs/2611.23138)
原文标题：RSI-Prime: Training Models to Train Models

## AI安全、可信与治理

### 1、ATI联邦信任架构将跨组织智能体攻击遏制率从43%提至84% {#event-278694}

【AI安全、可信与治理】 【ATI】 【联邦信任与远程证明】 【安全风险】

📋 **要点**：跨组织协作的AI智能体在调用工具和与其他实体运营的智能体交互时，现有框架缺少验证跨组织身份、执行完整性与授权的通用机制。论文提出Agent **Trust Infrastructure**（**ATI**），基于公钥基础设施、零信任架构和远程证明，通过同级组织证书机构AgentCAs建立联邦信任而无需共享根权威；执行请求前校验智能体证书、核验获批的模型、工具与系统提示配置，并通过三项策略检查实施授权。**ATI**以外部安全执行层形式集成，不修改底层模型，采用IETF WIMSE工作负载令牌与实体证明令牌。在八组织、六种智能体框架、每组织五智能体团队的仿真中，全部执行机制开启后攻击遏制率从**43%**升至**84%**，每请求引入约174微秒开销。
📌 **总结**：该工作把跨组织智能体协作的安全问题落到身份、证明与授权三层机制，并以联邦CA避免单一根权威依赖，对多域智能体互操作的安全架构设计具有直接参考价值。量化结果显示安全执行层可在微秒级开销下显著提升攻击遏制率，说明安全校验可作为独立旁路层部署而不侵入现有框架，为智能体平台在跨企业场景的商业化提供可审计的信任基础，也提示需关注证书体系与令牌标准的生态兼容成本。
来源：[研究团队](https://arxiv.org/abs/2611.23202)
原文标题：Agent Trust Infrastructure (ATI): A Federated Identity, Trust, Attestation, and Accountability Architecture for Cross-Organization Autonomous AI Agents

### 2、SceneSafetyBench揭示视觉语言模型场景状态安全漏洞，S3TA攻击成功率71.2% {#event-278351}

【AI安全、可信与治理】 【SceneSafetyBench】 【视觉语言模型安全】 【安全风险】

📋 **要点**：2026年11月17日，arXiv刊出论文，识别出视觉语言模型的场景状态安全漏洞：模型可在没有显式请求有害目标的情况下，通过解读视觉事件提供有害协助。作者构建**SceneSafetyBench**，包含375个图像—问题对，覆盖初始、中间和最终三种场景状态及五种视觉呈现方式。在八款VLM上，场景状态输入诱发有害协助的攻击成功率为**45.6%**–**72.3%**。对三款VLM的对比分析显示，场景状态输入在逐层安全相关信号分布上最接近二维码相关图像，但后层平均读出更低、生成过程信号动态不同。为将该漏洞转化为系统化攻击，作者提出S**3T**A，把有害目标翻译为场景状态、独立查询图像—问题对并汇总回答，在MM-SafetyBench七个类别、八款开源权重与商用VLM上取得模型平均ASR **71.2%**，超过最强基线6.1个百分点。文本侧过滤与视觉审核提供的防护有限。
📌 **总结**：该研究把多模态安全防线从输入内容筛查推进到场景化推理所推断出的协助行为，其技术价值在于揭示仅靠文本过滤和视觉审核无法覆盖场景状态攻击面，为VLM安全评测提供可复用的基准与攻击方法。对技术路线而言，安全对齐需覆盖视觉事件解读与推理链路，而非只做输入侧拦截；对产品架构而言，面向图像理解、辅助决策的多模态应用需在推理阶段引入场景级安全信号监测；对治理与合规而言，**SceneSafetyBench**与S**3T**A可作为红队与准入评测工具，但论文未给出完整防御方案，落地仍需后续研究。
来源：[研究团队](https://arxiv.org/abs/2611.23206)
原文标题：Reading Scene States: Uncovering Safety Failures in Vision-Language Models
