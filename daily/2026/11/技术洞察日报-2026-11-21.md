### 1、MATE执行层护栏将移动智能体高风险拦截率提至97% {#event-282716}

【智能体平台、协议与执行系统】 【MATE】 【移动智能体执行护栏】 【安全风险】

📋 **要点**：2026年11月19日，arXiv刊出**MATE**（**Mobile Agent Trustworthy Execution**）论文，针对个人手机上移动智能体可能触碰隐私数据、支付、设置和前台屏幕的风险，提出一种不修改底层模型的执行层系统，在智能体动作提议与设备实际效果之间建立控制边界。**MATE**把每个UI原语表示为包含指令、目标应用、屏幕上下文、原语和动作字段的结构化动作记录，运行时护栏将其映射为允许、阻断或用户批准三类决策；预定义任务路由让重复请求走已验证路径并做执行后屏幕校验，浮动界面把执行保持在紧凑浮层中。在MobileSafetyBench上，MATE在GPT-4o下把高风险阻断率从**29.7%**提升到**97.0%**；在AndroidWorld上把LLM调用最多减少**6倍**，重复使用任务成功率提升到**95.7%**。论文被EMNLP 2026接收。
📌 **总结**：**MATE**把智能体安全从模型对齐前移到执行层，用结构化动作记录和运行时护栏实现可审计的允许、阻断与用户批准决策，为移动端和企业智能体的权限沙箱设计提供了可量化参考。其高风险拦截率**97.0%**和LLM调用减少**6倍**的组合，说明安全约束与效率优化可以并行推进，对智能体运行时、工具调用权限和审计架构的规划具有直接借鉴意义。
来源：[研究团队](https://arxiv.org/abs/2611.25526)
原文标题：MATE: Mobile Agent Trustworthy Execution for Safe and Efficient Mobile Control

### 2、RoC框架以事件触发推理降低长程机器人操作Token消耗65.3% {#event-282687}

【智能体平台、协议与执行系统】 【RoC】 【事件触发推理】 【成本下降】

📋 **要点**：2026年11月19日，作者在arXiv发布**RoC**（**Reasoning** on **Call**）框架，针对大型多模态模型支持长程机器人操作时频繁调用导致高延迟与高Token成本的问题。**RoC**通过在线任务状态监控器协调低层策略与高层推理智能体，监控器结合时序视觉观测与有序交互记忆，联合估计当前子任务进度并预测后继子任务，据此触发事件式智能体审查，协调执行修复与计划修订。已验证结果驱动记忆更新与子任务切换，使常规执行留在策略层，推理仅聚焦需额外评估的决策。在RMBench上，RoC相比最强智能体基线任务成功率提升24.0个百分点，Token消耗降低**65.3%**，相比最强策略基线成功率提升15.1个百分点，并在三个真实长程操作任务中验证有效性。
📌 **总结**：**RoC**将智能体推理从持续调用转为事件触发，为长程机器人操作提供了一种降低推理成本与延迟的架构范式。其任务状态监控器与有序交互记忆的设计，对智能体执行系统中的规划、记忆与工具调用调度具有直接参考价值；在RMBench和真实任务上的成功率与Token消耗数据，可支撑机器人操作场景的预研规划与成本评估，并为高效智能体控制策略的工程化提供技术路线参考。
来源：[研究团队](https://arxiv.org/abs/2611.26341)
原文标题：Reasoning on Call: Efficient Agentic Robot Control for Long-Horizon Robot Manipulation

### 3、MemFolder结构引导记忆折叠在记录减半下保留99%智能体记忆性能 {#event-282752}

【智能体平台、协议与执行系统】 【MemFolder】 【智能体记忆管理】 【成本下降】

📋 **要点**：2026年11月19日arXiv论文提出**MemFolder**结构引导记忆折叠框架，针对长期智能体外部记忆存储增长导致检索开销上升、检索上下文变长推高预填充和解码注意力成本的问题，顺序降低记录数和上下文长度。框架含两个共享记忆组的核心组件：RecordFolder基于实体提及接地，渐进选择代表性且互补的锚点，结合语义与实体亲和度及时序链将兼容记录合并为更少检索单元；ContextFolder将组内原始记录编码为紧凑文本，并用验证反馈在关键事实无法恢复时修正编码。在LoCoMo、**PersonaMem**、LongMemEval三项文本基准和M3-**Bench-web**、**M3-Bench-**robot两项多模态基准上验证，Mem0上RecordFolder以**50%**更少记录保留**99.0%**原始平均性能，超最强基线1.9个百分点。
📌 **总结**：**MemFolder**表明结构引导的记忆折叠可在显著减少记录数的同时保留绝大部分性能，直接降低长期智能体的存储、检索和预填充成本。对技术路线而言，跨记录结构同时指导证据合并和紧凑表示的设计值得在智能体记忆系统中复用；对产品架构而言，该方案可缓解长会话智能体的上下文膨胀问题；对商业判断而言，记忆管理效率直接影响智能体服务的单次交互成本。
来源：[研究团队](https://arxiv.org/abs/2611.26427)
原文标题：MemFolder: Structure-Guided Memory Folding for Efficient Agent Memory Management

【智能体平台、协议与执行系统】 【LoopRoute 动作路由器】 【System 1 决策模型】 【成本下降】

📋 **要点**：2026年11月，arXiv 论文针对 **System 1 决策模型**虽快速低成本但现有智能体集成难以可靠完成任务、而每步调用 **LLM** 又带来大量开销的问题，提出 **LoopRoute 动作路由器**。该路由器观察到重复出现的状态-动作对可指示执行停滞，默认由决策模型 **Jev** 执行动作，检测到循环时由 **LLM** 提供简短反馈驱动协助后交还控制权，后续循环可再次请求协助。该规则无需额外训练，也不依赖模型特定置信度校准。在 **ALFWorld**、**MapReader**、**TextWorld** cooking 三个基准和七个 LLM 上，**LoopRoute** 相对独立 **Jev** 平均成功率提升 **21.0%**、**60.1%**、**30.1%**，相对全 LLM 控制显著降低每任务累计 **API** 时间和调用成本，并提升六个冻结决策模型的成功率。
📌 **总结**：该研究为智能体执行中快速局部决策与慢速全局推理的协调提供了一种无需训练的路由机制。对技术路线而言，循环检测作为停滞信号可能成为智能体运行时调度的通用组件；对产品架构而言，按需调用 **LLM** 可显著降低 **API** 成本，有利于大规模智能体部署的经济性；对研发工作而言，该规则可直接应用于现有决策模型而无需重新训练，降低集成门槛。
来源：[研究团队](https://arxiv.org/abs/2611.25363)
原文标题：Stop Going in Circles:Loop-Triggered Routing for System 1 Decision Agents

### 5、Seer框架以共享决策模型引导端侧深度研究智能体 {#event-282608}

【智能体平台、协议与执行系统】 【Seer】 【深度研究智能体】 【性能提升】

📋 **要点**：**深度研究智能体**需反复决定搜索、阅读和验证什么，通常依赖云端大模型进行动作提议，但隐私和本地控制需求推动智能体在用户设备上运行，有限内存和算力更适合小模型且端侧训练困难。推理时引导面临三个障碍：通过真实执行探索替代方案会增加工具调用，提示式自评估受限于智能体自身判断，模型特定引导带来重复适配成本。该论文提出推理时框架**Seer**，将智能体动作提议与学习到的后果预测和价值估计分离，从真实研究轨迹共享语料训练两个模型：基于观测调用-响应对的工具响应模拟器，以及基于带折扣终端正确性标签历史的价值估计器。两者离线训练并跨智能体复用，**Seer**只执行选中动作并将真实工具响应加入已提交历史，避免对丢弃候选产生额外推理成本。在多个深度研究基准上，GAIA准确率对Qwen3.5-**4B**从**13.6%**升至**41.7%**，对Qwen3.5-**9B**从**22.3%**升至**50.5%**。
📌 **总结**：**Seer**把智能体推理时引导从依赖真实执行或提示式自评估，转为可离线训练、跨智能体复用的预测与评估模型，使小模型在端侧也能获得接近大模型的深度研究能力。对技术路线而言，这提示智能体架构可将动作提议与后果预测解耦，把计算开销转移到可复用的本地模型；对产品架构而言，端侧隐私敏感场景可借此减少对云端大模型的依赖；对商业判断而言，小模型加推理时引导的组合可能降低智能体部署的算力成本。但该工作为学术预印本，工程落地效果尚待验证。
来源：[研究团队](https://arxiv.org/abs/2611.26423)
原文标题：Seer: Guiding Small Deep-Research Agents with Shared Decision Models

### 6、Hugging Face发布harness适配器，Qwen3.8-27B在Terminal-Bench提升至55% {#event-281349}

【智能体平台、协议与执行系统】 【Hugging Face】 【harness适配器】 【成本下降】

📋 **要点**：2026年11月20日，**Hugging Face**发布**harness适配器**方案，提出在真实agent harness内部进行强化学习训练，而非在框架自研的agent循环中训练。方案以Qwen3.8-**27B**为基座，针对pi、**Hermes** Agent和OpenCode三个harness分别训练LoRA适配器，训练数据来自**SWE-**smith、**SWE-**Gym和Tasksmith生成的agentic coding任务，经openenv validate校验和基座模型难度筛选后保留171个合格任务。训练使用TRL的AsyncGRPOTrainer，在2xB200 GPU上完成。结果显示，pi harness下Terminal-**Bench 2.**1得分从**39%**提升至**55%**，平均token从2.9K降至1.5K；三个适配器还可合并为rank 96的super-adapter，在三个harness下均优于基座模型，工具调用减少**53%**至**73%**。
📌 **总结**：该方案对智能体模型的训练与部署路线有直接参考价值：将RL训练嵌入真实harness，使模型学习目标与部署环境一致，避免框架自研agent循环与生产harness之间的偏差。对核心网运维Agent等场景，可借鉴其按harness和任务分布定制适配器的思路，在固定基座模型上通过LoRA降低token消耗和工具调用次数，从而控制推理成本。super-adapter的合并方法也为多harness统一部署提供了工程路径。
来源：[Hugging Face](https://huggingface.co/blog/harness-adapters-at-scale)
原文标题：Introducing harness adapters: adapt your favorite model to your harness to improve performance and cost

【智能体平台、协议与执行系统】 【STARK】 【长期记忆】 【体验提升】

📋 **要点**：针对个性化智能体**长期记忆**只记录“发生了什么”而无法沉淀“为何发生”的问题，**STARK**提出双图记忆架构：情景图按时间、因果和语义链接交互事件，洞察图存放由大模型抽取的行为信号并以支持事件数打分，事件同时充当连接洞察的边。推理阶段行为知识直接从洞察节点检索，由事件边提供依据，避免重复遍历情景图；该结构还可将知识图谱投影到关系嵌入空间，在共享上下文下实现跨用户迁移，为冷启动用户推断缺失洞察。在LongMemEval信息抽取上评审分提升1.48，LoCoMo开放域问答提升0.93；在LongLaMP摘要生成基准上，**5%**图稀疏度时跨用户迁移使开放式评审分提升0.7、**ROUGE-**L提升3。
📌 **总结**：该工作把智能体记忆从“事件存储”推进到“行为洞察+可迁移关系”的架构路线，对个性化助手、长期陪伴型Agent和冷启动推荐具有直接参考价值。事件作为边的设计降低了推理时的检索开销，跨用户迁移能力则意味着记忆系统可以在保护个体数据的前提下共享行为模式，为产品侧降低冷启动成本、提升留存提供新思路；同时其评测方法也为记忆类Agent的基准设计提供了可复用的指标组合。
来源：[研究团队](https://arxiv.org/abs/2611.25705)
原文标题：STARK: Moving towards Personalized Agents That Truly Learn and Remember

### 1、RoCoKV以不确定性与冗余感知压缩KV缓存提升vLLM推理吞吐 {#event-282712}

【AI安全、可信与治理】 【Tether】 【智能体运行时安全策略】 【安全风险】

📋 **要点**：自主AI智能体越来越多地部署于执行任意shell命令或程序的长期任务，但这些动作可能导致未授权网络请求或对用户文件系统、进程、权限的持久恶意更改。现有防御依赖缺乏可证明安全保证的LLM监控器或无状态策略执行层，后者会遗漏多步数据流和策略语言未建模的执行副作用。**Tether**提出在智能体动作观察到的副作用上进行有状态安全策略运行时执行的框架。**Tether**在临时隔离沙箱中执行每个提议动作，从观察到的系统调用推断抽象动作语义，然后在这些推断语义上执行有状态策略，仅当动作符合策略时才允许继续。策略和动作语义在Lean 4嵌入式DSL中定义，能表达信息流控制、访问控制和网络安全策略。由于动作可在源和目的地之间传播标签，单条规则可跨任意长度的多步执行流执行细粒度IFC策略。在Lean中表达策略可实现形式化验证，确保满足全局安全不变量。在真实编码智能体基准上，单一策略阻断**100%**范围内攻击，良性误报率低于**5%**。
📌 **总结**：**Tether**为智能体安全提供了从无状态策略到有状态、可形式化验证的架构升级路径，解决了多步数据流和未建模副作用的监控盲区。对核心网运维Agent、企业流程自动化等需要高安全保证的智能体部署场景，该框架的沙箱执行、系统调用语义推断和Lean 4形式化验证组合具有直接参考价值，也为智能体权限沙箱和审计机制设计提供了工程范式。
来源：[研究团队](https://arxiv.org/abs/2611.25599)
原文标题：Tether: Verified Stateful Policy Engine for System-Level Monitoring of Agents

### 2、DRJanus利用HDR增益图在单张JPEG中藏双图，绕过六家商用审核 {#event-282186}

【AI安全、可信与治理】 【DRJanus】 【HDR增益图】 【安全风险】

📋 **要点**：2026年11月19日，作者在arXiv发布**DRJanus**，指出图像可通过自动安全检查却向人类观看者展示有害内容。该攻击利用标准动态范围处理与高动态范围显示之间的差异：自动系统通常只读取图像的SDR基图，而HDR观看端借助辅助增益图重建外观。**DRJanus**逆向该重建过程，在单张JPEG中嵌入两幅独立选定的彩色图像，无需查询或针对目标模型优化，精确保留所选SDR基图，400张图像上HDR目标重建平均PSNR为43.03dB。在100张性内容图像基准上，绕过全部六家被测商用审核服务与九个视觉语言模型；五个智能体各120个任务用例下，审核规避成功率**31.67%**至**100%**，任务操纵成功率**95%**至**100%**。
📌 **总结**：该研究把视觉安全从模型能力问题转为显示管线与审核管线不一致的系统问题，说明仅保障机器读取内容不足以保障用户所见。对多模态内容审核架构、HDR图像处理链路的安全设计、跨视图一致性校验等缓解手段以及AI安全评测基准建设提供直接可验证的攻击面与量化结果。
来源：[研究团队](https://arxiv.org/abs/2611.25469)
原文标题：A Wolf in Sheep's Pixels: Visual Camouflage Attacks via HDR Gain Maps
