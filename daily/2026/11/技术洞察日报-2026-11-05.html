1、清华与智谱HarnessPro：递归自进化让Agent同时提性能降成本

智能体平台、协议与执行系统 HarnessPro 递归自进化 成本下降

📋 要点：清华大学与智谱团队提出HarnessPro递归自进化框架，针对过往RSI类工作如RHO性能越高token成本越高的痛点。背景是Agent能力不完全取决于基座模型，包裹模型的Harness包含系统提示词、工具调用、内存管理和校验策略，同样模型换Harness任务完成率和成本差异巨大。技术机制上，HarnessPro不修改模型权重只迭代Harness，流程分轨迹诊断、方案规划与Harness编辑、候选评估筛选三阶段，用帕累托多目标优化产出lite、medium、heavy三套版本，并引入独立测试合成智能体替代LLM自评判，故障识别召回率从41.7%提升至83.3%。

📌 总结：该工作对Agent执行系统架构的价值在于：证明性能与成本可同时优化，Heavy模式在Terminal-Bench2通过率80.8%高于RHO的76.3%且单任务成本从1.09美元降至0.72美元，Medium模式在SWE-Bench Pro通过率79.0%接近RHO的80.0%而成本从2.68美元降至1.26美元。对核心网运维Agent而言，按预算准备多套Harness版本、用测试合成替代LLM自评判的思路可直接借鉴，降低生产部署的token成本和幻觉风险。

2、WASP-Mem 让智能体自组织程序性记忆，TheAgentCompany 通过率升 4.6-6.1%

智能体平台、协议与执行系统 WASP-Mem 程序性记忆 研发效率提升

📋 要点：LLM 智能体在自动化复杂企业流程时，静态预置框架难以覆盖专有策略、未文档化行为和状态相关恢复路径。研究团队提出 WASP-Mem，将执行轨迹与反馈蒸馏为持久、互链的 wiki 页面，形成可复用的程序性记忆，实现免训练持续学习。在 TheAgentCompany 基准上，WASP-Mem 在三个模型上较最强基线提升 4.6-6.1% 检查点通过率，同时存储需求减少 57-61%。系统对照研究显示，人类定义的 schema 和显式去重规则等规范性知识组织反而损害性能，而人类诊断能把失败轨迹转化为纠正知识，单轮人类诊断优于四轮自评 7.0-10.9%。

3、Meta²预计算可复用知识用于长时程智能体在线harness演化，Terminal-Bench 2.1达81.00%

智能体平台、协议与执行系统 Meta² harness演化方法 Meta-Skill与任务局部编辑 研发效率提升

📋 要点：Harness优化通过改进冻结模型周围的提示、工具、记忆与钩子来提升长时程智能体。离线方法可从已完成轨迹学习，但部署一个共享harness容易过拟合训练任务，且无法对新运行中出现的证据作出反应；在线演化可在运行前、中、后通过演化器适应，但每次干预都要从零推理，或依赖测试时通常不可用的验证器反馈。该论文提出Meta²，把离线优化提升一层：不优化共享harness，而是学习用于harness演化的可复用知识并在每个任务内在线应用。离线阶段通过对比同一任务智能体在无演化器、有当前版本Meta-Skill引导的演化器、以及有训练期特权验证器信息的演化器三种配置下的训练轨迹，聚合轨迹与结果差异，把文本Meta-Skill精化为关于何时以及如何演化、何时保持不变、应避免哪些干预的可复用指导。在线阶段演化器结合冻结的Meta-Skill与新出现的轨迹证据，决定保持harness不变或通过任务局部编辑演化它，每次编辑只作用于同一运行的剩余部分而不重置环境或进度。在Terminal-Bench 2.1与DeepSWE 1.1两个长时程基准上，Meta²使用GPT-5.6-Terra分别达到81.00%与44.44%，为所评估方法中最高。

📌 总结：该工作把智能体harness优化从共享配置调优转为跨任务可迁移的演化指导，同时保持编辑任务局部化，对长时程智能体的工程架构有直接参考价值。对产品架构而言，Meta-Skill与任务局部编辑的分离意味着演化知识可以复用而不会污染单次运行的环境与进度，降低了在线自适应的风险；对研发流程而言，对比式离线学习避免了测试时依赖验证器反馈，使该方法更接近可部署形态，但结论基于两个基准与单一基座模型，跨模型与跨任务族的泛化仍需验证。

4、Corvic提出Agent Board协调基板，等待成本不随等待时长增长

智能体平台、协议与执行系统 Agent Board 持久任务协调 架构替代

📋 要点：当前大语言模型harness普遍收敛为单线程形态：一个智能体、一段历史、一台机器、一次会话，难以支撑跨多智能体、超出单次模型调用、或需等待非智能体系统的工作。论文描述Corvic harness中的协调基板Agent Board：一张持久共享的半语义任务表，含少量供系统路由的精确字段和仅由语言模型阅读的自由文本主体。智能体发布任务、监听任务并阻塞等待，结束回合且不持有进程，直到匹配的发布将其唤醒。系统智能体Board Keeper充当板的中断处理器，把非智能体部分的事件带到板上，通过阅读文本匹配等待任务，并为指定智能体类型的任务分配新智能体。

📌 总结：该设计把智能体协调从单线程会话升级为持久任务板加中断处理，直接作用于多智能体与长时任务的执行架构。可加载的协调策略内核为状态与角色赋予语义而不由板强制，设计类比人类团队的看板。论文报告在模拟试点中，板的等待成本不随等待时长增长，而朴素轮询增长约165倍，但普通外部监听器比板更便宜；Board Keeper匹配文本等待者无虚假唤醒，但漏掉3.6%的真实唤醒。对智能体平台与产品团队而言，这提供了跨厂商、跨会话协调的可复用机制，同时明确了机制保证与约定之间的边界。

📋 要点：2026年11月，CNCF博客发布面向平台工程师的OpenShell指南。OpenShell由NVIDIA发起，现为CNCF Sandbox项目，定位是安全运行智能体的运行时。它把每个智能体放进沙箱，由沙箱外的可信监督进程决定智能体可访问的资源，并通过YAML声明文件系统、进程、网络和凭证四类控制：Landlock限制可读写路径，运行时降权为非root并施加seccomp，出站流量默认拒绝并按二进制、主机、端口和HTTP方法放行，凭证以占位符形式下发并由监督进程在允许的端点替换真实密钥。在Kubernetes上，OpenShell不自带调度器，其后端使用SIG Apps的agents.x-k8s.io Sandbox资源，智能体以Pod、Service、PVC、Secret和NetworkPolicy形式出现，网关通过mTLS接收创建请求，策略可在运行中的沙箱上更新而无需重启。

📋 要点：在复杂终端任务中，Code Agent 一旦写错代码、报错命令或配坏环境，往往陷入重复安装依赖、沿错误假设继续修改的无效循环，直至预算耗尽。复旦大学联合香港中文大学 MMLab、上海交通大学提出 ReTerm，把训练起点放在 Agent 自己执行任务后留下的失败现场：先构建 ReTerm-10K，收集基础模型失败任务并由更强教师模型示范恢复，经成功验证与质量筛选得到约一万条恢复轨迹用于冷启动；再用 ReTerm-GRPO 让 Agent 从同一失败现场独立尝试多种恢复办法，由任务验证器判定成败并转化为强化学习信号更新参数。ReTerm-9B 在 Terminal-Bench 2.0 从 20.2% 提升至 34.8%，SWE-bench Verified 从 45.2% 提升至 58.4%，OpenThoughts-TBLite 从 44.2% 提升至 60.6%。
