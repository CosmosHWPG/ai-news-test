📋 要点：2026年11月，NVIDIA在KubeCon North America 2026期间发布Agent Substrate，一个已捐入CNCF沙箱的开源、安全加固、零信任的Agent沙箱运行时。Agent Substrate针对Agent工作负载的间歇性特征——唤醒执行一步后等待数毫秒到数分钟——采用小规模热worker Pod池多路复用大量Agent会话，空闲会话被检查点保存（含内存与文件系统状态），下次请求时恢复到任意空闲worker，无需重新经过API服务器、调度器和kubelet，避免每步多秒冷启动和每会话常驻Pod的内存浪费，宣称密度比标准容器高10倍。上游贡献包括路由器请求排队（PR #221、#1229）、基于Kubernetes DRA的容器级设备可插拔（issue #752）、microVM沙箱的每容器CPU与内存限制（PR #859），以及厂商中立的GPU状态暂停与恢复设计。NVIDIA Dynamo负责GPU侧推理编排，其路由器利用会话身份、KV缓存位置和工具调用边界将相关模型调用保持在已持有可复用上下文的worker上，并向Agent Substrate回传首token预计时间、GPU池饱和度等信号，用于决定保持、挂起或恢复Actor。KAI Scheduler负责将Substrate worker Pod与GPU训练器和推理服务器一同放置。

📌 总结：Agent Substrate把Kubernetes的调度粒度从Pod下沉到Actor会话，用检查点/恢复替代冷启动，直接回应Agent负载中CPU侧工具执行与GPU侧推理交替导致的资源闲置问题。对技术路线的启示是，Agent基础设施需要独立的执行层来管理高频生命周期，与推理层的KV感知路由协同才能同时提升CPU和GPU利用率。对产品架构的启示是，编码助手、RL后训练和GPU研究沙箱三类场景对会话持久性、突发密度和GPU共享有不同要求，运行时需支持gVisor与microVM两种沙箱并保持设备可插拔。对商业判断的启示是，NVIDIA以CNCF沙箱身份推动Agent运行时开源，配合Dynamo和KAI Scheduler形成DSX OS之外的开放生态，有助于在Agent基础设施碎片化趋势中维持Kubernetes作为编排底座的地位。

📋 要点：Airbnb 于 2026 年 11 月将其生产环境广泛使用的嵌入式工作流引擎 Skipper 以 Apache 2.0 协议开源，代码、文档与可运行示例已发布至 GitHub。Skipper 面向跨多服务、需等待人工输入或混合同步异步步骤的业务流程，允许开发者用 Java 或 Kotlin 类表达编排逻辑，将动作结果持久化为检查点，并在崩溃或瞬时故障后通过从头重放工作流方法、复用已保存动作结果来恢复。其架构特点是工作流运行时与调度器随服务副本一同部署，共享数据库保存工作流状态与调度任务，调度器通过租约协调任务归属，副本故障时由其他副本接管。开源版本包含核心引擎、MySQL 与 SQLite 适配器、测试工具、管理界面以及 Skipper State Machine 状态机 DSL。

1、华为提出MACaQ低精度量化方法，Qwen3-32B上开销仅2.3%

📋 要点：IFM 推出开放基础世界模型 PAN 2，接受描述的动作并生成最多 20 秒展示物理后果的视频，定位为让 Agent 把试错成本移入模拟。架构上由语言模型先规划情节、再由 29B 视频模型渲染，形成规划与渲染分离的两段式结构。官方基准显示 PAN 2 完成单步 71.5%、完整计划 34.0%，在开放模型中完整计划完成率第一、Physics-IQ Verified 排名第三。

📌 总结：PAN 2 把世界模型定位为 Agent 的试错沙箱，规划与渲染分离的架构降低了物理后果预测的工程耦合度，对具身智能与智能体执行系统的训练数据生成、策略预演和仿真验证路径有直接参考价值；开源属性使其可作为世界模型底座被二次开发，但完整计划完成率仅 34.0% 表明长程物理一致性仍是瓶颈，短期更适合单步或短程场景验证。
